# 0024 记忆和螺壳搜索的本机数据加密存放

状态：已定方向（2026-11-09，主人定「尽快做」）。怎么做、哪一版做由 johnz 定；起点是 luoke-mem 的提案，主控那部分的方案由 luoke-core 出。

## 背景

11-09 端侧日报的第 1 条：有人拆解了 macOS 自带的个人知识图谱。批评最集中的一点是那些库都是明文 SQLite。螺壳也有同样的问题：

- 记忆 `~/.luoke/mem.db` 是明文 SQLite，权限 0600，同一个用户账户下的任何程序都读得到。苹果那些库至少还要完全磁盘访问才能读。
- 记忆旁边还有几处明文：
  - `-wal`、`-shm`、`-journal`；
  - 重新定档前的整份拷贝（留 14 天）；
  - 记忆页面的令牌文件。令牌也落在文件里，所以只加密库文件不够。
- 螺壳搜索的索引存着受系统保护位置的全文，包括 OCR 和转写的文字，按 ADR 0013 的 10-22 修订还存了证件号和卡号原值。安全审查把这一条列了出来，做不做一直没定。

ADR 0013 定的是「本机就是边界，本机组件之间不设隐私限制」。加密不改这一条：螺壳自己的组件照样能读，挡的是螺壳以外的程序。

## 决定

- 记忆和螺壳搜索的本机数据加密存放，两边用同一套办法。
- **防**：
  - 同一个用户账户里别的程序，包括各种 AI 助手、同步工具；
  - 从备份、拷贝里流出去的文件。
- **不在这里管**：
  - 硬盘被拿走，由 FileVault 管；
  - 已经拿到 root 的；
  - 能往螺壳进程里注入代码的。
- **密钥**：由主控管，存在钥匙串里，交给螺壳自己的组件时不放进命令行参数和环境变量。
- **拿不到密钥就不打开**：答「加了密，要螺壳来开」，不另建一份明文。
- **迁移**：第一次拿到密钥时，把现有的明文库换成加密的，明文和旧拷贝删掉。
- **页面令牌不再写进文件**。
- **分工**（各项目确认）：
  - luoke-core：加密扩展的打包和签名；密钥的生成、存放、交付；socket 核对端；
  - luoke-mem：加密打开、迁移、拿不到密钥时不打开、令牌不落盘、删明文拷贝；
  - luoke-search：索引用同一套；
  - luoke-ime：核沙盒里的个人化组件能不能加载加密扩展；
  - luoke-mail：只用主控那份记忆库。

## 还没定的

1. **谁能拿到密钥**：只核签名不够。密钥要只交给螺壳自己起的进程，具体办法由 luoke-core 出方案。
2. **换新 Mac**：密钥跟不跟着走（迁移助理、时间机器、iCloud 钥匙串）；要不要给用户一个恢复办法（比如只显示一次的恢复码）。密钥丢了，记忆和索引就打不开了。
3. **能不能做**：加密扩展以可加载扩展的方式能不能接管 `-wal`、`-shm` 的读写；输入法沙盒里加载同一签名的扩展，能不能过库验证。
4. **哪一版**：luoke-mem 建议不挡 beta 2 的 RC，下一版做。
