# 0006 替用户做事：能撤回的确认后自动做并提示，不可逆的永远要用户点

状态：有效。取代 0016（「下载规则和特征库不算外传」挪到 0001）。

## 决定

1. **能撤回、不毁灭的，用户确认一次之后可以自动做**，比如归档、标已读、加标签、给出 filter 建议。每次都提示做了什么，并且能撤销；用户撤销一次，就算这条习惯的反证。
2. **不可逆或对外的，永远要用户自己点**：删除（移进垃圾箱）、标垃圾邮件、退订、发信、花钱、往外传数据。
3. **习惯的来路**：
   - 记忆从用户亲手做的处理里归纳习惯，按「来源 × 类别」记（比如「某商城的促销邮件」）；在哪里做的都算，在 Gmail 网页或手机上做的也算，改过工具的建议也算。
   - 归纳出来以后出一条建议「以后这类都这样？」，用户点「好」，这条习惯就是确定。
   - 工具按规则自动做的，记成「规则做的」，不拿来加固同一条习惯。
4. **先做、事后复查**：邮件助手分拣过的邮件标成已读；有确定习惯的照习惯归档；每天给一个复查页，列出今天处理过的全部邮件和各自的处理（没自动处理、留在收件箱也算一种结果），用户在那里一键撤销或改，改了就是反馈。要用户处理的（回复、日程、可疑）照旧提醒。
5. **AI 自己的邮箱**：推荐用户给螺壳开一个独立邮箱，把相关的邮件转过去（邮件助手一键生成转发规则）。
   - 里面的读、归档、删全自动。
   - 从它往外发信，默认先存草稿等用户点；用户可以按类型放开（退订、回复确认、预约改期这类低风险的），放开以后直接发，每封都进复查页。
   - 以用户的名义、从用户自己的邮箱发信，永远要用户点。
6. **螺壳扫描按确定的规则挑出的四类，不用先确认就清，事后能放回**：
   - 会重建的缓存（npm、uv、pip、cargo、go、bun、swiftpm、Xcode DerivedData、Homebrew 旧版本这类）：用工具自己的清理命令或删文件夹，对应的工具开着就跳过；
   - 已经装好的应用的安装包（放了 14 天以上）；
   - 下载文件夹里在别处还有一份的重复文件（只清下载文件夹里那份）；
   - 工具和 agent 留下的临时文件夹。

   后三类移到废纸篓。判定只用确定的规则，不靠模型。每次清完告诉用户清了什么、多大；废纸篓清空前能一键放回；用户放回过的那一类以后不再自动清；每一类都能在规则里关掉。
7. **自动清的开启条件**：规则评测覆盖这四类、「不该删的误判为 0」，并且用户看得到清了什么、点得到「放回」。满足以后默认开着。
8. **其余照旧要用户点**：AI 模型、对话记录、很久没打开的文件、很久没改的项目、规则没认出的目录、要管理员权限的、报毒的文件。删除优先移到废纸篓；用户的邮件不自动删。
9. **内测别太保守**：可撤回的能力默认放进测试版，配上提示和撤销，看真实反应；反对的声音多了再调。

## 为什么

项目负责人原话：「自动整理里进行归档，或者给用户一个 filter 建议，都属于可撤销的不会造成毁灭性影响的，这个是可以接受的，如果反对的声音多我们再调整」「之所以要做内测，就是为了看到用户真实反应，而不是先假设用户不接受自缚手脚」。
