# 0004 系统权限授权给螺壳本身：组件经螺壳去要，开启时确认一次

状态：有效。取代 0021，并收进 0014 的 11-06 修订里关于权限的两句。

## 决定

1. **完全磁盘访问这类系统权限只授权给螺壳本身**；螺壳扫描、螺壳搜索复用这一份，用户只给一次。
2. **组件不直接向系统要权限**：组件要用的权限都在清单里声明（`permissions`），没声明的不能申请；组件向螺壳请求，用户同意后，螺壳先查自己有没有，没有再向系统要。
3. **开启时确认一次**：用户在「应用管理」里开启组件时确认它要的权限，不在第一次用到时再弹第二个框；开启后马上发起第一次检查，让第一次真用到紧跟着用户的操作。用户后来手动关掉了，下次要用时再请求。
4. **不静默弹窗**：所有授权请求都在用户操作之后马上弹出，让用户知道这次授权和自己刚做的事有关；不在跑着跑着的时候突然弹。
5. **看得到**：权限页列出每个组件确认过什么；状态以本体报的为准，组件探到什么照实报。
6. **谁带着这份权限**（现状）：
   - 本体起包外的程序（引擎、空闲任务、输入法、启动器）时 disclaim，它们不跟着拿到这份权限。
   - 往螺壳.app 里写东西的进程（换包、升级）不能 disclaim。
   - 要读全盘的程序由本体起，起什么写死在本体里；清单里的 `permissions`、`owner` 只给权限页读。起之前核签名和版本的，现在只有扫描；搜索还没核。
   - 排期留在主控；参数、环境、SIGTERM 后 15 秒 SIGKILL、异常重启、卸载时停，都和别的配件一样，退出码和 stderr 交回主控记账。
7. 扫描的完全磁盘访问卡片：默认关，打开时照第 3 条确认一次。

## 为什么

- 体检、深度搜索都要读全盘，原来要用户给两次，主控还要逐个程序判断记在谁名下；授权给螺壳本身，用户只给一次。
- 主控的 Python 要解析本账户任何进程发来的 socket 请求，开着本机端点时还收 TCP，所以这份权限本来不该跟着主控走。原定的做法是本体起主控时 disclaim，让持权限的只剩本体和声明过、核过的程序，「默认不给」由结构保证。这一条还没做到，在修。
- 权限请求紧跟用户的操作，避免突然弹窗要敏感权限。

## 还没定的和缺口

- 还有两处已知的安全问题在修，修好、发版以后再在这里补上细节。
- 搜索起之前不核签名和版本。
- 主控起的扫描和 pmset、sysctl 还算在螺壳名下（参数固定，不读用户数据）。
- 没测的：升级时、退出螺壳时，正在跑的持权限程序还算不算有授权；搜索在正式签名下的授权。
