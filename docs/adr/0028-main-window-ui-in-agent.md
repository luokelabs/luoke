# 0028 主窗口的界面只在 luoke-agent，工具只给原始数据和动作

状态：已定（2026-11-13 主人定；2026-11-17 主人把同一条延伸到卡片、概览、动作结果和固定的名字，本文已整份改写成现行文本）。

## 背景

ADR 0014 定了主窗口由 luoke-agent 写，各工具在配件清单里声明能力，交互用 A2UI 一类的声明式界面描述。实际做下来，这句话有两种读法：一种是 agent 决定每一页长什么样；另一种是 agent 只负责把界面描述画出来，页面放什么、怎么排、按钮叫什么由各工具排好。各工具照第二种读法做，于是一页界面的改动要分到几个仓库里去改，同一套界面规范在几处各自落地，做出来的页面和定好的设计对不上，也没有一处能对整页负责。

页面收到 luoke-agent 以后，卡片、侧栏的概览、动作做完后的那句话、清单里写死的名字仍由各工具带文字过来。几个工具各写各的句子，口径不一，用户看到的像几个产品拼在一起。

## 决定

- **主窗口里的一切只在 luoke-agent 仓库里改**：「今天」、右边栏、卡片、各应用的页面（邮件助手、记忆、搜索、扫描）、应用管理、设置。每一页放什么、什么顺序、怎么分组、哪些按钮、什么措辞，都在这里定。
- **自带的应用只给结构化的东西**（邮件助手、记忆、螺壳扫描、螺壳搜索、输入法，加主控）：
  - 给的是：这是哪一种事、涉及什么、数字多少、什么状态、能做哪些动作和各动作的参数。
  - 不给的是：句子、标签、按钮上的字、排列顺序。这些一律由 luoke-agent 照数据写，全窗口一个口径。
  - 这一条管到四处：卡片、侧栏的概览、动作做完后的结果、清单里固定的名字（提醒的类别、权限的名字这类由 agent 按代号起）。
- **内容仍由工具给**：邮件主题、文件名、模型写的摘要、记忆里的理解。这些是用户自己的东西或工具产出的内容，不是界面措辞，agent 原样用。
- **工具给卡片这条路不删**：留给 luoke-agent 不认识的工具（第三方），它们照卡片协议自己带界面描述。过渡期自带的应用继续带文字，agent 有结构化数据就用数据、没有才用工具带的文字；数据补齐以后工具一侧的文字可以去掉。
- **工具里现有的页面层搬到 luoke-agent**：由 luoke-agent 牵头，和各工具商定怎么搬、先搬哪页。没搬完的页面，工具一侧不再改它的页面内容。
- **agent 缺数据或动作，向工具提**；工具遇到要改界面或措辞的事，转给 luoke-agent。
- **有自己窗口的自己改**：首次安装、升级窗口和菜单栏（luoke-core），输入法的设置和引导（luoke-ime）。它们照同一份界面规范做。

## 取舍

- 页面层和措辞放在工具里，好处是懂业务的一方直接决定怎么展示；代价是界面散在几处、改一页要等几家、整体的口径没人负责。选择把界面和措辞收到一处，业务上「该展示什么」的判断由 agent 向工具问清数据的含义来补。
- 工具给结构化数据以后，接口比「页面数据」和现成的句子更稳定，但数量会多一些，每一种事都要说清有哪些字段；接口怎么定仍由 luoke-agent 和各工具商定（ARCHITECTURE.md §5）。
- 第三方工具仍然自己带界面描述，口径做不到统一。这是有意留的：agent 不可能事先认识所有工具。

## 替换了什么

ADR 0014 里「交互用 A2UI 一类的声明式界面描述」作为工具声明能力的一部分，对自带的应用不再适用，只留给 agent 不认识的工具；0014 的其余内容照旧。
