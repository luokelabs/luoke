# 0028 主窗口的界面只在 luoke-agent，工具只给原始数据和动作

状态：已定（2026-11-13，主人定）。

## 背景

ADR 0014 定了主窗口由 luoke-agent 写，各工具在配件清单里声明能力，交互用 A2UI 一类的声明式界面描述。实际做下来，这句话有两种读法：一种是 agent 决定每一页长什么样；另一种是 agent 只负责把界面描述画出来，页面放什么、怎么排、按钮叫什么由各工具在自己的「页面数据」里排好。各工具照第二种读法做，于是一页界面的改动要分到几个仓库里去改，同一套界面规范在几处各自落地，做出来的页面和定好的设计对不上，也没有一处能对整页负责。

## 决定

- **主窗口里的一切只在 luoke-agent 仓库里改**：「今天」、右边栏、卡片、各应用的页面（邮件助手、记忆、搜索、扫描）、应用管理、设置。每一页放什么、什么顺序、怎么分组、哪些按钮、什么措辞，都在这里定。
- **各工具和主控给两样**：原始数据（有哪些信、哪些记忆、哪些文件、什么状态）和动作（能做什么）。它们不生成页面数据、界面描述或按钮标注，不决定页面的内容和排法。
- **工具里现有的页面层搬到 luoke-agent**：由 luoke-agent 牵头，和各工具商定怎么搬、先搬哪页。没搬完的页面，工具一侧不再改它的页面内容。
- **agent 缺数据或动作，向工具提**；工具遇到要改界面的事，转给 luoke-agent。
- **有自己窗口的自己改**：首次安装、升级窗口和菜单栏（luoke-core），输入法的设置和引导（luoke-ime）。它们照同一份界面规范做。

## 取舍

- 页面层放在工具里，好处是懂业务的一方直接决定怎么展示；代价是界面散在几处、改一页要等几家、整页的效果没人负责。选择把界面收到一处，业务上「该展示什么」的判断由 agent 向工具问清数据的含义来补。
- 工具给原始数据以后，接口比「页面数据」更稳定，但数量会多一些；接口怎么定仍由 luoke-agent 和各工具商定（ARCHITECTURE.md §5）。

## 替换了什么

ADR 0014 里「交互用 A2UI 一类的声明式界面描述」作为工具声明能力的一部分，这一点不再适用；0014 的其余内容照旧。
