# 0021 完全磁盘访问授权给螺壳本身

状态：已定（2026-11-02）。代码还没改：现在授权的仍是「螺壳体检.app」。

## 背景

体检要读全盘，原来的约定是用户把完全磁盘访问给体检，主控起它时让系统把它记在体检自己名下。深度搜索也要这个权限，这样用户要给两次，主控还要逐个程序判断记在谁名下。

主控的 Python 要解析本账户任何进程发来的 socket 请求，开着本机端点时还收 TCP。系统按「负责的进程」认权限，主控、引擎和工作进程现在都记在螺壳名下，所以授权给螺壳时，这些进程不能跟着拿到权限。

## 决定

- **用户只授权一次**：完全磁盘访问给螺壳本身，体检、深度搜索复用这一份。
- **主控脱离**：Swift 本体起主控时 disclaim 一次，主控、引擎、工作进程和不要权限的空闲任务都脱离，不用逐个判断。
- **要读全盘的程序由本体起**：本体核过声明和签名后起，不 disclaim。排期留在主控的 `jobs`，主控告诉本体该跑了；参数、环境、SIGTERM 后 15 秒 SIGKILL、异常重启、卸载时停，都和现在的配件规矩一样，退出码和 stderr 交回主控记账。
- **按程序声明**：配件清单里 `jobs` 的项和常驻项各写 `"permissions": ["fda"]`，不要权限的不写（比如体检的 `update`）。`"owner": "luoke"` 只管权限页怎么列。
- **状态由本体报**：只有持权限的进程探测得到。权限页以本体报的为准，配件探到什么照实报。
- **请求授权的卡片要等这几件做完才出**：主控起 `jobs` 前核签名和版本；退回不支持这套做法的旧版时怎么处理；在测试机上手动授权实测一次，包括升级和退出螺壳时，正在跑的程序还算不算有授权。

## 后果

- 持权限的只有本体和声明过的程序，「默认不给」由结构保证。代价是本体要接管这部分进程管理。
- 常驻的 `luoke-audit-serve` 这类程序由本体起，也跟着本体，它和读全盘之间不再有系统隔开。邮件里的注入经 agent 到 serve 这条路，只剩用户点按一道：serve 仍不带碰文件的代码，会改动东西的调用只认用户点按。
- 主控记到裸的 python3 名下，以前算在螺壳名下的权限弹窗会变，要测。
- `disclaim` 用的是私有接口（`responsibility_spawnattrs_setdisclaim`），Python 的 `subprocess` 和 Swift 的 `Process` 都传不了，要自己调 `posix_spawn`。
- 主控 DESIGN §10 和体检、agent、深度搜索的注册页要跟着改。ADR 0013 不变：这是进程之间的防护，不是组件之间的隐私限制。
