# 0023 luoke 自己的任务协议和统一调度

状态：已定方向（2026-11-05，主人在早会定）。协议和调度的方案由 johnz 出，见 luoke-ops#88。

## 背景

用到模型的工作，现在都是向主控登记任务（ADR 0018），按 `user-waiting` / `background` 两档优先级排队；各组件的空闲任务由主控轮流叫起。11-04 社区应用申请收录（luoke-contribute#11）以后，johnz 交了一份调用方案（luoke-ops#67）。方案的要点是：

- 不收录的应用也能调用，只能调开放出来的任务（`POST /open/v1/<能力名>`）；
- 第一个申请过来的应用要用户同意一次；
- 只在没有官方请求时运行，一次一条。

主人 11-05 定的范围比这份方案大：不只管外来的应用，而是给整个螺壳定一套自己的任务协议，所有任务一起统一调度。

## 决定

主人原话：「做 luoke 自己的 task 协议，包括优先级、权限、资源等等声明和注册流程，由 luoke-engine 层统一调度排序，同优先级冲突时默认按照时间排序，可以提供一个 task 队列组件让用户可视化看到当前任务队列并且拖动调整顺序」。

- **协议**：任务要声明优先级、权限、资源等，有注册流程。螺壳自己的组件和外来的应用都走这一套。
- **调度**：由引擎层统一排序。同一优先级的，默认按时间先后。
- **任务队列组件**（可以做）：用户能看到当前的任务队列，能拖动调整顺序。

## 还没定的（luoke-ops#88，johnz 出方案）

- 和 11-04 调用方案怎么并：
  - `/open/v1` 这个前缀留不留；
  - 外来应用「只在没有官方请求时运行」和「按声明的优先级统一排，用户能拖动」怎么合；
  - 用户能不能把外来应用的任务拖到官方任务前面。
- 放在哪一层：方案写的是 luoke-core 的本机任务，主人写的是引擎层统一调度。薄引擎（ADR 0020）的现状和路线，主人和 Keith 11-05 下午一起谈。
- 现在 `user-waiting` / `background` 两档优先级、空闲任务轮流、配方按档开关任务，怎么迁到新协议里。
- 协议名：早会议题建议的「螺壳本机任务」没有定。对外文档出来之前都能改。

## 后果

- 「推理都在主控」（ADR 0018）不变，调度从主控挪到引擎层还是留在主控，跟着上面「放在哪一层」定。
- 外来应用接入（扩展层，luokelabs/luoke#1）用这套协议，不另做一套。
- 用户第一次能直接看到螺壳在后台做什么、按什么顺序做。拖动的结果怎么算反馈、要不要记，由方案定。

## 修订（2026-11-06，调度归主控）

主人 11-06 早会更正（luoke-meetings 11-06 第 4 题）：

> 之前说错了，调度是 core 的，不是 engine 的

- **调度在主控**：任务协议的统一调度、排序由主控做，不放在引擎层。上面「放在哪一层」这一条就此定了，和 ADR 0018「推理都在主控」一致；引擎只管跑模型。
- **外来应用**：「A 类应用不影响我们自己的规划，理论上我们做的足够好的时候 A 类可以自己接入我们不需要我们知道的」。外来应用照本协议自己接入，不用逐个经我们同意。
- **用户接入螺壳没覆盖的模型**：螺壳保证不了体验，要给用户提示，等于允许用户自定义配方。UX 由主控和 agent 一起设计，优先级不高（luoke-ops#99）。
