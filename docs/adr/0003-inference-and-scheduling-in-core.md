# 0003 推理、模型和调度归主控：体系里没有脱离主控的模型运行实例

状态：有效。取代 0018、0020、0023，并收进 0014、0013 里「高级用户的本机端点」。

## 决定

### 推理和权重

1. **本机的模型推理和权重都归主控**：下载、版本、校验都走主控的分发（配方、发布清单），各工具不自带模型，也不自己加载模型。体系里没有脱离主控的 LLM 运行实例。
2. 唯一的例外是没装螺壳时的小精灵（0010）。
3. **垂类模型也做成主控的任务**：只给某一个工具用的专门模型，同样是工具按任务要结果、不点名模型，权重、版本、评测和别的模型一样由主控管。先看能不能复用现有的任务类型（生成、打分、嵌入），都不合适再加新的任务类型，只加不改。接入方写清两件：要什么接口；延迟要求（每次多大的输入、最慢能等多久）。
4. **对延迟敏感的，走主控的优先通道**，不靠「留在工具里自己跑」解决。
5. **一直加载的小模型**（语音转写、螺壳搜索的嵌入）由主控按任务统一管内存：每一档能放多少、空闲多久卸掉、和底座抢内存时谁让。
6. 现在的垂类模型：螺壳搜索的嵌入（任务 `luoke-search.embed`，接口见 luoke-core V1 §2）。隐私模型 PII-Tracer 不接。

### 调度和任务协议

7. **调度在主控**，引擎只管跑模型。
8. **螺壳自己的任务协议**：任务声明优先级、权限、资源，有注册流程；螺壳自己的组件和外来的应用都走这一套，同一张任务表、同一个调度。同一优先级的，默认按时间先后。方案由发版品控的一位负责人定，谁做也由这位负责人安排。
9. **外来应用照协议自己接入**，不用逐个经团队同意；碰记忆仍照 0001 第 9 条要用户另外同意。
10. **任务队列看得见**：右边栏单独一个页签列出当前的任务队列，以后做成用户能手动调顺序。
11. 用户接入螺壳没覆盖的模型，螺壳要提示它保证不了体验，等于允许用户自定义配方；UX 由主控和 agent 一起设计，优先级不高。

### 引擎

12. **引擎换成螺壳自己做的引擎**，不再用 oMLX。
13. 自己的引擎是科研线，在单独的仓库里做；怎么做、ADR 里写到什么程度、进不进内部版，由引擎的负责人定；进 beta 和正式版由项目负责人点头（0009）。切换前要补上输入法自己的评测、给本机端点留出路，三档评测照常把关。

### 高级用户的本机端点

14. 主控在 127.0.0.1 上开一个 OpenAI 兼容的端点：默认关，入口在设置的高级选项里，不当普通用户功能宣传。
15. 模型可以用主控自己的，也可以登记用户自己的本地模型（只读、只克隆，不改用户的文件和设置）；用户登记的不进评测和支持台账，质量由用户自己负责。
16. 端点的请求算「用户在等」，排在后台任务前面，打字照旧最优先。加载大模型时由主控让路：先暂停后台任务、卸掉底座，放不下就答「放不下」，不硬挤。
17. 安全：只听本机，校验 Host，拒绝带 Origin 的网页请求，请求文字不落盘。密钥默认生成一把，用户可以自己改，也可以留空；留空就不校验，设置页照实提示这台 Mac 上任何程序、任何登录的账户都能用这个端点。

## 为什么

- 显存、功耗、排队只能有一处管。两份权重、两套内存判断会撞车：项目负责人自己装的 oMLX 和主控就这样撞过，因此定「我们体系里不应该有脱离主控的 LLM 运行实例」。一步到位，不设「工具先自带、再统一」的过渡，不然要维护两套下载和版本。
- 内存预算怎么算正是主控的价值，也是定义任务这套标准的意义，所以一直加载的小模型也归主控管。
- oMLX 是给所有人用的本地模型应用，带了螺壳用不上、还要防着的能力（网页搜索和抓取、管理接口），包大，主控还依赖它没公开承诺的行为；只服务配方里那几个模型的薄引擎分拣更快、占内存更少，判断结果一致。
