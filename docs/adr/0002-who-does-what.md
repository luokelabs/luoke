# 0002 组件分工：模型在主控，理解在记忆，事情在工具，沟通、界面和措辞在 agent；除输入法外都在螺壳.app 里

状态：有效。取代 0014、0022、0028。

## 决定

### 四样角色

| 谁 | 管什么 |
|---|---|
| **主控** luoke-core（用户看到的名字是「螺壳」） | 本机所有模型的加载、内存、功耗、排队和任务调度（0003）；工具按任务要结果，不点名模型。提示词、输出格式、语言上的判断写在调用它的工具里，主控只给通用的推理原语。日历接口和浏览器桥也由主控提供（见下）。装、升级、卸载单独成包的东西（输入法、引擎、模型），包里应用的开启和停用，首次设置。 |
| **记忆** luoke-mem | 一份 `~/.luoke/mem.db`，归用户，不归任何一个工具；唯一下结论的地方（0005）。代码归 luoke-mem，跑在螺壳.app 里。 |
| **工具**（邮件助手、输入法、螺壳搜索、螺壳扫描……） | 把自己那件事做好，把发生了什么写成记录，读记忆的理解来做事；对外给结构化的数据和动作，不给页面和措辞。 |
| **agent** luoke-agent | 唯一主动找用户的出口：把记忆想问的、建议的和各工具的提议合起来，挑时机说；代表用户调用各工具声明的能力；主窗口的界面也在这里（见下）。 |

1. **工具之间不互相调用**，调用工具能力的只有 agent；工具之间读彼此的数据不受限（0001）。
2. **每个工具仍是一个配件、一个身份**，在不在同一个包里都一样。
3. **空闲任务**：任何配件都能在清单里登记「空闲时跑」的命令。主控只决定时机（有空闲算力、用户不在、电量和内存允许），用户回来时让它收尾。
4. **agent 是螺壳.app 里的后台组件**：不单独成 app，不在「应用」列表里单独勾选；设置里有「主动提醒」开关，关掉时窗口和应用管理照旧在。

### 一个螺壳.app

5. **除输入法外，所有 `luoke-` 应用都在螺壳.app 里**：记忆、agent、邮件助手、螺壳搜索、螺壳扫描和以后的新应用。签名只有螺壳一份。
6. **收进来的应用跟螺壳一起整体升级**，不单独换，也不能单独退回；出了问题，出一版新螺壳。
7. **输入法照旧单独一个包**，装在 `~/Library/Input Methods`，由螺壳安装和升级；引擎、模型也单独下载、单独换。
8. 现在都打进包里。以后应用多了可以改成按需下载：版本仍由螺壳的发布清单钉住、跟螺壳整体换，同一个团队签名公证，螺壳起它之前核签名。
9. 通知由螺壳本体代发。

### 主窗口的界面和措辞只在 luoke-agent

10. **主窗口里的一切只在 luoke-agent 仓库里改**：「今天」、右边栏、卡片、各应用的页面（邮件助手、记忆、搜索、扫描）、应用管理、设置。每一页放什么、什么顺序、怎么分组、哪些按钮、什么措辞，都在这里定。
11. **自带的应用只给结构化的东西**（邮件助手、记忆、螺壳扫描、螺壳搜索、输入法，加主控）：
    - 给的是：这是哪一种事、涉及什么、数字多少、什么状态、能做哪些动作和各动作的参数。
    - 不给的是：页面数据、界面描述、句子、标签、按钮上的字、排列顺序。这些一律由 luoke-agent 照数据写，全窗口一个口径。
    - 管到四处：卡片、侧栏的概览、动作做完后的结果、清单里固定的名字（提醒的类别、权限的名字这类由 agent 按代号起）。
    - **内容仍由工具给**：邮件主题、文件名、模型写的摘要、记忆里的理解。这些是用户自己的东西或工具产出的内容，不是界面措辞，agent 原样用。
    - **工具自己带界面描述的卡片这条路不删**：留给 luoke-agent 不认识的工具（第三方），它们照卡片协议自己带界面描述。过渡期自带的应用继续带文字，agent 有结构化数据就用数据、没有才用工具带的文字；数据补齐以后工具一侧的文字可以去掉。
    - 工具里现有的页面层搬到 luoke-agent，由 luoke-agent 牵头和各工具商定怎么搬、先搬哪页；没搬完的页面，工具一侧不再改它的页面内容。
12. agent 缺数据或动作，向工具提；工具遇到要改界面或措辞的事，转给 luoke-agent。
13. **有自己窗口的自己改**，照同一份界面规范：首次安装、升级窗口和菜单栏（luoke-core），输入法的设置和引导（luoke-ime），桌面小精灵（luoke-sprite），手机端原型。
14. 界面照什么做、合之前怎么验，写在界面规范和团队内部的工作约定里，不在这里重复。

### 配件之间的约定

15. **配件清单里的能力只加不改**：能报什么（结构化的数据）、能做什么（动作），以及要的权限（`permissions`，0004）。
16. **资源地址只在协议里当标识**，不交给系统打开；新加的资源用相对 id（如 `summary`、`permissions`、`page/<id>`），完整地址由 luoke-agent 和 luoke-core 一起定。不用自定义 URL scheme 跳到工具的界面（别的程序能注册同名 scheme）。
17. **会改动东西的动作只认用户点按**；自动做事的开关不在清单里写死默认值，由工具照实报当前状态，开和关都是写入，要用户点。
18. **账号、授权码这类凭证不在卡片里填**；卡片只给「去设置」。输入框画在主窗口的设置里，值直接交给工具存进钥匙串，不经过 agent 的模型。
19. **装、卸载、开启、停用每一步要用户点**：只认用户在窗口里的点按，agent 核心（读邮件这类不可信内容的那部分）发不起，不能让注入卸掉别的工具。验签名、Gatekeeper、卸载时「一起忘掉」都留在主控。
20. 还没装的应用，「应用管理」里看到的介绍（一句话、类别、装之前看得到的权限说明）由发布流水线从配件清单抄进发布清单；大小由流水线实测，能在哪档用由配方和评测定，不由配件自己报。

### 主控提供的两样本机接口

21. **日历**：主控提供一个很薄的本机日历接口（EventKit：按时间段读事件、写一个事件并返回编号）；系统的日历权限挂在螺壳名下，只要一次，读写都要。「这封邮件的日程是不是已在日历里」这类判断留在各工具。配方里登记哪些配件能用；第三方配件要用，先得到用户明确同意。
22. **浏览器桥**：浏览器插件碰不到本机，中转（native messaging host）放在主控里：插件经它把当前页的信息交给主控的任务、调用日历接口、往记忆写记录。网页内容一律当不可信的数据，只收固定格式。认页面、站点适配、什么时候提示用户留在插件里，插件是独立的项目。

## 为什么

- 显存、功耗、排队只能有一处管，所以模型归主控；只有记忆看得到所有工具的记录，下结论放在一处，规矩也只用实现一次；打扰只能有一个出口，所以沟通归 agent。
- 每个工具一个 app 的三条理由都变了：系统权限已经授权给螺壳本身（0004）；配方按任务名和版本认，和在不在同一个包里无关；只有输入法必须单独成包，由系统的输入法框架加载。独立应用对用户打扰大、实现也不经济。
- 页面层放在各工具里，一页界面的改动要分到几个仓库去改，做出来的页面和定好的设计对不上，也没有一处能对整页负责。收到一处以后，业务上「该展示什么」由 agent 向工具问清数据的含义来补；结构化数据的接口比「页面数据」和现成的句子稳定，数量会多一些，每一种事都要说清有哪些字段。
- 卡片、侧栏的概览、动作做完后的那句话、清单里写死的名字由各工具带文字过来时，几个工具各写各的句子，口径不一，用户看到的像几个产品拼在一起；所以措辞也收到 agent。第三方工具仍然自己带界面描述，口径做不到统一，这是有意留的：agent 不可能事先认识所有工具。

## 还没定的

- **扩展层**：社区应用、第三方怎么接，照 0003 的任务协议。
- **扫描、搜索要不要挪出螺壳.app 单独升级**：和第 6、8 条冲突，另行讨论，定之前照第 6、8 条。配件发版的其余做法见 0008 第 18–21 条，还在定的部分定稿后直接改那几条。
