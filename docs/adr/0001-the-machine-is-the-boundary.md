# 0001 本机就是边界：数据不出用户的设备，本机组件之间不设隐私限制

状态：有效。取代 0013、0024，并收进 0016 里「下载规则不算外传」一条。

## 决定

### 边界

1. **数据不出用户自己的设备。**
   - 工具和模型只在用户的 Mac 上运行。
   - 数据只在用户自己的设备之间流动，端到端加密，比如经 Tailscale 连回 Mac 的手机 app。
   - 螺壳自己的服务器和用户没选过的第三方拿不到内容，只经手读不了的加密数据或不带内容的提醒。
   - 默认不往外发任何内容；诊断只含元数据，由用户决定发不发。
2. **不算外传的两种。**
   - 写进用户自己选定并已在用的账户：在他的邮箱里归档、加标签、存草稿，往他的日历里加日程。
   - 往本机下载签名过的规则和特征库（病毒库、规则包），不上传任何东西；下载频率守上游的规矩。
3. **本机组件之间不为隐私设限。** 主控、记忆、各工具、agent 要读什么就读什么，包括原始记录、原文和依据，只要能把事做好；agent 可以把依据原文给用户看。
4. **用户随时看得到、改得了、删得掉。** 每条理解都查得到依据，用户可以否定、修改、忘掉。
5. 对外的说法：「你的数据不出你的设备；在你的设备上，螺壳会读它需要的一切，好真正懂你。」

### 凭证

6. **凭证不当内容存。** 密码、验证码、密钥、令牌、完整的卡号和证件号不进记忆，要用时走钥匙串或用户的密码管理器，值不经过模型。过滤只针对这几样，命中时只遮那一串，不丢整段。
7. **例外：螺壳搜索的本机索引可以存原值**，也原样送主控的本机嵌入模型算向量，用户拿完整号码搜得到；交给 agent、画成卡片时再遮，只留后四位。索引目录只有本账户能读、排除出时间机器。名字像密码、密钥、证书的文件不读。
8. **保险箱是方向，没有排期**：凭证的值放在钥匙串里，记忆只记元数据（比如「有一张尾号 1234 的 Visa，在保险箱里」）；值直接填进表单，不经过模型（防注入）；花钱照 0006 永远要用户确认。

### 安全上照旧的

9. 下面这些是安全问题，不是隐私限制，照旧：
   - 密码框等安全输入时不记；
   - 第三方代码（社区引擎、可替换的组件）跑在沙盒里，碰记忆要用户另外同意；
   - 本机服务只监听 127.0.0.1 并带令牌（高级用户的本机端点见 0003）；
   - 删除这类不可逆的操作只在明确的地方做；
   - 推送不带内容，手机上不留记忆副本。

### 本机数据加密存放

10. **记忆和螺壳搜索的本机数据默认加密存放**，两边用同一套办法。加密不改第 3 条：螺壳自己的组件照样能读，挡的是螺壳以外的程序。
    - 防：同一个用户账户里别的程序（各种 AI 助手、同步工具）；从备份、拷贝里流出去的文件。
    - 不在这里管：硬盘被拿走（FileVault 管）；已经拿到 root 的；能往螺壳进程里注入代码的。
11. **密钥归主控。**
    - 默认放在登录钥匙串：跟着这台 Mac 上的这个用户账户走，用开机密码解锁；不放 iCloud 钥匙串，不和 Apple ID 绑在一起。要的是换机时（迁移助理、时间机器）能和家目录一起带过去；具体用哪一种钥匙串、能不能带过去，要先在真机上核实。只认这台设备、换机带不走的那种不做默认。
    - 只交给本体起的固定入口，不放进命令行参数和环境变量。
    - 可选的一档「密钥只留在这台 Mac」：用户自己打开，打开时给一次恢复码，写明丢了恢复码就打不开。
12. **拿不到密钥就不打开**：答「加了密，要螺壳来开」，不另建一份明文。打不开时照实说明原因、不删文件；换回原来的钥匙串或输入恢复码，仍能打开。
13. **迁移**：第一次拿到密钥时，把明文库换成加密的，删掉明文和重新定档前的旧拷贝（库旁的 `-wal`、`-shm`、`-journal` 也算）；页面令牌不再写进文件。
14. **不悄悄做**：设置里写明数据加密存放、密钥在哪、换机时怎样带过去；界面用正式的说法，口语的解释放在「?」帮助或文档里。

## 为什么

- 本机 AI 能赢云端的只有一点：用户的全部数据都在自己机器上，可以毫无保留地交给 AI 去理解。在本机内部再层层设限，就把这个唯一的优势丢了。项目负责人原话：「本来 local 受限于模型和算力就已经要差了，隐私上不放开的话，凭啥用你？」
- 凭证存了对理解用户没用，泄露的损失却最大，所以单独处理；这是安全问题，不是隐私问题。
- 记忆是明文 SQLite，同一个账户下任何程序都读得到，苹果自己的那些库至少还要完全磁盘访问才能读；加密挡的就是这一条。密钥跟着用户的账户走，换机不丢；想要更强保护的人自己保管恢复码，权责对等。

## 还没定的

- **谁来做加密**：0024 原来按项目分了工（主控管密钥，luoke-mem 管加密打开和迁移，luoke-search 用同一套），写在 11-11 分工之前；现在安全相关的改动归发版品控一侧写（0009）。现在的安排：主控和记忆那部分（打包 pysqlite3 和 sqlite3mc、钥匙串里的密钥、旧库迁移）和搜索的索引，由发版品控的两位负责人分别做，都放 beta 2 之后。
- **能不能做**：加密扩展以可加载扩展的方式能不能接管 `-wal`、`-shm` 的读写；输入法沙盒里加载同一签名的扩展，能不能过库验证。
- **换机带不带得走**：登录钥匙串里的密钥，迁移助理和时间机器能不能带过去，还没在真机上核过。
- **哪一版**：不挡 beta 2，下一版做。
- **固定入口**：和完全磁盘访问那边要做的启动器一起做（0004），方案由发版品控的一位负责人出。
