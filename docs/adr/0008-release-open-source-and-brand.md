# 0008 发布、开源和品牌

状态：有效。取代 0017。谁执行、谁点头、推送的权限这些操作上的规矩只写在团队内部的工作约定里，这里写定下来的做法和理由。

## 决定

### 硬件和系统

1. **Apple 芯片、16 GB 起，推荐 32 GB 以上，macOS 26.2 以上。** 首次运行按内存档和芯片照实说能有什么体验。
2. **每个任务在哪一档开，按评测定**：连过 3 遍才开，失败一遍就关。

### 名字和品牌

3. **对外以「螺壳实验室」（Luoke Labs）为主。** 用户装的应用叫「螺壳」（`螺壳.app`）；bundle id、数据目录、命令名 `luoke` 不变。各应用对外怎么叫，照 `CONTEXT.md`「对外怎么叫」。
4. **官网、logo、应用图标、吉祥物原稿、对外文案、招募和 luoke-community 归品牌的负责人**；应用里用这些素材时只拷贝使用，不在各项目里改图。
5. **应用里所有面向用户的界面照哪套规范做，由产品线定**，规范由顶层会话维护。

### 渠道

6. **安装包分两处**：beta 和正式版放公开的 `luokelabs/luoke-releases`；内部版放公开的 `luokelabs/luoke-internal-builds`（预发布、名字标「内部版」，不从官网链出去）。螺壳检查更新按渠道查对应的仓库，并且翻页查，不只看最新一页。
7. **GitLab 镜像**：beta 和正式版每次发布后，同样的文件同步到 gitlab.com/luokelabs/luoke-releases，两边文件和 sha256 一致；官网和螺壳的下载在连不上 GitHub 时走 GitLab。镜像的组和令牌挂在团队的组织账号下。内部版不同步。
8. **内部版每天两版**（10:00、21:00 截，当天发），不用每次问项目负责人；流程写在团队内部的出版文档里。

### 开源

9. **要发给大家用的组件默认开源**，有具体问题才拿出来讨论。第一次随 beta 或正式版发布时用原名建公开仓库，从一个新的初始提交开始，作者 Luoke Labs；开发和团队的 issue 留在 `<名>-private`。
10. 现在公开的：顶层 `luoke`、`luoke-core`、`luoke-mail`、`luoke-mem`、`luoke-ime`、`luoke-agent`、`luoke-search`、`luoke-scan`，以及 `luoke-releases`、`luoke-internal-builds`、`luoke-atlas`、`luoke-contribute`。
11. **许可统一 Apache-2.0**，版权署名「螺壳实验室 Luoke Labs」，NOTICE 写明「螺壳」的名字、图标和品牌素材不随许可授予。邮件助手、记忆从 beta 2 起由 MIT 换过来，已经发出的版本仍按 MIT；agent 里给别的工具直接抄的协议帮手文件可以另按 MIT 用；带进来的第三方程序照它自己的许可。
12. **公开的树由各组件的导出工具从私有仓库生成**，去掉写给 AI 会话的文件、测试机名、人名、私有链接和真实数据。

### 公开同步

13. **怎么同步**：每个组件的 `<名>-private` 里留一个 `public` 分支，内容和公开仓库的 `main` 完全一样；同步时从私有 `main` 导出公开的树，作为一个新提交加在 `public` 上，扫过泄漏后推成公开 `main`。不改写历史。
14. **什么时候同步**：只在发 beta 或正式版时，几个公开组件一起，是发版流程里的一步；项目会话平时不发起同步。导出和推送用团队的机器账号在出版机上做。beta 1.x 的补丁版不做公开同步。
15. **钉哪个提交**：内部版从私有 `main` 出；beta 和正式版只钉 `public` 上的提交，钉住的不在 `public` 上出版机就停。签名、公证、上传令牌、评测机和语料只在出版机上。
16. **私有仓库开不了分支保护**（组织是免费版），不等它：四个公开组件（`luoke-core`、`luoke-mail`、`luoke-mem`、`luoke-ime`）的 `main` 已经保护，只有机器账号能推，后来公开的 `luoke-agent`、`luoke-search`、`luoke-scan` 还没核过；私有仓库里的 `public` 分支靠同步工具只快进、泄漏扫描和推之前项目负责人点头来守，作为已知缺口。
17. **每个公开版（beta、正式版、公开同步）开始前项目负责人点一次头**，其余步骤由发版品控执行（0009）。公开仓库里发现泄漏，立刻修，单独问项目负责人。

### 配件发版

18. **主控不再按版本认配件，配件能不能发由配件发版的 CI 把关。** 现在主控只放行配方「已验证版本」里列着的配件版本；这道检查去掉（原先拟改成按「面向模型部分的指纹」认，也不用），面向模型的部分改了要过评测这条底线，挪到各配件自己发版流程里的 CI。
19. **配件只声明自己需要的主控版本。**
20. 输入法的新功能做好了可以单独升级发给测试者，不等螺壳整体的版；收进螺壳.app 的配件照 0002 第 6 条，换上新产物重出一版螺壳。
21. 清单字段、CI 核什么、在哪几个主控版本上评测，还在定，定稿后直接改本条第 18–21 条。

### 版本节奏

22. 封闭测试那段「只修不加」已经结束；以后只在 RC 截版后只修不加。每一版的范围和日期记在团队内部的范围 issue 里，不写进 ADR。
23. 语音输入不算螺壳整体的功能，作为输入法自己的下一个大版本演进。
24. 现阶段的重点是让受众感到价值：把螺壳搬进虚拟机、给 agent 做隔离环境、做 Windows 版都先不做。

## 为什么

- 内部版和 beta 分两个仓库，外面的人不容易误装内部版；内部版的仓库要公开，因为螺壳检查更新不带令牌。
- 国内用户连不上 GitHub 时也要能下载。
- 外面的人已经开始提 issue，却看不到代码，所以组件默认开源；公开仓库只在发版时同步、公开版只钉公开的提交，用户拿到的就是公开的那份代码。
