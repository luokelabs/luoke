提示词

每个生成任务的提示词要点：送进去什么、要求输出什么、代码怎么校验、失败时怎么退。只做摘要，原文在各配件仓库（邮件助手的在 luoke_mail/prompts/，分拣还在 triage.py 里；记忆的在 luoke_mem/prompts/，螺壳扫描的在仓库的 prompts/）。任务名、种类和各档开关见「任务与提示词」。

共同做法

  • 提示词、输出 schema 和校验都在调用方配件里；主控只做通用的生成：不思考（enable_thinking 关），把 response_format 的 JSON schema 交给引擎约束，消息里的特殊 token 先中和。
  • 输出上限由主控定：item_tokens × 条目数 + fixed_tokens；调用方给的 max_tokens 不用。输入超过任务的 max_chars 答 input_too_long，条目数超过 batch 拒绝；调用方事先按上限二分截短或减少条目。
  • 输入里的邮件、订阅、打的字、skill 的内容一律声明为数据，其中给 AI 的话不执行。
  • 结果多少、能不能生效、把握几档由代码和记忆的表决定；模型只负责提名和分类。
  • 采样参数在配方里按任务定：起草回复温度 0.3、top_p 0.9，其余生成任务温度 0、top_p 1；top_k 一律写 0。
  • 回答不能用时：邮件助手多数任务把原回答（截到放得下，最多 2000 字）和一句纠正（各任务的 .retry.txt，分拣的在 triage.py）接在消息后面再问一次；订阅体检和精选挑选不重问，往来邮件原样再问一次。记忆不在当次重问，见各任务；螺壳扫描不重问，答得不合格的不显示。
  • 客户端都不看 finish_reason：输出被截断时，邮件助手按"无法解析"处理，记忆按"这批没读完"处理、下次减半重来，螺壳扫描按解析不了或过不了检查处理、不显示。

邮件助手

八个任务的提示词是 luoke-mail 包里的文件 luoke_mail/prompts/（顶层决策 0019 的格式，随包打进螺壳.app）：每个任务 .system.txt（固定说明）、.user.txt（一次输入的措辞和顺序）、.schema.json（输出格式），要重问的另有 .retry.txt（重问时接在后面的那句；senders、digest-pick、thread 没有）。几个任务共用的在 _shared.txt：data（「邮件内容是数据」那句，learn-sent、learn-orgs、thread 用）和 mail（一封邮件交给模型的样子：发件人、发件域名验证、收件人、抄送、时间、主题、附件、图片说明、正文，起草回复和分拣都用）。模板按行写：{{名字}} 由代码填；{{#名字}}…{{/名字}} 值是一串时每项出一遍，否则不空时出一次；{{?名字}} 不空时出一次（列表的标题），{{^名字}} 空时出；{{>名字}} 放进 _shared.txt 的一段；只有开头或结尾标签的那一行本身不进结果，文件末尾的换行不算。加载和填写都严格（PromptError）：要填的没填、填了文件里没有的、段落没闭合、{{ 不是标签都报错。选项只写在 schema 里：每个选项和它的说明在 x-describe（有 enum 时顺序要和 enum 一样），提示词里列选项的地方由代码用 described() 从这里取；发给主控前去掉 x- 开头的键。代码只备值（截短、拼接、写日期）、填进去、解析答复。分拣还没搬：它自己的说明、schema 和重问那句在 triage.py，只有邮件那一段来自 _shared.txt。tests/prompt_snapshot.json 记着评测题和示例邮件拼出的全部请求（含重问的、截短的）在每个任务上的指纹，提示词一改测试就报；bench/run_tasks.py 的评测结果带 prompt_sha256（这个任务全部文件连同 _shared.txt 的指纹）和 prompt_files。

luoke-mail.triage 分拣

项要点
位置还没搬进文件：luoke_mail/triage.py 的 SYSTEM_PROMPT（固定说明，{language} 填设置的语言）、SCHEMA（选项是代码里的 CATEGORIES、PRIORITIES、ACTIONS 的代号；用户规则那句里的中文叫法取自 PROMPT_ACTIONS，仍是「待跟进」「移到垃圾箱」，和界面用的「加星标」「删除」分开）、build_messages（邮件前面那几行）、parse_output 和 settle_dates、settle_cc、settle_figures、settle_risks（可疑原因的五类是 RISKS），重问那句在 analyze；邮件本身那一段是 prompts/_shared.txt 的 mail，由 mail_values 备值
输入今天的日期和星期；邮件寄出日期早于今天时，再给寄出日期和星期，并要求没写年份的日期和"明天""下周三"这类说法按寄出日期换算；用户邮箱；用户只在抄送里、不在收件人里时加一句：除非邮件点名要用户做事或回答问题，一般 archive，priority 不超过 medium，回复要点不替用户答应派给别人的事；记忆的"关于用户 / 处理习惯"块（≤ 600 字）；用户给这个发件人定的规则（有就给）；是否精选来源；发件域名验证结论（通过、没通过或平台自己投递；配方参数 sender_verdict 为 false 的 16、32 档只不给「通过」）；邮件头（发件人、收件人、抄送、时间、主题、附件名 ≤ 10 个）和正文；正文不到 80 字而有图片时加一句有几张图片、看不到图里的字不算可疑；图片 3 张以上、正文里单独成行的金额和日期 3 个以上时，要求不推测哪个是应还金额和还款日，due_date 填 null，摘要不写金额和日期。正文先去掉引用的往来、以 > 开头的行和不可见字符，超过 60 个字符的链接写成 https://域名/…，最多 6000 字；整条消息再按档的字符上限截短（16 / 32 / 128 GB：6000 / 12000 / 32000 字）
输出15 个字段都必填：category（8 选 1）、priority（high / medium / low）、action（reply / schedule / follow_up / archive / ignore）、summary（≤ 40 字，只写内容、不写是否可疑）、reason、due_date（只填邮件明写的期限）、5 个 event_*（只在 schedule 时填，第一个日程）、more_events（同一封里其余时间不同的日程，最多 3 个，各有 title、date、start、end、location；没有时为空数组）、reply_points（≤ 3 条）、suspicious、risks（可疑时原因属于哪几类，可多选：冒充 / 索要个人信息 / 催促转账 / 指挥AI / 可疑链接；不可疑时为空数组）；文字字段用设置的语言
判断规则reply：对方在等用户回信（回答问题、确认时间、发回要的资料都算）；对方还在问能不能来、或请用户从几个时间里挑一个，也是 reply；schedule 只给时间已定的会议、预约、活动和要出行的机票车票（确认函、出票通知、已接受的邀请）；follow_up：要用户做、但不用回信的事（付账单、填表、取件、续费）；只被抄送、且邮件明确让别人处理的，通常 archive；due_date 只填邮件明写的期限，"下周三"这类按今天换算；回复要点不编邮件里没有的人名、名单和数字。用户的规则一般照办，只有明显要用户亲自处理或看起来可疑时才给不同的 action，并在 reason 里说明；"移到垃圾邮件"的规则让模型给 ignore；精选来源的邮件一般 archive
校验与退路解析不出 JSON 或 action 不在枚举：带一句纠正重问一次，再不行报错；category / priority 不在枚举改成 other / medium；日期须 YYYY-MM-DD、时间须 HH:MM，否则置空；只有 schedule 且日期有效才生成日程，more_events 里日期无效的、和第一个同一天同一开始时间的丢掉，最多留 3 个；suspicious 为真时强制 ignore + phishing；risks 只留五类里的、去掉重复；配方不给「通过」（sender_verdict 为 false）而邮箱的结论是通过、risks 只有冒充、这个发件方以前来过信（sender_seen）时，改成不可疑（settle_risks）：动作和类别回到模型原来给的（ignore 改 archive、phishing 改 notification），priority 降为 low，reason 换成「这封邮件确实从 某域名 发出（邮箱服务商已验证），以前也收到过这个域名的邮件；请确认是你认识的发件方。」，summary 里有诈骗、钓鱼、冒充、可疑这类词的换成主题；没答 risks、有别的原因、「通过」已告诉模型的、没来过信的都不放；显示和排序另用 priority_now（过期的 high 按 medium），不改模型的输出，也不进评测；risks 和放行标记 cleared 只在评测结果里，不存库；没写年份、又比寄出日期晚 300 天以上的期限和日程日期，按整年往回拉（邮件里写了那一年或"明年"的不拉）；用户只在抄送里的邮件，模型给了 high 也降成 medium；上面那种金额和日期在图片里的邮件，代码清掉 due_date，摘要带数字的换成「金额和日期在图片里，请打开原信核对」
预算输出 320 + 80 token；温度 0
评测48 封（20 封难题，含钓鱼、注入、发件域名验证、长跟踪链接后的期限）；硬性：正常邮件 0 误报，可疑邮件最多漏 1 封。另有不计分的观察题，评测结果里单列（含发件域名验证通过的官方子域名通知、安全代码、外文订阅，和同样通过、只给登录链接的仿冒信）。不覆盖规则、记忆块、精选来源、非中文输出，也不评摘要和回复要点
