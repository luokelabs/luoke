输入法

macOS 输入法。壳负责按键、组字、候选窗和上屏；候选全部由沙盒里的引擎子进程给出。语音输入是随包自带的快捷键引擎，设置里默认关：按住说话、松开上屏，转写和整理都交给主控。个人化组件把上屏写入记忆，把打分和联想请求转给主控，并给语音提供热词。

仓库 luoke-ime · 版本 0.1.88（build 91），按代码 6b827c6 核对 · bundle id ai.luoke.inputmethod.Luoke

结构

部分实现职责
壳Swift：LuokeShell（平台无关的状态机和引擎宿主）+ LuokeIME（InputMethodKit 外壳）；另有共用状态机的命令行版按键、组字、候选窗、上屏、沙盒、转问
打字引擎自带小鹤双拼 xiaohe、自然码双拼 ziranma、全拼 quanpin（苹果转换引擎和 RIME 出候选）。自然码和小鹤是同一个程序，以 --scheme ziranma 运行，只换韵母键位表，声母、零声母、词库和 RIME 的数据都和小鹤共用（RIME 用雾凇自带的自然码方案）；评测时加 --from-xiaohe 把小鹤的按键换成自然码的，600 句语料上和小鹤一样（先给的 78.8%，重排后 89.8%）出候选，经个人化组件请求打分后重排。三个打字引擎都有评测用的选项 pause（毫秒，默认 0）和 pause_when（slow / always，缺省 slow）：键后停顿够久才重排；默认关。另有选项 rerank、rime、gate、budget、rounds、correct（打错纠正，默认开，只有双拼会纠）。
个人化组件engines/personal（Python，仅标准库），运行在主控自带的 Python 上写入记忆；把打分和联想转给主控；给语音热词
语音引擎engines/voice（Swift，程序 voice），快捷键引擎：hotkey 为右 ⌥、按住（hold）、arm；声明麦克风，转问主控和个人化组件，前文 200 字。同一目录放整理用的提示词 tidy_prompt.txt 和示例 tidy_examples.json录音，经壳请主控转写、整理，上屏

进程模型

  • 壳由系统拉起，不进程序坞；用户自己打开 LuokeIME.app 时也作为输入法服务运行。每个输入框一个 Session；全进程一个 EngineManager，主线程每秒轮询配置和引擎状态。带不认识的参数时打印用法退出。只运行一份：父进程不是 launchd 时直接退出；用 $TMPDIR/ai.luoke.inputmethod.Luoke.lock 文件锁占位（最多等 3 秒），已有一份时请在跑的那份按需弹添加引导，自己退出。
  • 换版：每 5 秒读一次磁盘上包里的 build 号，和启动时不同且新包的可执行文件在时，等所有输入框空闲（不在组字、没挂着逗号、不在快捷键会话、联想没打开）且 3 秒没有按键、设置窗口和添加引导都关着，收尾退出，1 秒后用 open -g 从原路径拉起新版。
  • 引擎以 posix_spawn 在独立进程组中启动，命令为 /usr/bin/sandbox-exec -p <模板> …，工作目录是引擎文件夹。run[0] 为 luoke-python 时使用螺壳（主控）包内的 Python：依次找 /Applications、~/Applications 下的 螺壳.app、螺壳主控.app，核对 bundle id ai.luoke.core，不问 LaunchServices；都没有时用 PATH 里的 python3；参数前加 -B -E -s -u。自带引擎用固定 PATH；第三方引擎第一次启动时才解析登录 shell 的 PATH（最多 3 秒）。快捷键引擎平时第一次按到快捷键才启动；声明了 hotkey.arm 的（语音）随壳启动，崩溃后马上重启，不等下一次按键。
  • 通信：标准输入输出上每行一个 JSON，第一条必定是 hello；写入走每个引擎自己的串行队列。
  • 停止：关闭 stdin，1 秒后对整个进程组 SIGKILL。
  • 崩溃与卡死：一次询问 1 秒没有答复视为卡死并杀掉；60 秒内崩溃 3 次则停用该引擎。
  • 退出：收到 SIGTERM、SIGINT、SIGHUP、正常结束或换版让位时，把使用计数写盘、结束系统日志订阅，并向主控发 POST /accessory/exiting（1 秒超时）。
  • 重启条件：每秒轮询读到设置文件变化时，当前引擎、开发模式或模糊音变了才重启打字引擎，语音开关、说完后整理、说话的键变了重启快捷键引擎，记忆开关变了重启个人化组件，确认过的第三方引擎变了全部重扫重启，其余只重新绑定；菜单和设置窗口的改动同样，只在上面这几项变了时重启对应的引擎。另外用户引擎目录变化、非自带引擎的文件变化、options.json 变化、主控 Python 被替换（每 10 秒检查）也会重启。
  • 麦克风：语音打开、壳启动声明了麦克风的快捷键引擎时，系统还没问过就向系统申请麦克风（弹窗里的应用名是「螺壳」，说明用 Info.plist 的「你启用的输入法引擎（比如语音输入）声明需要使用麦克风。」）；用户拒绝了不再问，设置窗口里提示去系统设置打开。

引擎协议

版本 1。完整规格见 luoke-ime/docs/引擎协议.md。

方向消息
壳 → 引擎hello、query（输入、前文、应用）、committed、deleted、forget、forget_all、unforget、arm / start / stop / cancel（快捷键引擎；arm 只发给声明了 hotkey.arm 的，cancel 带原因 esc、key、focus、timeout、short）、ask、reply
引擎 → 壳answer（候选、more、autocommit）、show（可带 hint：光标旁的提示；listening：是否已经听到声音）、commit、end、ask、reply

引擎说明 engine.json

  • 必填 protocol（=1）、name、kind、run；打字引擎需 input_keys，快捷键引擎需 hotkey（key、mode，可选 arm：只能和 hold 一起用，按下那一刻先发 arm）。
  • 转问：向个人化组件只能请求 score、ping、hotwords（热词只给自带的引擎，第三方的答 not_allowed），predict 只有壳能发起；向主控只能问 luoke-ime. 开头的任务，方法有 score、continue、predict、tasks、warmup（可带 lease_id 续期）、generate、transcribe，壳只转发、不看内容（见「主控任务」）。
  • 可选 context（0–2000 字前文）、app、feedback、forget_all、asks（⊆ personal、hub）、options、punctuation。
  • permissions：network（none / local / any）、write（≤ 16 个路径）、local_ports、microphone、camera、screen、gpu、memory（只有个人化组件能声明）。
  • 声明 asks: personal 的引擎只能 network: none，或 local 并用 local_ports 限定端口；个人化组件不能联网，不能声明麦克风、摄像头、屏幕，asks 里只能有 hub。
  • 设置里的「语音输入」管所有声明了麦克风的快捷键引擎（包括第三方的）：关着时不启动、不要麦克风；选的说话键盖过它们的 hotkey.key；「说完后整理」经 hello 的选项 tidy 交给它们。

第三方引擎

  • 声明联网、GPU 或写权限的第三方引擎不能启用；声明麦克风的可以确认启用，受语音开关管，拿不到热词。
  • 启用需要用户确认，确认记录绑定引擎说明的指纹（关键字段 SHA-256 的前 16 字节），说明变化后需重新确认。
  • 不会被自动选中；与自带引擎同名时使用独立的数据目录 <id>.third-party。

候选流程

  1. 按键经 MacKeys.translate 翻译，进入会话；空闲时按下输入键会读取前文（安全输入时不读）。
  2. 壳向打字引擎发 query；只采用最新一次询问的答复。不标 more 的答复一到就画；标了 more 的最多等到发问后 50 ms 再画。
  3. 打字引擎先给快答复（改选过的词、苹果候选、RIME 补充），能重排时标 more；再经壳把 score 转给个人化组件，个人化组件转主控 luoke-ime.rerank，最多等 0.7 秒。
  4. 逐词重排：模型得分须比苹果整句首选高出阈值（自然对数 3）才替换；换掉首选时补发答复，界面让新首选淡入。
  5. 空格、数字、标点等收尾键在还没有任何答复时先等第一份答复，最多 1 秒（判定卡死）；卡死则按原始字母上屏，数字原样交给应用。之后最多再为补发等 150 ms。回车、Esc 不等。上屏后，空格或数字选中的会接着请求联想。
  • 快答复：顺序是改选过的词、苹果的候选（emoji 最多 2 个）、整串读得通时 RIME 的候选。英文单词：整串读不通时排第一，读得通时排第二且至少 4 个字母，超过 12 个键不查；大写字母开头只出英文。重排要整串读得通、至少两个音节、这串键上没改选过。标了 more 时候选末尾有个呼吸的 ✦，模型换掉的首选后面带 ✦，打错纠正出的整句带 ✎。双拼时丢掉苹果只按音节开头读出的候选（键是 zhen miao，苹果按 zhen mi 读出的「缜密」不要；开着模糊音时只差一个 g 的放行）。用户停手 0.3 秒后从头不限步数再选一遍，结果不同就补发。已定的词沿用：双拼往后看够 8 个键、全拼 12 个键才沿用。
  • 打错纠正（只在小鹤、自然码，选项 correct 默认开）：整串读不通、至少 4 个键、这串键上没改选过、有模型时才纠，读得通的不会被改。在第一个读不通的键往前 4 个、往后 2 个键里改一处：换成相邻的键、补一个相邻的键、删一个键、对调相邻两个键，只留改完键数成双、整串读得通的。每种改法取苹果的整句首选（没有就取 RIME 的），去掉这串键上忘掉过的和重复的，最多 20 个（小档 10 个）交模型按前文打分，最高的随补发排第一、标 ✎，认识的英文单词仍在它前面；没有能用的改法或模型出错就以快答复为准。这时快答复也标 more。引擎启动自检多一项打错纠正。
  • 日期和时间：打出「日期」「时间」「星期」「农历」这几个词本身时，这会儿的值跟在它后面：日期给 YYYY-MM-DD 和「Y年M月D日」两种，时间给「时:分」，星期给「星期几」，农历给干支、生肖和月日（如「丙午马年九月二十六」）；三个方案都按打出的词触发，不用别的触发码。
  • 以词定字：组字中按 [ 只要高亮候选的第一个字、] 只要最后一个字，这个候选用掉的键算打完，剩下的键接着打；全打完就直接上屏、接着请求联想。还没有答复时先等第一份，候选还没画出来时这一下只把候选画出来；没有候选时照常当标点。上屏反馈里这一段带 char（first / last）。
  • 慢的机器换小档：主控在 GET /tasks 里给 rerank 标 slow，个人化组件每 60 秒读一次、随打分答复带上；引擎据此换小档：完整档每步给 12 / 4 / 8 个候选（苹果 / 单字 / RIME）、步数不限，小档 6 / 2 / 4、最多 2 步。
  • 引擎怎么学：选了非首选就记一次，下次放首位；分几段选出来的一整段全是汉字且不超过 8 个字时，整串键也记住拼起来的词；切走时的自动上屏和以词定字的那一段不学；「清掉学到的词」保留忘掉的名单。
  • 模糊音（0.1.38 起，默认关）：z = zh、s = sh、c = ch、an = ang、en = eng、in = ing 六组，打开后默认全勾，三个打字引擎共用一份设置，壳经 hello 的 fuzzy 交给引擎（盖过 options.json 里的同名值）。苹果那一路用私有接口 MecabraSetFuzzyPinyinPairs，系统没有这个函数就不开；RIME 那一路在拼写规则最前面插入，an = ang 不含 ian / iang、uan / uang。打开后 600 句整句首选约降 1.5–2 个点。
  • 拼音显示位置：默认显示在输入框里（显示串），可按全局或应用改成显示在候选窗里。
  • 中英文间自动空格（设置里开着时）：上屏的一段和光标前的字之间、上屏的这一段里面都补，快捷键引擎的显示串也一样。
  • 「-」：第一页按「-」（翻页键为 - 和 = 时），已选部分和拼音串照原样字母上屏，再交给应用一个「-」（可打 luoke-ime、gpt-4）；不在第一页照旧翻页。
  • 数字后的标点：数字后按逗号先挂在光标处，接数字上屏半角「,」，接别的键上屏「，」，退格就不要；数字后的「.」「:」保持半角。
  • { }：中文状态下默认打成「」（设置里能关），不看引擎的标点表。
  • 忘掉一个词：候选上按 Shift+⌫，告诉打字引擎和个人化组件。

联想

  • 在空格或数字选词、标点、以词定字上屏、快捷键引擎（包括语音）上屏、选中联想后触发；开不开按应用算：应用设置优先，没设时终端（Terminal、iTerm2、Ghostty、Warp 等）默认关，其余跟随全局；个人化组件须在运行。上屏后 0.25 秒内没有按键才发出请求，期间按键即取消。
  • 个人化组件请主控续写（/v1/continue，k=8、最多 6 个 token、遇标点停），开头的 token 是汉字、概率 ≥ 0.2 的才要；再从最近 5000 段上屏中找用户写过的接续（最多 3 个，至少 2 个字、全是汉字），交 luoke-ime.rerank 打分（加上续写里把握最大的那个开头作参照），每个字平均对数概率不低于 -1 才留下。两路放在一起按每字平均对数概率排，去掉单字，最多 5 个。没有模型（主控不可用）时不给联想；给写过的接续打分失败时只给模型的。老主控没有 /v1/continue 时退回 /v1/predict。
  • 发出后 1 秒内无答复则放弃；未激活时淡显前 3 个、不放显示串，按键照常交给应用，4 秒后收起；按 Tab 激活后列出全部，数字、空格选，方向键和 Tab 移动，Esc、回车、退格收起；激活后高亮的那个放在光标处当显示串（拼音显示在候选窗里时也一样），免得 Chromium 把 Tab 交给网页。
  • 有的应用（Grok 这类 Electron 应用）在输入法接下 Tab 后自己又插一个制表符：选词时连它一起换掉；收起联想时不去掉。

语音输入

随包自带的语音引擎，在设置「通用」里打开（默认关）。按住说话键（默认右 ⌥，可换成右 ⌘、右 ⌃）说话，松开上屏；识别和整理都由主控在这台 Mac 上做（任务 luoke-ime.transcribe、luoke-ime.tidy）。

  • 按键：按下说话键（不在快捷键会话中、不在密码框）就发 arm，引擎开始录音；同一个键 0.3 秒内又来一次按下算同一次。按满 150 ms 且期间没按别的，用同一个号发 start，带光标前最多 200 字（正在组字的先上屏）。不到 150 ms 松开发 cancel short，按着时按了别的键或鼠标发 cancel key，切走发 cancel focus。松开发 stop，10 秒还没结果就把显示着的字上屏、发 cancel timeout。会话中按 Esc 什么都不上屏，按别的键先把显示着的字上屏，再照常处理这个键。
  • 录音：收到 arm 才开麦克风（AudioQueue，只开输入设备），16 kHz 单声道 PCM16，0.1 秒一块；start 之前只录不送。默认输入是蓝牙耳机、机器有内置麦克风且盖子没合上时，改用内置麦克风；内置麦克风开不了或开头 0.3 秒全是零，换回默认输入（选项 bluetooth_mic 为 true 时一律用默认输入）。松开、取消、结束时马上关麦克风，不等识别和整理；0.5 秒内又来一次 arm 就接着录。
  • 光标旁的提示：还没收到声音时黄点闪「准备中…」，有声音了红点跳「正在听」，松开后灰点呼吸「识别中…」，整理时「整理中…」；字比别的提示大、颜色深。识别出的字作为显示串放在输入框里，还没上屏。
  • 草稿：每 0.5 秒（内存 24 GiB 及以下的 Mac 1 秒）送新录的音频、要一份草稿，同时只有一份在算；新草稿多出来的字每 40 ms 逐字补出，前面变了的字就地换掉，不删了重打。听到说话的块（音量约满幅的 1%）不到 0.3 秒时不显示草稿，松开后也不上屏。
  • 分段：这一段说到 30 秒以后在停顿处分段，一直不停顿时 100 秒硬切（主控一次最长 120 秒）：先要这一段的终稿、在后台整理，再开新的一段；显示的是前面各段的原文接上这一段的草稿。
  • 终稿和上屏：松开后等录到的音频都送出去再要终稿；各段都整理完（最多等 2.5 秒）一起上屏，没整理成的用原文；整段是空的就不上屏。
  • 整理（「说完后整理」开着时）：先由代码去掉单独成段的「嗯、呃、啊、额」，只剩语气词的那段算空的；再交 luoke-ime.tidy 去口头禅、理顺改口，写成书面的数字和英文（提示词见「提示词」页）。结果的字母和数字个数不在原文的 0.5 倍到 1.3 倍加 2 之间、2.5 秒没回来或出错，都用原文。
  • 数字（整不整理都做）：连着 5 个以上的汉字数字逐位换成阿拉伯数字；紧跟在英文后面的汉字数字（可带十、百、千、两、点）换成阿拉伯数字，和英文之间空一格，后面跟量词的不换。
  • 上下文和热词：交给转写的 context 开头一行是「常用说法：」加热词（hello 和每次 arm 时向个人化组件要 50 个，5 分钟内不重复要），后面是光标前的字接前面各段原文的最后 300 字；转写结果里连着出现 4 个以上热词的一串去掉。
  • 出错：superseded 丢掉这份草稿；session_lost 这一段从头重送；not_ready、busy 按 retry_after 重发（缺省 1 秒，最多 3 秒）。还没识别出字时遇到 unsupported、task_unavailable、unavailable，光标旁说明原因（「这一版螺壳还没开放语音输入」「螺壳的语音模型还没准备好，稍后再试」「没连上螺壳，语音输入用不了」），不再送音频，松开 2 秒后结束、不上屏；别的错误用最近一份草稿顶上，尽量不丢字。取消时已经 start 过的，告诉主控 want: cancel。
  • 上屏以后：写进记忆（ime-commit，kind 为 hotkey），接着请求联想；不记使用计数。

安全

  • 安全输入（IsSecureEventInputEnabled）：不读前文、不写记忆、不打分、不记使用计数，快捷键引擎不触发、不发 arm（语音不会往密码框里出字）；一段组字中碰到过安全输入，整段都按安全输入处理。
  • 沙盒：默认拒绝；禁止读取钥匙、凭据、浏览器、邮件等 40 多个路径和整个 ~/.luoke（只放行自己的文件夹）；不许创建符号链接；禁止借助 open、osascript、剪贴板等外发。引擎连分布式通知（com.apple.distributed_notifications 的 mach-lookup）照样拒绝，但算轻的，只记日志、不进菜单（录音组件会顺手连它）。
  • 拦截上报：每条拒绝带标签，壳读取系统日志，严重的列入菜单。系统日志订阅（log stream）套在一个 sh 里，输入法退出（含被强制结束）时随之结束。
  • 语音：音频只在语音引擎的内存里，这次听写结束就丢，不写盘；壳原样转发、不看内容，也不把应用告诉语音引擎。交给转写模型的上下文是常用说法（热词）和光标前的字接前面各段原文的最后 300 字。语音程序单独签名，权限只有麦克风（com.apple.security.device.audio-input）。

安装与添加

LuokeIME --register 只注册（macOS 26 起不再请求启用，须用户在系统设置里添加）；--status 输出一行 JSON（state：not_registered / not_added / added_not_selectable / ready，另有 registered、added、consent_list、tis_enabled、tis_selectable、current、other_copies（含废纸篓里同一 bundle id 的包）、version），供螺壳的首次运行向导和诊断用；--select 切换后另起进程核对，调用失败退出码 1，调用成功却没切过去退出码 3；另有 --disable、--current。配件清单的 capabilities.listing 给出「添加应用」时显示的一句话介绍（tagline：「小鹤、自然码双拼和全拼，本机模型帮你挑词、往下联想，从你打的字里学」）和类别「输入」（category），不写 permissions。用户自己打开 LuokeIME.app 而还没添加时弹添加引导，每秒检查，加好后提示去任意输入框试打。引导和安装、卸载脚本的提示都用系统设置的原词「键盘 → 文字输入 → 输入法 → 编辑…」；引导卡片右上角能点开「图文教程」：三步，每步一张系统设置的截图（简体中文、浅色，缩到 900 宽）配一句话，可以上一步、下一步、返回，加好了自动退出（--render-guide tutorial1|2|3 能单独画出这几页）。螺壳首次设置的完成页用同一套教程。

自带的 librime 在编译时把源码路径换成相对路径（-ffile-prefix-map），组装时删掉它自带的全部 rpath 和 rime_helper 指向 vendor 的 rpath；编好的版本标记对不上就重编，没有 cmake 就报错退出、不删旧的。安装脚本对两个壳程序 strip -S，组装完在整个 .app 里查编译机的仓库路径，查到就失败。

系统要求

螺壳只在 macOS 26 起安装输入法（清单 min_macos 26）；LuokeIME.app 本身的最低系统是 14.0，供手动安装验证旧系统。只编 arm64（Apple 芯片）。

评测

  • 首选准确率（600 句博客语料）：苹果 78.8%；完整档重排 89.8%（小鹤、自然码、全拼一样）；小档 88.8%。
  • 逐键打字到选好：M5 Max 完整档 p50 / p90 42 / 70 ms；M1 小档 150 / 183 ms。
  • 联想（去掉单字联想、写过的接续要模型点头以后）：博客语料约 7% 的上屏出联想，出联想时第一个对约 26%；用户自己最近一周的上屏（eval_personal.py，读记忆文件的副本，只报比例）上出联想 11.6%、出了却全不对 8.7%、每百次上屏省 6.8 个键。
  • 打错纠正：每句照真人的比例随机打错一处，博客 600 句首选 4.3% → 22.2%（改错 0），另一份 720 句 2.1% → 16.4%；打对的句子三份答复逐条不变；纠出的那份用时中位 79 ms。
  • 语音转写（evals/transcribe）：44 句自己写的句子用系统的 say 现合成，照语音引擎的用法 1 秒一块、要草稿和终稿，另加两条按住不说话；总分字准确率（数字一类不算），硬性条目是按住不说话不出字。internal-1109：16 档 98.7%，32、128 档 99.2%。
  • 语音整理（evals/tidy）：42 条，分口头禅、改口、数字、英文、停顿的逗号、英文后的数字、照留、像指令的八类，照引擎的做法（去语气词、换数字、长度检查）评；总分是整理后的字准确率，硬性条目是照留和像指令的一个字不改。internal-1109：16、32 档（9B）97.7%，128 档 99.2%。
  • 工具：bench.py、eval_predict.py、evals/transcribe/eval_transcribe.py、evals/tidy/eval_tidy.py，都能用 --result 写证据（任务名 luoke-ime.*），往标准错误打进度（每 50 条，转写每 10 条），供主控的发布脚本判断有没有停住；bench.py 读到「答完」时最终答复还没到，再等最多 2 秒；转写没评成时退出码 3。主控的发布脚本每档跑这四个评测，打分、联想这类评测总时长超过 1 小时会被停掉。发布时的硬性条目：重排改错不超过 max(3, 1%)；出联想 ≥ 3%、出时第一个对 ≥ 25%；按住不说话不出字；照留、像指令的不改字。

已知限制

  • 打分和联想不读记忆中的理解，没有个人化；只有语音的热词读常用说法。
  • 候选窗不能用鼠标点选；引擎选项没有 A2UI 界面。
  • 快捷键引擎不检查冲突；装了两个声明麦克风的快捷键引擎时都用设置里的说话键，壳只认第一个。
  • 个人化组件卡死不检测；转问没有限流。
  • 打错纠正只在双拼，只纠整串读不通的，每次只改一处。
  • 苹果转换引擎依赖私有库 libmecabra，系统升级后可能失效；引擎启动时自检（给不出「你好」就退出，全拼还要求能拿到音节长度），壳把这当崩溃，60 秒内 3 次就停用。
  • 候选多于一批（默认 16，完整档每步最多约 20 个）时壳串行分批打分，可能赶不上引擎每步等的 0.7 秒。
  • 语音：内存 24 GiB 及以下的 Mac 默认不整理；整理 2.5 秒没回来就上屏原文。
  • 快捷键引擎（包括语音）上屏后的退格不转给个人化组件。
  • 引擎停用、被沙盒拦下只在候选窗提示和菜单里显示，不发系统通知。
  • 收起联想时，应用自己插的制表符留着。
