决策

影响多个组件的设计决策以 ADR（Architecture Decision Record）记录，原文保存在顶层仓库 docs/adr/。现在有效的是 0001 起的十条，每条只写现行的决定，变了就直接改写正文。2026-11-18 以前的 0013–0028 已并进这十条，旧路径各留一个占位文件，旧号和新号的对照在 docs/adr/README.md。

编号决策要点
0001本机就是边界数据不出用户自己的设备（设备之间端到端加密）；写进用户自己选定并在用的账户（他的邮箱、日历）不算外传。本机组件之间不为隐私设限，要读什么就读什么；每条理解都查得到依据，用户能否定、修改、忘掉。凭证（密码、验证码、密钥、令牌、完整卡号和证件号）不进记忆，走钥匙串，值不经过模型，命中时只遮那一串；螺壳搜索的本机索引可以存原值，交给 agent 或画成卡片时再遮。记忆和螺壳搜索的本机数据默认加密存放，密钥归主控，拿不到密钥就不打开、不另建明文。
0002组件分工，一个螺壳.app模型在主控，理解在记忆，事情在工具，沟通、主窗口的界面和措辞在 agent。工具之间不互相调用，调用工具能力的只有 agent；每个工具仍是一个配件、一个身份；空闲任务由主控定时机。除输入法外所有应用都在螺壳.app 里，跟螺壳整体升级，签名只有一份，通知由螺壳代发；输入法单独一个包，由螺壳安装和升级。主窗口里的一切（「今天」、右边栏、卡片、各应用的页面、应用管理、设置）只在 agent 里改；自带的应用和主控只给结构化的东西（哪一种事、涉及什么、数字、状态、能做的动作和参数），卡片、概览、动作结果上的句子和固定的名字由 agent 照数据写，邮件主题、文件名、摘要、记忆里的理解算内容、仍由工具给；工具自己带界面描述的卡片留给 agent 不认识的工具和过渡期。清单里的能力只加不改；会改动东西的动作只认用户点按；凭证不在卡片里填；装、卸载、开启、停用每一步要用户点。主控另提供日历接口（EventKit）和浏览器桥。
0003推理、模型和调度归主控本机的模型推理和权重都归主控，工具按任务要结果、不点名模型，不自带模型也不自己加载；垂类模型同样做成主控的任务；一直加载的小模型（语音转写、搜索的嵌入）由主控按任务管内存。唯一的例外是没装螺壳时的小精灵。调度在主控，引擎只管跑模型；螺壳自己的任务协议：任务声明优先级、权限、资源，自己的组件和外来应用走同一张任务表，外来应用照协议自己接入；任务队列在右边栏看得见。引擎换成螺壳自己做的，在单独的仓库里做。高级用户的本机端点：127.0.0.1 上的 OpenAI 兼容端点，默认关，只听本机、校验 Host、拒绝带 Origin 的请求，请求文字不落盘。
0004系统权限授权给螺壳本身完全磁盘访问这类系统权限只授权给螺壳本身，螺壳扫描、螺壳搜索复用这一份。组件不直接向系统要权限：要用的在清单里声明（permissions），经螺壳请求。用户在「应用管理」里开启组件时确认一次，不在第一次用到时再弹第二个框；所有授权请求都紧跟在用户操作之后弹；权限页列出每个组件确认过什么。
0005记忆怎么想工具只记发生了什么（谁做的、什么时候真正发生，可以带原文），不下关于用户的结论；记忆读原文去理解、下结论。三档把握程度：猜测、比较确定、确定，工具只用比较确定以上的，确定只来自用户说的或确认的。先粗后细，按用户的确认、否定、撤回逼近；按依据里最新一条的真实时间算新鲜度，太久没有新依据的算「以前的事」；同一机构的事实合成一条；空闲时反刍，产出「想问的」和「建议」，只提议不动手；用户对理解说的话归记忆，卸载工具时留着；不按上下文隔离记忆。
0006替用户做事能撤回、不毁灭的（归档、标已读、加标签），用户确认一次之后可以自动做，每次提示做了什么并能撤销，撤销算这条习惯的反证。不可逆或对外的（删除、标垃圾邮件、退订、发信、花钱、往外传数据）永远要用户自己点。邮件先做、事后复查，每天一个复查页；推荐给螺壳开一个独立邮箱。螺壳扫描按确定的规则挑出的四类不用先确认就清、事后能放回，开启条件是规则评测「不该删的误判为 0」；其余照旧要用户点。
0007提示词放成文件每个用到模型的配件，提示词放在 prompts/ 里，每个任务一组纯文本文件；代码只读文件、填占位符、发请求和解析，占位符加载时严格核对，枚举只写在 schema.json。系统文档的「任务与提示词」页从各配件的 prompts/ 生成；每个任务的评测证据带 prompt_sha256；每个用到模型的任务都要有评测集；改了提示词的改动附评测结果，安全相关的附改动前后三档的逐题对比。
0008发布、开源和品牌Apple 芯片、16 GB 起、推荐 32 GB 以上、macOS 26.2 以上；每个任务在哪一档开按评测定，连过 3 遍才开、失败一遍就关。对外以「螺壳实验室」（Luoke Labs）为主，用户装的应用叫「螺壳」。beta 和正式版放 luokelabs/luoke-releases，内部版放 luokelabs/luoke-internal-builds，发布后同步到 GitLab 镜像。要发给大家用的组件默认开源，许可统一 Apache-2.0，名字、图标和品牌素材不随许可授予；公开的树由导出工具从私有仓库生成，只在发 beta 或正式版时同步。主控不再按版本认配件，配件能不能发由配件发版的 CI 把关，配件只声明自己需要的主控版本。只在 RC 截版后只修不加。
0009产品线和发版品控分开螺壳的产品代码归产品线一处迭代；所有应用是同一个架构，界面和交互在 agent，业务逻辑在各自的后端。发版和品控是另一条线：出版流水线、截版和发布、公开同步、评测、配方的验证、配件发布的 CI。品控按版本做，不按 PR 做：没过就报哪一项没过、卡在哪个提交，怎么修由产品这边定。推理引擎和专用小模型作为科研单独做。两条线之间只有三样往来：交版本、回结果、报进展。
0010螺壳小精灵给还没装螺壳的人的轻量入口：检测这台 Mac、把模型跑起来、做一次本地 AI 能力的自检并给出实测数字，再介绍螺壳。在螺壳之外：不进配方、不由螺壳安装、不读写记忆。16 GB 内存、macOS 26.2 起。没装螺壳时可以自带一个小模型，是 0003 唯一的例外；装了螺壳就删掉自己下的模型，改用主控的任务接口。模型要在国内下得动；数字照实说。

设计原则

  • 合理默认，按反馈逼近：不要求用户事先设定规则或逐条审阅；用户的确认、否定和撤销就是调整的依据。
  • 测试版不过度保守：能撤回的能力默认开启，配上提示和撤销，通过真实使用检验。
  • 本地优势不打折：在本机内部充分使用数据，体验才能弥补本地模型和算力的差距。
  • 产出要像用心的助理：理解要说清领域和具体对象，不照搬标题或品牌名。
