决策

影响多个组件的设计决策以 ADR（Architecture Decision Record）记录，原文保存在顶层仓库 docs/adr/。0001–0012 已归档，下列为当前有效的决策。

编号决策要点
0013本机就是边界数据不离开用户自己的设备（设备之间端到端加密）；本机组件之间不为隐私设限；凭证不进记忆，走钥匙串；高级用户端点的密钥可自定义或留空。修订（2026-10-21）：写进用户自己选定并在用的账户（他的邮箱、日历等）不算外传，内容仍不能发到螺壳自己的服务器和用户没选过的第三方；深度搜索的本机索引可以原样存文件里认出的完整证件号、卡号，也原样送主控的嵌入模型，交给 agent 或画成卡片时再遮（只遮那一串、保留后四位），名字像密码、密钥的文件照旧不读，记忆仍不存凭证的值
0014分工模型在主控，理解在记忆，事情在工具，沟通在 agent；工具之间不互相调用，只有 agent 调用工具的能力；高级用户端点经主控调度。修订（2026-10-21）：日历由主控提供（EventKit 薄接口：按时间段读、写一个事件并返回编号，日历权限挂在主控名下，配方登记哪些配件能用，第三方配件要先得到用户同意，beta1 之后做）；浏览器桥（native messaging host）也放在主控里，插件经它把页面信息交给主控的任务、调用日历接口、写记忆记录，网页内容只接受固定格式。修订（2026-10-24）：用户看到的应用「螺壳」就是主控（螺壳.app，bundle id 仍是 ai.luoke.core）；agent 并进它，对话、卡片、提示从螺壳的窗口和通知出去，agent 作为后台组件保留，分工不变 修订（2026-11-02）：主窗口由 luoke-agent 这边写，写完开 PR 大家一起审，主控不排窗口外壳，也不写 A2UI 渲染；装、升级、换回、卸载仍归主控。修订（2026-11-06，跟 ADR 0022、0021 对齐）：「每个工具一个签名的 .app」作废，除输入法外都在螺壳.app 里，签名只有螺壳一份，每个工具仍是一个配件、一个身份；装、升级、换回现在只对单独成包的输入法、引擎、模型，包里的应用在「应用」窗口里开启、停用（停用时可选同时删数据），没有单独退回，出了问题出一版新螺壳来修；工具不再自己向系统要权限，经螺壳要。
0015记忆如何形成理解工具只记录、记忆读原文下结论；三档把握程度；合理默认、按反馈调整；看依据的时间；空闲时反刍产出提问和建议；不按上下文隔离
0016替用户做事能撤回的在确认习惯后自动执行并提示，事后每日复查；不可逆或对外的始终由用户点按；agent 自己的邮箱可按类型放开外发。修订（2026-10-20）：系统检查查出的"会重建的缓存"（npm、uv、pip、Xcode DerivedData、Homebrew 旧版本等）用户确认一次后可对该类自动清理，每次提示，对应应用在用时跳过；其余类别每次由用户点按，删除优先移到废纸篓；只往本机下载的签名规则包、特征库不算数据外传
0017v1 首发首发邮件助手和输入法，主控和记忆随装；Apple 芯片、16 GB 起、macOS 26.2+；先封闭测试再公开。修订（2026-10-20）：所有面向用户的界面按同一套设计规范，由品牌负责人在 luoke-brand 牵头制定，各项目照着改；beta1 只修明显的不一致，整体改版在 beta1 之后；顶层仓库公开，各组件仓库仍私有。修订（2026-10-22）：主控的所有窗口和邮件助手的网页在 beta1 前按设计规范整体改，记忆界面、输入法设置、agent 卡片仍在 beta1 之后；封闭测试顺延到 11-02，只做一批，招满 30 位为止，开测时对应的项目在 GitHub 上公开。修订（2026-10-23）：记忆页和输入法设置也在 beta1 前改（agent 卡片仍在之后）；主控里加「应用」窗口，各应用单独安装、升级、换回、卸载，升级主控不再顺带替换应用；「螺壳主控」改名「螺壳」，bundle id、数据目录和命令名不变；版本截止 10-28 20:00，beta1 10-29。修订（2026-10-28）：内部版换到单独的公开仓库 luokelabs/luoke-internal-builds，luoke-releases 只放 beta 和正式版，螺壳按渠道查对应仓库，过渡的那一版两边都发；检查更新往后翻页，随 beta1.1。螺壳、邮件助手、记忆、输入法四个组件公开：原名是公开仓库，从新的初始提交开始，团队开发和 issue 在 <名>-private，往公开仓库同步每次先问主人。修订（2026-10-29）：beta 和正式版的发布包在 GitLab 上放一份镜像，GitHub 仍是主渠道；私有仓库留一个和公开仓库 main 完全一样的 public 分支，同步时把导出的树作为一个新提交加在上面，扫过泄漏再推成公开 main，不改写历史。修订（2026-10-31）：公开仓库只在发 beta 或正式版时同步，四个组件一起，是发版流程里的一步；从下一个公开版起，beta 和正式版只钉 public 上的提交，内部版照旧从私有 main 出。公开仓库发现泄漏时立刻修。修订（2026-11-01）：要发给大家用的组件默认开源，体检、agent、深度搜索第一次随 beta 或正式版发布时建公开仓库；agent 和体检一起上，和螺壳窗口进同一个 v1.x，用户看得到清了什么、点得到「放回」之前，体检不开放 修订（2026-11-02）：下一版是 beta 2，以 agent（螺壳主界面）上线为放行标准，体检和深度搜索一起进，这两个的名字可能改；语音输入作为输入法下一个大版本自己演进；会议纪要等放到 beta 2.x 讨论。 修订（2026-11-03）：开源许可统一用 Apache-2.0（邮件助手、记忆从 beta 2 起换）；输入法这类应用的新功能做好了可以单独发给测试者，不必等螺壳整体的 beta。修订（2026-11-06，跟 ADR 0022 对齐）：主控和应用分开升级、应用自己发版，现在都只对输入法；收进螺壳的应用要发新版，就出一版新螺壳。
0018推理和权重归主控体系内没有脱离主控的模型运行实例；垂类模型也做成主控的任务，对延迟敏感的走优先通道。修订（2026-10-20）：嵌入任务由深度搜索（luoke-search）接手，任务名由 digup.embed 改为 luoke-search.embed，接口、评测和多模态安排不变
0019提示词放成文件每个用到模型的配件在仓库根目录 prompts/ 里按任务放 system、user、retry 的 .txt 和 schema.json，代码只读文件、填占位符；枚举只写在 schema 里；本站「任务与提示词」页改为从各仓库生成；出版证据记 prompt_sha256；没有评测集的任务补齐。修订（2026-11-04）：现在开始搬，Python 配件可以放在包目录里（如 luoke_mem/prompts/），没有重试的不写 retry、没有共用句子的不写 _shared，可选段写 {{#名}}…{{/名}}；改了提示词文件的 PR 要作者以外的一位成员 Approve，安全相关的提示词还要附改动前后三档的逐题对比，只看总分不算数
0020引擎换成自己做的薄引擎只服务配方模型，底层用官方 mlx-lm，不换 mlx-serve。先进内部版，beta 线和 11-02 的测试不换；推理和权重仍归主控（ADR 0018）。现在的引擎还是 oMLX。
0021完全磁盘访问授权给螺壳本身用户只授权一次，螺壳扫描、螺壳搜索复用；本体起主控时 disclaim，主控、引擎、工作进程都脱离；要读全盘的程序由本体核过声明和签名后起；清单按程序写 "permissions": ["fda"]。请求授权的卡片要等主控起 jobs 前核签名和版本、旧版回退、测试机实测都做完才出。螺壳扫描这边已改（读磁盘的程序跟着螺壳用授权，没有授权时卡片请用户给「螺壳」打开）；主控这边的脱离还没做；起螺壳里的程序前核签名的有螺壳扫描、螺壳搜索。修订（2026-11-06）：组件不直接向系统要权限，向螺壳请求，用户同意后螺壳先查自己有没有、没有再向系统要；螺壳扫描这类要敏感权限的，在「应用」里开启以后由螺壳拉起一次，当场把权限要到，不在跑的时候突然弹窗。哪几条跟着改、授权卡片跟不跟 beta 2 还没定。同日补记现状：本体要起什么写死在本体里，不读清单，权限页才读清单里的声明；空闲任务由主控起螺壳的 --run-tool，核过再起工具；权限状态还没由本体报，现在是扫描自己探测；「主控脱离」等 disclaim 在真签名下的实测结果再定。同日 johnz 定：只在「应用」里开启时确认一次，开启后马上发起第一次检查，不在第一次用到时再弹第二个框；用户手动关掉以后才再请求；要用的权限都要声明；授权请求只在用户操作之后马上弹，不静默弹窗；权限页列出每个组件确认过什么。
0022除输入法外的应用都收进螺壳.app邮件助手、螺壳搜索、螺壳扫描和以后的 luoke- 应用都合并进螺壳.app（记忆和 agent 已经在里面）；输入法照旧单独一个包，装在 ~/Library/Input Methods，由螺壳安装和升级。系统权限已授给螺壳本身（ADR 0021），版本和评测按任务名认、和在不在一个包里无关，只有输入法必须单独成包。合进来以后每个工具对主控和记忆仍是一个配件、一个身份，工具之间不互相调用（ADR 0014）；通知改由螺壳发出，从单独的 .app 换过来的用户要重新允许一次。修订（2026-11-05）：收进来的应用跟螺壳一起升级，不按组件单独升级，哪个应用有新版就出一版新螺壳；输入法、引擎、模型照旧单独下载、单独换。修订（2026-11-06）：集成做完，邮件助手、螺壳搜索、螺壳扫描、agent 都在 internal-1106 的螺壳.app 里；螺壳扫描不常驻，用时由螺壳起，起之前核签名和版本的只有它；通知由螺壳本体代发邮件助手和 agent 的。
0023螺壳自己的任务协议和统一调度给整个螺壳定一套自己的任务协议：任务声明优先级、权限、资源等，有注册流程，螺壳自己的组件和外来的应用都走这一套，外来应用接入不另做一套；由主控统一排序（2026-11-06 更正，原写引擎层），同一优先级默认按时间先后；可以做一个任务队列组件，让用户看到当前的队列、拖动调整顺序。推理仍归主控（ADR 0018）。外来应用照这套协议自己接入，不用逐个经我们同意；用户接入螺壳没覆盖的模型时要有提示，等于允许自定义配方（优先级不高）。协议和调度的方案、现在的 user-waiting / background 两档优先级和空闲任务怎么迁过去、外来应用的任务能不能排到官方任务前面、协议名都还没定。
0024记忆和螺壳搜索的本机数据加密存放挡同一账户里别的程序直接读文件和流出去的拷贝（硬盘被拿走靠 FileVault）；密钥归主控，只交给螺壳自己起的进程，拿不到密钥不打开、不另建明文；第一次拿到密钥时把明文库换成加密的，页面令牌不再写进文件。修订（2026-11-09）：默认加密，密钥放登录钥匙串，随迁移助理和时间机器带走，不放 iCloud、不和 Apple ID 绑；「密钥只留在这台 Mac」加一次恢复码是用户自己打开的一档；打不开时照实说、不删文件；界面用正式说法，口语的解释放「?」帮助或文档。下一版做，密钥怎么交由主控出方案。
0025螺壳小精灵在螺壳之外给还没装螺壳的人的轻量入口：打开就检测这台 Mac、跑起小模型、做一次本地 AI 能力的自检并方便分享，再介绍螺壳。不是螺壳的组件：不进配方、不由螺壳安装、不读写记忆。没装螺壳时可以自带小模型，是 ADR 0018 唯一的例外；装了螺壳就把模型交给主控。模型要在国内下得动；数字照实说，8 GB 的机器照实说螺壳暂时跑不了。先做原型，验证国内网络下出第一句话要多久、动画好不好玩、8 GB 机器上的内存和速度。

设计原则

  • 合理默认，按反馈逼近：不要求用户事先设定规则或逐条审阅；用户的确认、否定和撤销就是调整的依据。
  • 测试版不过度保守：能撤回的能力默认开启，配上提示和撤销，通过真实使用检验。
  • 本地优势不打折：在本机内部充分使用数据，体验才能弥补本地模型和算力的差距。
  • 产出要像用心的助理：理解要说清领域和具体对象，不照搬标题或品牌名。
