agent

螺壳的后台组件，螺壳里唯一主动找用户的部分。以后并进螺壳：不在「应用」列表里单独勾选，随螺壳装好，设置里有「主动提醒」开关；现在的独立开发版「螺壳 agent（开发）」是过渡形态。它把记忆的提问和建议、各工具要报的事合并成卡片和简报，挑时机告诉用户，并代表用户调用工具声明的能力。当前版本不使用模型。

仓库 luoke-agent · 核心 0.0.1 · 自带 luoke_mem 0.23.4 · 按代码 536f134 核对 · 不在 v1 首发中，和体检、螺壳窗口进同一个 v1.x

职责

  • 从记忆读取待问的问题和建议（asks），从各工具读取待报事项（outbox），统一排序后在窗口、通知和简报中呈现。
  • 把用户的回答交回来源：交给记忆的经 Memory.reply，交给工具的经工具协议调用对应能力。
  • 只在用户点按卡片时发出会改动数据的调用。不自行推断用户信息，也不替工具执行动作。

进程模型

部分实现职责
壳Swift 应用（macOS 14+），菜单栏常驻，依赖 A2UI 渲染包菜单栏、窗口、系统通知、卡片渲染、上报用户是否在场
核心Python 包 luoke_agent（仅标准库），运行在主控自带的 Python 上读记忆、连接工具、事项库、决定何时说
  • 启动：设计上主控按配件清单（resident: true，登录时带 --resident，不开窗口）拉起壳；现在配方和发布流水线里都没有 agent，主控不装也不拉起它。壳起核心的命令是 <python> -B -E -s -m luoke_agent serve --home H --memory M --parent-pid P，可再带 --hub S、--tool 配件=socket（可多个）、--memory-app；环境只给 PATH、HOME、PYTHONDONTWRITEBYTECODE、LUOKE_AGENT_PYTHON，标准错误追加到 <home>/logs/core.log。
  • 借主控的 Python：壳按 bundle id ai.luoke.core 找到主控，用它的 Contents/Resources/python/bin/python3；每次起核心都重新找，主控换版本、改名、挪位置都跟得上。
  • 存活：核心意外退出时壳会重启它，间隔从 2 秒翻倍到 60 秒；核心每 2 秒检查父进程，壳退出时随之退出。核心同时盯着 LUOKE_AGENT_PYTHON 指向的文件：它被换掉（设备号或 inode 变了），或路径消失超过 30 秒，核心以退出码 75 退出，壳立刻重起，不等间隔，并把间隔复位为 2 秒；核心稳定跑过 60 秒后才退出时，间隔也复位。
  • 壳与核心之间：<home>/run/agent.sock 上的 HTTP/1.1，见「界面协议」。
  • 轮询：核心每 5 秒一个周期；工具 outbox 每 60 秒读一次，记忆和主控每 300 秒各读一次，简报到点前 5 秒起每个周期都读记忆，直到简报发出；窗口打开时立即把全部来源读一遍。一个来源出错不影响其他，暂时不在运行的来源卡片先收起，回来后照旧。
  • 使用的主控接口（只在给了 --hub 时）：GET /accessories 发现已安装的工具（只认 capabilities.protocol 为 1 且有 socket 的，排除自己）；主控没答时保持现有工具，答了而清单里没有的工具算已卸载，卡片撤下、事项记为撤回；--tool 指定的不受影响。核心每次启动时经 GET /tasks 取主控内置的 luoke_mem 路径，取不到或导入失败时用自带的副本。壳正常退出时调 POST /accessory/exiting，告诉主控别再拉起。

  • 事件内容：feed 为 {order, open, notices}；notify 为 {id, title, body, urgent, silent, surfaceId}，同一 id 的通知换掉上一条；busy 为 {surfaceId}；result 为 {surfaceId, text, error, replaced}，replaced 表示卡片已换成结果，界面不再重复写那句话。
  • 窗口里的状态提示（notices）：工具没在运行、螺壳记忆打不开、螺壳记忆比螺壳新请更新、螺壳没在运行暂时找不到工具、这一版不在螺壳验证过的版本里、系统通知被关掉、系统正在问能不能发通知。
  • 系统通知被关：通知到不了时，窗口里说一句怎么在系统设置里打开，不替用户改系统设置；系统还在问用户（not_determined）时，窗口里说明答了以后才到得了；状态变化在 core.log 记一行。通知到不了时的处理见「何时说」。
  • 壳的命令行：--notify-status 打印一行 JSON {authorization, alert}，不发通知、不请求授权、不起核心，10 秒没答复退出 5；--notify <标题> <副标题> <正文> [--open <参数>] 发一条通知，退出码 0 交给系统了、3 没允许、4 系统拒收、5 十秒没答复、64 用法不对。两者和主控启动器的同名参数一致，给主控首次运行的完成页用。
  • 调试子命令：python -m luoke_agent feed|tap|presence|window --home H，用文字看卡片、点按钮、报在场、开关窗口。

工具协议

工具在配件清单的 capabilities 中声明协议版本（1）、socket 路径、可报事项（reports[]：kind、title、默认 urgency）和动作（actions[]），并在自己的 Unix socket 上提供 MCP 子集。完整规格见 luoke-agent/docs/工具协议.md。目前没有已发布的配件声明 capabilities.protocol：输入法的清单只有 listing，agent 跳过它；邮件助手的实现默认关闭，声明单放在 packaging/agent-capabilities.json，不进发布清单；体检和深度搜索已实现协议并在清单中声明，但都未发布。agent 实际只有记忆一个来源。

传输

  • 每个请求一条连接：POST /mcp，请求体为一条 JSON-RPC 2.0 消息，上限 1 MB；MCP 协议版本 2026-07-28，在 params._meta 中携带。
  • 超时：连接 10 秒；读 outbox、列工具 10 秒；只读调用 30 秒；写调用 300 秒。socket 不存在视为工具未运行，不算错误。

方法

方法用途
server/discover协议版本和服务能力；工具要实现，agent 现在不调
resources/read读 outbox：luoke://<配件>/outbox，内容 {items:[…]}
tools/list能力列表，带 readOnlyHint
tools/call调用能力；写调用必须在 _meta 中带 ai.luoke/user-action（{surfaceId, componentId, at}），否则工具返回 needs_user_action
  • outbox 事项字段：id、kind、urgency、deadline、expires、created、why_now、title、summary、card。缺 id 或 title 的丢弃；kind 缺省 other；urgency 不合法时用清单里这一类的默认，再没有就是 normal。outbox 是一份完整状态，上一轮有、这一轮没有的事项视为撤回。完成的编号在记录保留的 30 天内不再显示，工具要重新报同一件事须换新编号；撤回的编号再列出来就恢复，说过的不重说。
  • 回执：工具实现了 outbox_ack（看 tools/list）时，agent 在一件事第一次说给用户时回 state: "shown"，每件一次（进了简报、发了急事通知，或用户正看着窗口时进来）；用户答完回 answered，放下回 dismissed。用户不在、简报没发出去、系统通知到不了时不回 shown。
  • 调用结果的 structuredContent 可带 card（更新原卡片）、done（事项完成，卡片保留 30 分钟以便撤销）。失败码：needs_user_action、invalid、not_ready、needs_setup、stale、failed。
  • 撤销是结果卡上的一个写按钮，走同一条点按路径。
  • 打开东西的动作（打开文件、在访达中显示、打开工具自己的页面）一律带 ai.luoke/where: mac，只在用户点了按钮时才调，不管是否只读；readOnlyHint 由工具照实写。

卡片（A2UI）

  • A2UI v0.9.1（消息的 version 字段写 "v0.9"），目录 ai.luoke/a2ui/agent/1，组件限于 Text、Row、Column、List、Card、Divider、Button、CheckBox、ChoicePicker、TextField、DateTimeInput、Icon。
  • 校验：根组件存在、可达组件 ≤ 200、累计 ≤ 1000、无环、单父、绑定路径存在、文字 ≤ 2000 字；未通过校验的卡片改为纯文本卡。
  • agent 自己处理的动作：agent.open_url（仅 https，按钮文字后附域名）、agent.dismiss；agent.remind 只用于 agent 自己的「少说」卡片，工具卡片用了点按时答「不认识这个按钮」。
  • 渲染器：Swift 包 LuokeA2UI（macOS 14、iOS 17），LuokeA2UICore 只依赖 Foundation，LuokeA2UI 是 SwiftUI 画法；校验规则和 luoke_agent/a2ui.py 一条条对应。另有输入法用的目录 ai.luoke/a2ui/ime/1。DateTimeInput 目前画成文本框。

协议里有、agent 还没做的

  • 基础页和权限（§1a，已定）：工具可在 capabilities 里加 service（summary、pages、ui）、permissions、listing；对应资源 summary、page/<id>、permissions 用相对 id。权限分四种：system、account、delegate、each-time，状态由工具照实报。窗口归螺壳.app 画，agent 供内容；主控和 agent 现在都不读这些字段，体检和深度搜索已实现工具一侧（基础页只有体检有）。
  • 问螺壳（§1b，草案）：service.ask 的 suggest、search 两个只读动作，只在用户点开或打字问时才调。search 回 hits：固定形状的数据，不是 A2UI，由 LuokeA2UI 里只给窗口用的 HitsList 画。草案还给目录加 Image，现在不在目录里。主控、agent 都没有实现。
  • 不从卡片发起的调用（§5，草案）：用户在对话里问时，只读工具的结果带一张新卡片，不进 outbox 和简报。agent 没有对话，未实现；深度搜索已按此回。
  • ai.luoke/where: mac（§5）：标明只在 Mac 上有意义的工具，手机上不调。agent 没有手机端，不读它。
  • 工具自己做了的事（§8a，已定）：auto-done（normal，能撤销给撤销，撤不回给「以后别自动做」）和 daily-review（low，每天一份）。agent 不需要专门处理，按普通事项走。体检已报 auto-done；邮件助手未实现。

与记忆的交互

  • 以 Memory(path, tool="luoke-agent") 打开记忆；文件不存在时不创建，遇到版本过新的库时提示更新。
  • 读取 asks(status=["open"])，该不该问、每天几条由记忆决定；带 about_note 的问题和建议附上该理解最新的 3 条依据原文（来源、日期、每条 120 字以内），没有时显示 ask 的 evidence。记忆的提问和建议 urgency 默认为 normal，走简报。
  • 回答经 reply(ask_id, choice, text) 交回：
卡片按钮 → choice
是非类建议（answer.type 为 yes_no，或 action.capability 为 habit）好 → useful（处理习惯同时确认这条理解）· 不用 → useless · 别再提 → never
其余建议（包括退订建议）知道了 → useful · 别再提 → never
关于某条理解的问题对 → yes · 不对 → no · 以前是，现在不是 → past · 按我改的 → revise · 以后再说 → later（记忆收起这条理解下开着的问题，至少 7 天内不再问；之后由反刍视情况作为新的一条再问）
自由问题（单选、是非、文字）交回或 是 / 不是 → answer · 以后再说 → later（只收起这一条）

带 about_note 的卡片多一个「在螺壳记忆里看」，打开 luoke://memory?note=N，不写入。记忆现在只产生关于理解的问题和建议，自由问题这一行暂时用不到。

何时说

  • 排序：urgency（urgent、normal、low）→ deadline → 首次出现时间。
  • 每类的方式（modes）：now、brief、window、off；未设置时 urgent 为 now，其余为 brief。
  • 急事：用户在 Mac 前（120 秒内有上报、未锁屏、屏幕未睡、空闲 < 180 秒）时立即通知，不受免打扰时段限制。一轮只有一件时，标题是事项标题、正文是 why_now（没有则用 summary）；同一轮有多件时合成一条，标题「N 件急事」，正文列前 3 个标题，点开定位第一件。
  • 简报：第一件待简报的事项（normal；只有 low 时距上一份 low 简报 ≥ 24 小时）出现后计时 60 分钟，到点后等用户在场且不在免打扰时段才发；每份含全部 normal，最多附 2 件 low；通知正文列前 3 个标题；上一份未打开窗口时新的一份静音。
  • 窗口：窗口在最前面、用户也在场时算正看着，现有事项和新来的事项都算看过，不再发通知。窗口开着但最小化、在别的应用后面，或人已离开，都不算。
  • 通知到不了：系统通知被拒、横幅关着或用户还没答时不发、也不算说过，急事和简报都排着，打开后补发；壳还没上报过授权时照常发。
  • 少说：同一类连续 3 次没有回应，从 brief 降为 window，并给出一张"以后只放在窗口里"的卡片，用户点了才收起，核心重启后画回来。同一次说的同类事项只算一次。算没回应的：通知过、到下一份简报时仍没看过的；通知后过期的；用户按「放下」。用户答复或点「还是提醒我」把连续计数清零。
  • 清理：过期事项撤下；窗口关着时，完成的卡片 30 分钟后撤下，完成或撤回超过 30 天的记录连同 contents 一起删除。

数据和文件

位置内容
~/.luoke/agent/数据目录（700）
state.db（600）表 items（事项状态）、contents（卡片内容，用于重启后恢复和撤销，撤下后留作历史）、settings、meta、reactions（每类展示、回应、忽略的统计）；put_off 已不再使用

设置默认值：brief_minutes 60、away_seconds 180、ignore_limit 3、quiet 无、modes 空。brief_minutes 可由 serve --brief-minutes 写入，modes 只由「少说」改，其余没有修改途径。

安全

  • 写调用只在 POST /action（用户点按）时发出，并附 user-action；方案编号、链接、问题编号等写死的值只认核心保存的卡片声明，不采用界面送来的同名值。
  • 工具和记忆送来的文字一律按纯文本渲染；每张卡片带来源前缀，按钮只转给出这张卡片的来源。
  • socket 只靠文件权限（目录 700、文件 600）限定在当前账户内，不核对调用方身份。

已知限制

  • 没有对话，不使用模型；outbox 靠轮询，未实现订阅。
  • 写调用只看 tools/list 的 readOnlyHint，不对照清单里声明的 actions。
  • deadline 只影响排序，过期不会标记；off 与 window 效果相同。
  • 设置没有界面；卡片上用户改过的选项只存在壳里，壳重启、核心重启或重新连上时丢失；core.log 不轮转。
  • 简报通知的正文包含事项标题。
  • 核心只在启动时取一次主控的 luoke_mem 路径，主控换版本后靠退出码 75 重起再取；连不上主控时隔 2 秒重试，共 3 次，都不行就用自带的副本，直到下次重起。
  • 连主控时要过版本校验：配方的 verified 没有 luoke-agent，主控不答它的请求，agent 只能说明这一版用不了工具；主控一侧还没接。
  • 下一版修：本页按仓库主线写，试用版换装后才生效的有：窗口要在最前面才算看过、通知到不了时不算说过、少说按次计数且卡片不丢、来源读不到时事项不丢、改写含密码类内容时提示正确、主控不认版本时单独提示、重启间隔复位。这些修复有单元测试，窗口状态的计算在 AppKit 测试程序上跑过，开发版 app 本身还没在真窗口上点过。
