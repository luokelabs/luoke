螺壳（主控）

用户装的应用「螺壳」（螺壳.app）；"主控"是它在内部分工里的叫法。本机所有模型推理的唯一入口。邮件助手、螺壳搜索、螺壳扫描、记忆和 agent 都打在它的包里，跟它一起升级；输入法单独一个包，由它安装和升级。它按配方为每个硬件档选择模型，调度各配件的请求和空闲任务，监管推理引擎和专用模型进程，并负责下载、升级和卸载。

仓库 luoke-core · 按代码 364e582 核对 · bundle id ai.luoke.core（开发版 ai.luoke.core.dev，名为「螺壳（开发）」，数据在 luoke-core-dev，不认领 luoke://）· 接口细节见「参考 · 主控任务接口」「参考 · 配件清单与配方」

生命周期

启动

  1. 本体判断是否以安装器身份运行：位于认得的安装位置（/Applications 或 ~/Applications 下的 螺壳.app、螺壳主控.app）时不是；否则文件名不是 螺壳.app、位于 /Volumes/ 或被系统隔离时是，进入安装流程。
  2. 不是装好的那份（按 /Applications/螺壳.app、/Applications/螺壳主控.app、~/Applications/螺壳.app、~/Applications/螺壳主控.app 的顺序取第一个 bundle id 相同的）时弹框说明后退出。先装上菜单栏图标；上次换包没成时弹框说明原因（「App 管理」挡住时指明去系统设置里打开），升级标记作废；把 luoke 命令行链接改指到装好的那份；在后台清理上次经「检查更新」升级时留下的安装包（首次运行没走完也清）。首次运行未完成时显示首次运行向导（升级标记作废，有预选时预选上那个应用，主控进程到下载那一步才启动）；否则启动主控进程，随后起 agent 核心和螺壳里开着的应用（先挪走收进来以前单独装的旧 .app，见下文「旧的单独 .app」），有升级标记（run/upgrade.json）时重新登记登录项（用户关掉过的不动）并接着显示升级卡片；没有则直接拉起常驻配件，有预选（run/preselect.json）时打开「应用」窗口在那一行里装。主控进程启动时注销 previous.noindex 里旧版的 LaunchServices 登记。
  3. 主控先绑定 socket 并应答（启动期间除 /tasks、/status、/downloads 外答 busy），再启动引擎：清理上次留下的孤儿进程、等待底座出现、做冒烟检查。
  4. 启动采样线程，进入运行状态；设置中开启了端点则开启端点。

运行

采样线程每 5 秒检查引擎是否崩溃，刷新电源、温度和内存压力，按需打断后台工作、卸载闲置底座、跑探针、每 60 秒重扫配件清单、调度空闲任务，并写入 state.json。本体每 3 秒轮询一次 /status。空闲超过 10 分钟的专用模型工作进程停掉；内存压力 critical 时全部停掉，30 秒内不起。

退出

本体先停螺壳里的应用（SIGTERM，邮件助手等 8 秒、螺壳搜索等 5 秒，还不退就 SIGKILL）和 agent 核心（等 3 秒），再给主控发 SIGTERM，等待 40 秒。主控依次停止端点、空闲任务（SIGTERM，15 秒后 SIGKILL）、工作进程、引擎，最后删除自己绑定的 socket。

调度

请求等级

等级来源待遇
打字打分、联想（输入法）立即处理；记为交互；16 GB 档会立即卸载底座让出内存
用户在等生成请求带 X-Luoke-Priority: user-waiting；端点请求优先；正在运行的后台工作若预计剩余超过 11 秒则被打断（返回 interrupted）；端点请求先等完能耗模式的歇息再开始
后台X-Luoke-Priority: background；空闲任务需通过后台接纳

交互中指最近 60 秒内有过用户在等的请求或新的预热；安静时刻指距最近一次此类事件满 5 分钟。

能耗模式的歇息中（空闲任务所属配件的请求不挡回，由主控挂着等歇息过去，最多 4 分钟）busypower_cooldown

能耗模式（全局）：全速、均衡、静音。每项后台工作、每条本机端点请求结束后，按占用时长的 0、1、3 倍歇息，端点一次最多歇 600 秒；均衡、静音下端点一次只放一条请求；打字和配件里用户在等的请求不受影响。静音模式下温度 fair 即按过热暂停后台。专用模型通道（嵌入）每个任务有独立通道和间歇，不占用引擎的后台名额；用户在等的嵌入查询插在后台批（每 8 条）之间。

内存

  • 模型能否加载要过两道检查：大小不超过引擎上限 (guard_gb − 2) × 0.95；且不超过 Metal 可用上限减去当前 wired 内存（按物理内存的 74%–84% 估算）。端点的用户模型独占引擎时，上限改为 内存 − 8%（3–8 GB）− 常驻专用模型 − 1 GB，换回底座时还原。
  • 起专用模型工作进程前先算剩余内存（Metal 上限 − wired + 已加载的底座），装不下它的 wired_gb 就不起，答 not_ready（retry_after 30）。
  • 引擎上限随正在运行的工作进程动态调整。
  • 引擎同时只有一个"当前模型"；端点登记的小模型放得下时与底座同时加载，放不下则独占（先卸掉其他模型）。
  • 底座闲置超过本档 idle_unload_secs 后卸载；有后台工作或有效的预热租约时不卸。

空闲任务

同一时间只运行一个。启动条件：主控空闲、处于安静时刻、后台未暂停（清单可声明允许电池）、距上次启动满 min_interval_minutes（上次被收尾时缩短为 10 分钟）。用户回来、别的配件的后台工作占用引擎、超时、后台暂停、卸载配件或主控退出时收尾；任务自己发的请求和它引起的底座加载不算占用。

配方和档位

  • 配方（recipe.json）定义硬件档（内存范围、引擎上限、底座是否常驻）、模型（目录、类型、常驻内存）、每档的模型分配、引擎版本、每个任务的参数、允许接入的配件版本和评测证据。
  • 选档：取第一个满足 min_gb ≤ 内存 < max_gb 的档；用户可在设置中选择更低的档（如 128 档的"省空间"）。
  • 任务开关：每个任务在哪一档开启由出版流程的支持台账决定：未开启的档须 3 遍评测全部通过才开启（复测在发布后补跑，补满后下一版开启）；开启的档一遍不过即关闭；没评到的档沿用上一版；"上一版"指最近一个真正发布出去的版本；beta 版全部重新评测、重新打包，不沿用别的版本的证据。
  • 冒烟检查：引擎启动后测一次实际的预填和生成速度，后台估时使用实测值。
  • 探针：打分、联想工作进程就绪后测 p90 延迟，超过配方 latency_ms 时把任务标为较慢。

下载、安装、升级、卸载

  • 下载：依据发布清单（每项有文件列表、大小、sha256、多个镜像地址）。多地址时先测速排序；每个地址重试 3 次，403、404、410 直接换地址；支持续传；sha256 对上才落位。本机已有同名模型（~/.omlx/models、Hugging Face 缓存、LM Studio）时逐文件核对后 APFS 克隆，不重复下载。首次运行以后发现还缺模型时自动补下（失败后从 30 秒起加倍间隔，最长半小时）；网络按流量计费或开了低数据模式时不自动补下，只在设置「下载」的「还缺」一行说明，点「重试」照下；首次运行、「应用」窗口、换档是用户点的，照下。下了模型或引擎包才重启引擎、重做冒烟检查，只装应用不动引擎；发布版的新引擎冒烟检查通过后，删除 engines/ 里的其他版本。
  • 配件安装校验：codesign --verify --deep --strict、Team ID、bundle id 与清单一致、公证票据有效。
  • 安装位置：主控 DMG 是拖放窗口，左边「螺壳」、右边「应用程序」快捷方式，拖过去装在 /Applications/螺壳.app。在 DMG 里直接双击「螺壳」时提示先拖进「应用程序」，另给「帮我装进去」。发布页只放螺壳的 DMG（Luoke.dmg），应用在「应用」窗口里装；应用的安装器（安装<应用>.app）和「帮我装进去」把主控拷进 /Applications/螺壳.app（写不进去时拷进 ~/Applications/螺壳.app），去掉下载标记并登记；目标位置已有 bundle id 不同的同名应用时不覆盖，改放另一处，两处都被占才弹框请用户改名或挪走。已装的主控以实际位置为准：/Applications、~/Applications 两处，螺壳.app、螺壳主控.app 两个名字都认，只认 bundle id 相同的，两处都有时用 /Applications 那份：另一份被打开时（例如登录项还指着它）直接交给装好的那份后退出，装好的那份启动时把没在跑的另几份移进 previous.noindex、注销登记并重新登记登录项（用户关掉过的不动）；已装着主控而安装器不比它新时，把预选交给它后退出。邮件助手、螺壳搜索、螺壳扫描、记忆和 agent 核心在 螺壳.app 里，不另装；单独成包的只有输入法，装在 ~/Library/Input Methods。
  • 螺壳里的应用：邮件助手、螺壳搜索、螺壳扫描、agent 核心各自在包里的位置见「参考 · 配件清单与配方」的打包布局；这一版没带上的，「应用」窗口里没有它。签名只有螺壳一份：发布时由内向外签，Contents/Helpers 里的程序保留打包时定的签名标识和 entitlements，签完再核一遍标识（螺壳搜索 ai.luoke.search；螺壳扫描 ai.luoke.scan、ai.luoke.scan.admin，它用的 ClamAV、YARA 程序是 ai.luoke.scan.clamscan 这样的标识）；邮件助手、agent 核心是 Python 代码，由螺壳的签名盖着。本体当子进程直接起它们（邮件助手、搜索、agent 核心用 Foundation 的 Process，扫描用 posix_spawn），不经 open、不经主控，也不 disclaim：它们用到的完全磁盘访问、照片、Apple Events 都算在螺壳头上；带了搜索时，这几项权限的说明写在螺壳的 Info.plist，照片和 Apple Events 的 entitlement 在螺壳外层的签名里。起之前核签名和版本的是扫描和搜索（见「组成」）。主控按包里各自的清单把它们当配件认，版本就是这一版螺壳带的版本。
  • 开启、停用：螺壳里的应用不用下载。开没开记在 state.json 的 enabled（主控没起时本体也直接读）；用户没选过时按清单的 default_on，邮件助手默认开着，螺壳搜索、螺壳扫描默认关。在「应用」窗口那一行点「开启」：螺壳搜索先开「开启螺壳搜索」窗口，读一次选中的文件夹（桌面、文稿、下载默认勾上，第一次读时 macOS 问），勾了照片的要照片权限，要到至少一样才把选中的写进搜索的设置；别的直接开启。开启都经 POST /accessories/enable 记下（hub.log 里是 enabled luoke-scan=True 这样一行），常驻的随即起来。没开着的不起、不跑空闲任务，GET /accessories 也不列。「…」里的「停用」走卸载窗口，写明「它在螺壳里，这里只是停用」，可选同时删除数据（有 uninstall 命令的先跑它）、从记忆里忘掉；本体先停掉它，主控停它的空闲任务、记下停用（enabled …=False），删掉 previous.noindex 里同 bundle id 的旧版 .app，注销同 bundle id 的其他登记，螺壳里的程序不动。
  • 旧的单独 .app：从各自单独装的版本升上来的用户，螺壳每次起来（主控进程起来以后），本体在 ~/Applications 和 /Applications 里按 bundle id（ai.luoke.mail、ai.luoke.search、ai.luoke.scan，邮件助手还有更早的 AppleScript 启动器）找收进来以前的 .app：先结束里面的进程（SIGTERM，等 15 秒，再 SIGKILL），注销登记，挪进废纸篓，用户没开启的也挪；邮件助手和搜索等旧的挪完才起螺壳里的那份，免得两份抢同一个数据目录。邮件助手还先移除旧的登录项 local.luoke-mail，注销并删掉 ~/.luoke-mail/notifier 里通知用的小 App。数据目录和钥匙串里的授权码不动，螺壳里的那份接着用；搜索的系统授权不跟过来，旧的挪走时搜索还没开启，就弹「开启螺壳搜索」窗口重新要。挪走的每一个在系统日志里记一行，不进 hub.log。开发版、实验室构建不动本机装着的。旧的「螺壳 agent.app」不挪：它在跑时 agent 核心不起，主窗口里请用户退出它、从「应用程序」里删掉；登录时不再拉起它，「应用」窗口也不列它。
  • 首次运行：步骤条五步：这台 Mac（预检：档位、磁盘、系统版本、照实说明体验；内存不到 16 GB 或系统版本低于引擎要求时停在这一步）→ 选应用（发布清单里单独成包的，现在只有输入法）→ 确认下载 → 下载安装（逐项进度，主控排第一行；总进度的剩余时间在头 10 秒、下到 2% 以前不估；应用装好即打开，不等模型；含本机试跑）→ 完成；后来加装应用在「应用」窗口那一行里装，不走向导。离开下载页时注册登录项；下载页结束时分几种结局给出下一步：有项没下下来（先继续 / 重试）、试跑没过（重新检查 / 继续）、缺底座、主控没起来（重试会重启主控）。确认页上废纸篓里有旧输入法时提示。完成页：输入法的 --status 答 not_registered 时调一次它的 --register，每秒检查是否已添加；添加后输入法没在跑时在后台拉起它，可试打并一键切换（--select），切过去后试打框重新取得焦点，切不过去、或输入法报告还登记着别的副本时给「重新登记输入法」，重新登记后仍不行则提示注销重新登录；邮件助手开着时有一行写「已经在浏览器里打开了，第一次要连接邮箱。」，给「打开」；带了螺壳搜索时有一行「螺壳搜索」，没开启的给「开启」（走「开启螺壳搜索」窗口）；单独成包的普通应用（type 为 app）列出通知权限（经启动器的 --notify-status）：已允许 / 还没问过（按钮发一条测试通知，让系统询问）/ 已关闭（按钮打开该应用的通知设置），未全部允许时每 2 秒刷新；螺壳里的应用和输入法不在这里列。
  • 升级：同一张卡片走完五步：下载安装包 → 核对签名和公证 → 换成新版螺壳 → 补齐推理引擎和模型 → 本机试跑，大小、位置相同。有两条路：菜单「检查更新」（前三步在「检查更新」窗口里），或打开比已装的新的安装器（应用的安装器，或在主控 DMG 里直接双击「螺壳」；第三步在安装器的卡片里）。两条路都先把新版拷到环境目录的 staging.noindex 并核对签名，写 run/upgrade.json，起一个独立的换包脚本，再结束旧主控、旧包里的应用（按程序路径认）和记忆进程、自己退出。脚本等它退出（最多 2 分钟），把旧版（连同它里面的应用）移入 previous.noindex（只留上一份），把新版换到目标位置并登记，再用 /usr/bin/open 以用户身份打开新版，结果写入 run/swap-result.json。目标位置：已装在 /Applications 的还在那里；装在 ~/Applications 的，/Applications 写得进去就搬过去，否则留在原处；名字统一为 螺壳.app。目标目录写不进去（标准账户的 /Applications）时，脚本经系统的管理员授权框以 root 运行；授权框在旧主控退出之前弹出，取消则什么都不动、原来的主控照常用；只有换包两步用 root，打开新版时切回用户身份。换包没成时脚本把旧版放回并重新打开，旧版启动时弹框说明原因；脚本起不来或授权被取消时卡片写原因，给「先用着」和「重试」。新主控读到标记（读后删除）接着显示卡片：常驻配件在卡片一开始就拉起，补齐未装的引擎包和本档缺的模型，等本机试跑通过或推迟后写「已升级到 X」和这一版的更新说明；已装的应用有新版本时列出名字并给「去升级应用」。螺壳里的应用跟着整个包换，不单独升级；输入法不随主控升级。补齐或试跑没成时卡片写哪一步、为什么，给「先用着」（标记写回，下次主控启动接着补）和「重试」。经应用的安装器顺带升级的，完成后到「应用」窗口那一行里接着装那个应用。
  • 应用：菜单「应用」打开，列出这一版发布清单里单独成包的应用（现在只有输入法；组件配件不列）、螺壳里带的应用和清单外已装的应用，每个应用的操作都在它那一行里做。螺壳里的应用只写版本，没有「安装」「升级」「回到上一版本」：没开启的标「没开启」、给「开启」，邮件助手开着时给「打开」（打开它的页面），「…」里是「停用」。没装的标「未安装」，点「安装」由主控按清单下载、核对、放好，装好后经 /usr/bin/open 打开，常驻的以 --resident 在后台拉起，输入法装好后登记一次并提示到系统设置里添加；系统版本不够的写原因、不能装。首次运行没走完时，点「安装」或应用安装器交来预选，都回到首次运行并预选上这个应用。已装且清单版本更新的标「有新版本」、写「旧版 → 新版」，点「升级」只换这一个应用：普通应用先退出、换好后拉起（原来在跑的重新打开）；输入法先换包，再结束旧进程并立即重新拉起。结果写在窗口顶部，没成时旧版照常能用。有可升级的应用时顶部提示「升级螺壳不会顺带升级应用」。「…」菜单里的「卸载」（螺壳里的应用是「停用」）把这个窗口换成卸载确认，完成或取消后回到这里。菜单「应用」一行、「应用」窗口、检查更新窗口和升级完成卡片按同一判断提示应用有新版本：已装版本比发布清单旧、这台 Mac 的系统版本够、不是用户回到上一版本时换下的那一版。
  • 检查更新：菜单「检查更新」打开窗口，按本机主控的渠道查：内部版查 luokelabs/luoke-internal-builds 里的 internal-*，beta 和正式版查 luokelabs/luoke-releases 里的 beta*；每页 100 条往后翻，翻到出现这个渠道的版本为止（最多 10 页），取发布时间最新的一版，built_at 更新才算；有新版本时列出发布说明的「更新说明」一节和大小，说明这里只升级主控、应用在「应用」里单独升，给「以后再说」和「升级到 …」。升级时在这个窗口里走前三步：下载主控 DMG（显示进度），核大小、sha256、公证票据，只读挂载后核 .app（螺壳.app 或 螺壳主控.app）的签名和 Team ID，拷到 staging.noindex 再核一次签名，卸下并删掉 DMG，起换包脚本（要管理员授权时在这里弹），然后主控退出，由新版接着显示卡片；连不上、核对不过、某一步失败时给「重试」（升级中失败还给「先用着」），原来的主控不动。螺壳已是最新、但已装的应用有新版本时，窗口里提示并给「去升级应用」。本机版、开发版不查，窗口里说明。默认自动检查（内部版每 3 小时、beta 每天一次；启动 60 秒后，之后每小时看是否到时间，查成了才算；开关在窗口底栏，升级中不显示），发现新版只在菜单「检查更新」一行显示「有新版本」，点它直接显示那一版，不自动安装。
  • 回到上一版本：「应用」窗口里某个应用在 previous.noindex 里有经过验证的上一版时，它那一行的「…」菜单有「回到上一版本（版本号）」，就在这一行里做：主控先核签名、Team ID、bundle id、公证，两处对调并注销备份目录里的登记；普通应用对调前先结束，输入法对调后再结束旧进程并立即重新拉起（不动输入源）；结果写在窗口顶部。换下的那一版不再算作新版本，再选一次可换回。主控把每个被本版配方认可的配件版本，连同本版当时放行的任务（评测通过的，加上配方里没有评测的，如草稿、每日摘要），记入 verified-history.json（每配件 3 个版本）。换回的版本、以及主控升级后还没升级的应用，只能用记录中的任务；记录外的任务答 task_unavailable，提示到「应用」里升级。无记录的版本不提供回到上一版本。螺壳里的应用没有这一项；换包时旧版螺壳连同里面的应用留在 previous.noindex，但没有换回它的入口，从那里打开只弹框说明、不起主控。
  • 卸载：入口在「设置 › 关于 › 卸载螺壳」（全部）和「应用」窗口某一行的「…」›「卸载」（该应用），直接到确认页，取消或完成后回到原来的窗口；螺壳里的应用在这里是停用（见「开启、停用」）。输入法的输入源还启用时先停用（macOS 26 起不能代停，拦下并请用户在系统设置里移除），删完再核一次，并删除它的临时目录和锁；结束进程；删除 .app 时连同 previous.noindex 里的旧版，并注销同 bundle id 的其他副本（含废纸篓里的）；可选"一起从记忆里忘掉"和"删除数据"（删数据时先跑配件自己的 uninstall 命令）。只删除配件清单 data 中声明且符合配件自身标识的路径；不删除 mem.db。完成页列出还留着的数据和位置。"卸载全部"删除环境目录、登录项、设置和命令行链接，把主控移到废纸篓后退出。
  • LaunchServices 登记：装配件前先注销同 bundle id 的其他副本（含废纸篓里的）；previous.noindex 里的旧版在换装、回滚后和主控启动时都注销登记；「检查更新」只挂载安装包、不打开里面的主控，拷到暂存处时注销两边；换包脚本注销移入 previous.noindex 的旧版、登记换上的新版；收进来以前单独装的旧 .app 挪进废纸篓前先注销。主控和安装器拉起别的应用一律经 /usr/bin/open，不把自己记成被拉起者的父进程（否则 macOS 27 上已退出的父进程会一直留在程序坞）。
  • 重新登记输入法（切不过去时）：结束它、注销其他副本，用新复制的一份换回原位并重新登记，不改内容、不重新下载。
  • 通知：首次运行、加装、升级都不发通知，结果只在窗口里。邮件助手和 agent 核心要发的通知由本体以「螺壳」的名义发：邮件助手经标准输出说一声，还没问过时系统先问一次，点了打开它的页面；agent 核心的点了打开主窗口。带了 agent 时，螺壳起来就请求通知授权。

故障和降级

情况表现
引擎崩溃以新端口和密钥重启；600 秒内崩溃 3 次熔断，生成任务保持 paused 直到主控重启
请求中途引擎出错连接断开且尚无输出时自动重试一次；引擎在流里报错时不把错误当答复转给配件，内存类按内存不够处理，其余以 engine_failed 结束
模型放不下用户在等的请求返回 needs_user 并附占用内存的进程列表；后台请求返回 paused
引擎因内存拒绝（开始前答 400，或在流里报内存中止，尚无输出）卸载并重新加载底座以释放 MLX 缓冲池，重试一次；仍不行答内存不够
冒烟检查放不下推迟，每 300 秒在空闲时重试
专用模型进程空闲或内存紧张停掉；按需重起时答 not_ready（retry_after 2），内存不够时 retry_after 30
专用模型进程失败 ≥ 3 次该任务暂停，不再重启
下载失败分三类说明：服务器上找不到、连不上、核对不过
配件版本未通过验证调用返回 unknown_accessory

菜单和窗口

  • 菜单：第一行是状态（启动中 / 工作中 · 底座模型 / 空闲 · 底座模型），后台暂停时下一行写原因（在用电池、低电量模式、过热、等内存）；然后是主窗口那几项（带了 agent 时：急事（有才列）、打开螺壳、暂停提醒一小时）、记忆（随主控带的时候才有）、开着的邮件助手（打开它的页面）、应用、设置、检查更新，「应用」「检查更新」有新版本时写成「名称：有新版本」、值加粗；最后「退出螺壳」（⌘Q）。主控没连上或引擎出错时，第一行是「出错了」，下一行写原因（进程退出码、连不上的原因或熔断原因），给「重新启动螺壳」和「导出诊断信息」。菜单栏图标是单色海螺，五种状态，都不动：虚线（启动中）、实心（准备好了）、半满（在处理请求或后台任务）、空心（后台暂停）、实心带圆点（出错：连不上主控、引擎没在运行或熔断）。
  • 窗口期间：主控的任何窗口（首次运行、升级卡片、应用、卸载、检查更新、设置、主控小窗口）开着时，主控出现在程序坞和 ⌘Tab 里，全关后回到只在菜单栏。同一流程只开一个窗口：卸载接替「应用」或设置窗口，安装器的升级卡片出现后「检查更新」窗口关掉。
  • 再次打开主控：有安装器交来的预选时，首次运行没走完就回到首次运行并预选那个应用，否则在「应用」窗口那一行里装；没有预选时，带了主窗口、首次运行已走完、首次运行和升级窗口都没开着就打开主窗口；不然有开着的窗口就叫到前面；都没有且首次运行已走完时弹出主控小窗口，显示运行状态（在运行 / 启动中 / 没连上），说明主控在菜单栏的海螺图标里、找不到时可能的原因，给「打开菜单栏设置」，并列出 记忆（随主控带的时候才有）、应用、检查更新、设置 四个入口。⌘, 打开设置窗口。
  • 设置：通用（能耗模式 全速 / 均衡 / 静音、使用电池时仍运行后台、登录时启动螺壳）、下载（有下载或缺模型时出现：逐项进度或排队中，缺的可重试）、模型（占多少空间——可选档多于一个时出现，磁盘不够换档时在下面写明；底座模型；换档等待时的说明；已下载的模型及大小；本机放行）、高级（本机端点）、关于（螺壳版本即发布号、导出诊断信息、卸载螺壳）。Finder「显示简介」里的版本也是发布号（如 beta1、internal-1027；CFBundleShortVersionString），主控版本号在 CFBundleVersion。档位、引擎、本机试跑在诊断信息里。
  • 只给本体用的接口（下载、设置、端点、冒烟、卸载、开启、回到上一版本、重新登记、重新启动输入法）按 socket 对端进程核对是不是本体，/settings、/endpoint 也认主控自带的 luoke 命令行；不是的答 forbidden（403）。

已知限制

  • 内存压力会暂停和打断后台、停掉专用模型工作进程，但不主动卸载底座。
  • 熔断不会自动恢复，需要重启主控。
  • /status、/jobs/run 不核身份（/jobs/run 只在内部版、本机版开放）。
  • 配方不支持撤回已发布的配件版本，也不声明最低主控版本。
  • 端点只有 /v1/models 和 /v1/chat/completions；luoke launch 只支持 pi。
