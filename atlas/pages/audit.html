螺壳扫描

在空闲时查一遍这台 Mac：空间去向、会重建的缓存、卸载残留、久未动的项目、重复和久未打开的大文件，以及常驻项、进程、键盘监听、权限、浏览器扩展、MCP 配置、AI 工具的 skill 和说明文件、依赖里的已知恶意包、基础安全设置和病毒。是不是垃圾、能不能删由确定的规则决定，主控的本机模型只把发现讲成人话。打在螺壳.app 里，不常驻：空闲任务由主控经螺壳本体起，agent 的每个请求由本体起一次。结果经 agent 告诉用户；删除只执行用户在卡片上点过的方案，用户打开以后，四类按规则挑出的东西不用点就清。除会重建的缓存和失效的链接外都移到废纸篓，能放回。

仓库 luoke-scan（用 Go 写，Apache-2.0；两个程序 luoke-scan、luoke-scan-admin）· 版本 0.3.8，规则包 0.1.0，按代码 37c38cb 核对 · 封闭测试，随 beta 2 第一次提供 · 只支持 Apple 芯片、macOS 26.2 及以上

职责

  • 查的时候不改任何东西；只有主控定时起的、带 --autoclean 的一轮在查完以后清（见「清理」）。能用元信息（大小、时间、inode、签名、链接数）判断的不读内容；要内容的（重复文件的哈希、锁文件和全局包的名字与版本、明文凭据和散落的密钥、AI 工具的 skill 和说明文件）只在本机读，内容不进报告、日志和卡片。
  • 每条发现带结论（放心删 safe / 要确认 confirm / 仅供参考 info）、类别、严重度和依据。只有会重建的缓存能得到"放心删"。
  • 检查没跑成记成"没扫描"并写原因，不算没有发现。
  • 不主动找用户：没有通知、没有菜单栏图标、没有自己的窗口，要说的事放进 outbox，由 agent 挑时机。
  • 不带模型：讲成人话、给认不出的文件夹认名字、看 skill 说的和做的对不对得上，用主控的三个生成任务（见「生成任务」）；模型说的只附在发现下面，不改结论；主控不在或任务没开时照样查、照样出结果。病毒扫描用随包的 ClamAV 和 YARA。
  • 只有 freshclam 每天最多一次从 database.clamav.net 下载病毒库会联网。恶意包名单只从本机文件导入，git 不 fetch，模型和记忆都经本机的主控，给 agent 的接口是本体交来的标准输入输出，不开 socket、不监听端口。

运行形态

程序行为
luoke-scan在 螺壳.app/Contents/Helpers，签名标识 ai.luoke.scan。读磁盘的是它：扫描、出方案、执行方案、不用点就清、问主控的模型、写记忆都在它里面；从不开 socket。三种起法：空闲任务 update --this-mac、scan --this-mac --autoclean（主控经螺壳本体的 --run-tool 起）；agent 的每个请求起一次 luoke-scan mcp --this-mac；scan_now 另起一个脱离的 scan --for-agent --this-mac（自己一个进程组，起它的请求先答完退出）
luoke-scan-admin同在 Contents/Helpers，单独签名（ai.luoke.scan.admin）。平时不运行，只在用户在螺壳弹出的密码框里输入密码以后，以 root 做一次「要密码的删除」，见「清理」。不是常驻的 root 辅助程序
  • 空闲任务：主控按配件清单的 jobs 起：update（每天最多一次，memory_mb 800，20 分钟）和 scan（每天最多一次，用模型，1500，60 分钟，声明用到完全磁盘访问 "uses": ["fda"]），都不用电池，要用户安静、后台状态允许、没有别的空闲任务在跑。主控起的是螺壳本体的 --run-tool luoke-scan <参数>：本体只认 update --this-mac、scan --this-mac --autoclean 两条，一字不差，用户在「应用」里开启了才起（默认关），停着起、核过签名再放行（见主控页）。环境只有 HOME、TMPDIR、PATH、LANG，没有描述符 3（空闲任务不提权）。
  • agent 的请求：本体起 luoke-scan mcp --this-mac，标准输入输出接在交给 agent 的那条连接上，描述符 3（LUOKE_HOST_FD=3）是请本体弹密码框的通道；同时最多 4 个，一个最长 300 秒（见主控页）。扫描读一条请求或一行一条，读到结尾就退出；一条超过 1 MB 或什么都没读到时退出码 3。
  • 第一轮：用户开启螺壳扫描或刚确认权限时，清单里标了 first_use 的 scan 马上跑一轮（用户在跟前也不让路，只看超时）；病毒库这时多半还没下，病毒扫描记成没扫描，update 等下一个安静时刻。之后每天一轮，被打断的隔 10 分钟就能接着跑。自动清默认关，persistence.new 第一轮只记基线，space.growth 要攒几天历史。
  • 装好的包只认 --this-mac：--home、--data、--tmp、--projects、--tool-dir、--fixture、--clock 这类开发参数和 eval-*、make-skill-evalset 都拒绝。扫描工具只用 Helpers 里同一份的，每次用之前核签名（标识 ai.luoke.scan.<名字>、发行团队），不对就当没有，不找 Homebrew 的（那些文件夹用户可写，会借到完全磁盘访问）。提示词、freshclam.conf 和 ClamAV 的根证书编在 luoke-scan 里，起它之前核的签名也盖住它们。
  • --this-mac 查哪里：家目录、本用户的临时目录（$TMPDIR），/Library 和 /var/db/receipts，应用目录 /Applications、~/Applications、/System/Applications，项目目录取 ~/Developer、~/Projects、~/Documents/GitHub、~/code、~/src、~/repos、~/workspace 里存在的；数据放 ~/.luoke-scan。
  • 完全磁盘访问：授给螺壳本身（ADR 0021），本体起的扫描和扫描起的程序都跟着用。有没有：打开 TCC.db 试探（不弹框），试不出算没有。用户没在螺壳的权限窗口确认这一项时，本体给 LUOKE_PERMISSIONS_OFF=fda，扫描不管 macOS 给没给都当没有，连 Mail、Messages、Safari 这类隐私目录也不碰；scan_now 那一轮从起它的进程继承。
  • 没有完全磁盘访问时：不碰 macOS 会弹框问的地方（桌面、文稿、下载、音乐、~/Movies/TV、~/Library/Photos、iCloud 云盘、CloudStorage、Containers、Daemon Containers、Group Containers，和任何 .photoslibrary），走别的目录时碰到也不进，~/Documents/GitHub 连在不在都不看。看不到的写成「没有完全磁盘访问，…没看」，已看到的照报；受保护文件夹里的程序签名记成"不知道"，不当成不存在；方案不碰这些路径；记过的大小、哈希、项目结论不忘。outbox 出 needs-access。
  • 一次一轮：每个数据目录用 round.lock 保证空闲任务和 agent 叫的那一轮不重叠（等 3 秒还拿不到就说「已经在查了」、退出码 0）；快速扫描另有 quick.lock；一份方案同时只在一个进程里执行（plans/<编号>.lock）；数据表和 agent-state.json 读改写都加锁。
  • 跑得轻：外部命令都带超时（默认 20 秒），超时或这一轮被叫停时先 TERM、2 秒后 KILL；起的程序留在扫描自己的进程组里，主控按组强杀时一起结束。只在 iCloud 的文件不读（读会触发下载）。
  • 被打断：收到 SIGTERM 时停在做完的那一步、保存报告、退出码 0；没来得及查的规则沿用上一轮的发现并在 skipped 里注明，量过的留给下一轮。被打断的一轮不做不用点就清；清的时候被打断见「不用点就清」。主控发 SIGTERM 15 秒后对整个进程组强杀。
  • 快速扫描（scan --this-mac --quick）：只在接着电源、不在低电量模式、内存压力不高（kern.memorystatus_vm_pressure_level ≤ 1）时跑；FSEvents 显示下载或桌面有改动才扫，只跑病毒扫描（不扫正在运行的程序），用精简库，跳过 120 秒内写过的文件，结果并进上一轮的报告；整轮在跑、还没有完整的一轮或没有完全磁盘访问时不做。现在没人起它，见「已知限制」。

检查什么

一轮按顺序跑 26 条规则（RuleOrder），每条记耗时（ruleSeconds）。下表按类别合并；"结论"是规则给的。只有会重建的缓存是"放心删"；仅供参考的不删东西，写清怎么处理。大小门槛按 MiB、GiB 算。

病毒扫描

  • 扫什么：下载文件夹里 30 天内来的文件（按修改时间或加入时间）和 Spotlight 记着在家目录别处下载的（kMDItemWhereFroms），这两处一轮最多 2000 个；下载来的应用里的程序（Contents/MacOS 全部，另加至多 50 个可执行文件）；本用户 LaunchAgent 运行的程序；正在运行的本用户程序（最多 300 个，系统目录里的不算，解释器跑的脚本也扫）；AI 工具 skill 里的文件（不论新旧，最多 1000 个）。
  • 只扫新的：扫过的记在 malware_scanned（路径、inode、大小、修改时间、当时认出的）；没变的 7 天后再扫，病毒库换新以后 3 天内来的文件用新库再扫；没有要扫的就不起 clamscan。
  • ClamAV：--max-filesize=100M --max-scansize=400M --alert-exceeds-max=yes，不跟链接；太大的合成一条 malware.too-large；读不了的不交给扫描器，下一轮再看；文件名带控制字符的单独报 malware.odd-name。整轮 clamscan 限 30 分钟、YARA 15 分钟。
  • YARA：自带两条规则（反弹 shell、伪造的系统密码对话框），加上 macOS 自带 XProtect 的规则（取版本新的那份；编不过时只用自带的），发现记成 malware.yara.xprotect.<规则>。
  • 精简库：快速扫描用的库由 sigtool --unpack 拆开后去掉 Win.、PUA.Win. 开头的特征和 PE 的节、导入表哈希，每个库文件一个子目录、只重做变了的；快速扫描扫过的记成 +quick，下一次整轮用全库再扫。
  • 病毒库更新（update）：每天最多一次；freshclam 读编在程序里的配置（每次写进新建的临时目录），库下载到从现有库克隆出的 clamav.staging，sigtool --info 逐个校验通过才换库，任何一步失败保留旧库；被上游限流时保留 freshclam 的冷却状态。ClamAV 的根证书编在 luoke-scan 里，用时写进临时目录，--cvdcertsdir 指过去。库超过 14 天没更新报 malware.stale-db，照样扫。

依赖里的已知恶意包

  • 名单：luoke-scan malicious-import <OSV 的 JSON、文件夹或 .zip> 从本机文件导入，不联网；只留 MAL- 开头、没撤回的 npm、PyPI、crates.io 条目，并进原有的名单（同一编号的换新）。没导入过时这条规则不查也不提；名单超过 30 天报 supplychain.stale-list。
  • 看哪里：项目目录下每个项目往下 3 层的九种锁文件（package-lock.json、npm-shrinkwrap.json、pnpm-lock.yaml、yarn.lock、bun.lock、uv.lock、poetry.lock、Pipfile.lock、Cargo.lock；node_modules、测试数据和示例文件夹里的不看），和全局装的包（npm 的全局目录里每个包的 package.json，bun、yarn、pnpm 的全局锁文件，pipx、uv tool、cargo install）。只读名字和版本，不打开包里的代码。
  • 比对：按「生态 + 规范化的包名 + 版本」，名单写着「所有版本」的也算；从 git、本地路径、别的网址装的不算；从私有源装的同名包照报，写明来自哪里。
  • 报法：同一个包一条 supplychain.malicious（高），列出用到它的地方和怎么办（删掉 node_modules 或虚拟环境、换到名单外的版本、装过就把令牌和钥匙都换掉）；最多单列 10 个包，其余并成一条。进 outbox 当急事，不替用户删项目里的东西。

增量

  • 量大小：每个文件夹和它下面两层 ≥ 1 MiB 的子目录记下 FSEvents 事件号、inode、大小；下一轮回放日志，没改动、inode 没变、真正量过不到 7 天的沿用，被碰过的只重量改过的子目录。日志换了（UUID 不同）或丢了事件就当一切都变了。回放前先等 fseventsd 交出刚写的事件（最多 5 秒），回放最多 60 秒，一轮里几条规则共用一次。
  • 临时目录、老项目、卸载残留：同样按 FSEvents 沿用上次的结论（temp_entries、project_state、leftover_state），最长 7 天。
  • 遍历在 APFS、HFS+ 上用 getattrlistbulk，不跟符号链接，不进挂在里面的别的卷；不够 20 个的临时目录前缀组不细看。新装应用和常驻项的签名结果按文件记下，最多沿用 7 天。

清理

  • 方案：scan_plan 或 outbox 卡片从上一轮的发现出方案（最多 30 项），每项可选移到废纸篓、先不动、以后别提；重复文件另有换成克隆，会重建的缓存是「删掉（会自动重建）」，失效的链接是「删掉（只是失效的链接）」。放心删的默认清，要确认的默认先不动。"仅供参考"的不进方案。要密码的项单独一份方案、单独一个按钮。方案存在 plans/，30 天后删掉。
  • 能进方案的：缓存类里不是仅供参考的（会重建的缓存、单个 AI 模型、Xcode 旧设备支持文件、恢复镜像）、残留（含没下完的下载、旧的 Intel 版 Homebrew）、临时目录的成批前缀、干净的久未动项目和其中的构建产物、久未打开的大文件、重复文件、本用户指向不存在程序的 LaunchAgent 和新出现的本用户 LaunchAgent、病毒库或 YARA 认出的文件。目标只能在家目录或临时目录里面（不能是家目录、临时目录、项目目录本身）；要密码的那份和 /usr/local 下的失效链接例外。
  • 执行（scan_apply）：没有 ai.luoke/user-action 就拒绝；只执行本工具出过的方案、只接受方案里列的选项，没送的项当"先不动"。每个目标再核对：还在、不是链接、设备号和 inode 没变、在家目录或临时目录里、父目录本用户可写、里面没挂别的盘、查过以后没改过（会重建的缓存 cache.rebuildable.* 除外，归在缓存类别里的 AI 模型、设备支持文件和恢复镜像要重下，同样要查；未来时间不算；核对总共最多 2 分钟）；久未动的项目再问一次 git；移的那一步再比一次核对时的设备号和 inode。核对不上的跳过并写原因。
  • 怎么删：移到废纸篓是改名挪进 ~/.Trash（重名时加「 2」「 3」，和访达一样）。会重建的缓存由扫描自己删：从 / 起一级一级不跟链接地打开，里面的链接只删链接，挂进来的别的盘不进去，不进废纸篓、放不回。LaunchAgent 要 launchctl bootout 和移走配置。重复文件移走前确认要留的那份还在且内容相同；换成克隆前逐字节再比一遍，几份都留着；比的时候读失败算不一样。系统级常驻项、登录项、crontab 不进方案：登录项打开系统设置，crontab 说用 crontab -e 删哪一行，系统级常驻项说在访达里移走（会要密码）。

不用点就清

四类默认关，用户在卡片或设置里点了「以后自动清」（scan_autoclean）才开；开了以后只在主控定时起的、带 --autoclean 的一轮里、查完且没被打断时做；agent 叫的一轮、快速扫描都不清。用户说过「以后别提」的不挑。

类判定怎么清
会重建的缓存位置正好是缓存清单里的那一处、是真文件夹不是链接、到它的路上也没有链接（真实路径正好是家目录的真实路径加上缓存的位置）、里面没挂盘、用它的程序都没在运行。清单里没写谁在用的不自动清（测试要求每项都写）扫描自己删文件夹，不跑工具自己的清理命令。不进废纸篓，放不回；还留 ≥ 1 MiB 算没清完
安装包下载文件夹里的普通文件，名字去掉版本、芯片、系统词后正好是已装的应用（≥ 4 个字母）；有隔离标记、有签名、来了 ≥ 14 天；名字带版本时不高于已装版本；没被打开、没挂着移到废纸篓
重复文件副本在下载文件夹里，来和改都 ≥ 7 天、不在项目里、独占 ≥ 1 MiB；留的那份在下载之外、在本地、不在构建类文件夹里，是另一个文件、内容相同；副本没被打开移到废纸篓
测试工具的临时文件夹只认 6 个前缀（Puppeteer、Playwright 的配置文件夹和产物、Lighthouse）；先要有 leak.temp-prefix 发现；每个文件夹 3 天没写、属于本用户、没挂盘、浏览器没开着、没被任何命令行点名；读不到进程列表就都不清移到废纸篓
  • 移进废纸篓的三类，动手前和点过的方案做同样的核对，每项前重读开关，ctime 不晚于这一轮开始。
  • 开关：scan_autoclean 开关全部四类，默认关。从某类放回过东西，那一类以后不再自动清（autoOff），关了再开时清空。状态文件读不出就不清，之后从"关"开始。
  • 被打断：每项之前都看一次，用户回来就停在两项之间，剩下的等下一轮。主控发 SIGTERM 15 秒后强杀，所以每清一项就写一次记录；这一轮的报告没存下时，由下一轮那一件告诉用户。
  • 清了的记成 auto-done：卡片给 [放回]（整批，缓存除外）和 [以后别自动清]。

要密码的删除

  • 范围：/Library 的 Application Support、Caches、Logs 里 root 拥有的卸载残留，和旧的 Intel 版 Homebrew（Cellar、Caskroom、Homebrew 三个文件夹全动或全不动）。按钮是「移到废纸篓（要输入密码）」，选项绑在 /admin_choices。
  • 流程：用户进程先再判一遍，在 plans/ 记下每个目标的设备号和 inode，再经描述符 3 请本体弹框，只交方案编号、自己的用户号、项的编号和 bundle id（最多等 280 秒）。本体逐项核对这些参数，用一个只有 PATH 环境的子进程弹 macOS 的授权框，框上是螺壳，每次都问。root 那一侧把本体包里的 luoke-scan-admin 拷进只有 root 能写的临时文件夹，核对是小于 100 MB 的普通文件，按螺壳的团队验这份拷贝的签名，用空环境运行；扫描说的话不进那条命令。临时签名的开发版不提权。
  • luoke-scan-admin：读用户的那份方案（不跟链接），按和扫描同一个判定重判每一项，再看整棵树，30 天内写过或有别的账户东西的不动，逐层不跟链接地打开，renameatx_np 移进用户的废纸篓。结果只经标准输出交回，由用户进程写记录。取消密码框时方案保留；本体等到时限也没答复时，已经挪走的照记，下一轮或放回时按设备号和 inode 再核。
  • 在终端里：luoke-scan system --this-mac 列出，--trash a0,a1 把同一步交给 sudo，每次在终端里问密码；root 直接跑会被拒绝。

放回

  • 清理记录写在只追加的 cleaned.jsonl，scan_restore 按一条（c-…）或一批（p-… / auto-…）放回，移进废纸篓的都带 ai.luoke.scan.cleaned 标记。
  • 用 RENAME_EXCL 放，原位置有同名的放成「名字（放回）」。整批不带报毒的文件和常驻项；受保护的位置不放回；要密码删的要在访达里拖。缓存放不回。

接口

给 agent 的 MCP 工具

按 agent 工具协议（版本 1，MCP 2026-07-28 的无状态子集：server/discover、resources/list、resources/read、tools/list、tools/call），走本体交来的标准输入输出（配件清单 capabilities.transport 是 "stdio"），一条消息至多 1 MB，通知不答。卡片是 A2UI v0.9（目录 ai.luoke/a2ui/agent/1，至多 200 个组件）。不支持订阅。

工具只读参数 → 答复
scan_status是— → 上一轮的时间和耗时、三种结论各多少、放心删能腾出多少、病毒库版本和日期、没查成的规则、自动清开着哪几类、是否正在查；带卡片
scan_findings是可选 verdict（safe / confirm / info）、category、limit（1–50，默认 20）→ 发现列表和卡片；标成"以后别提"的不列
scan_now是— → 另起 luoke-scan scan --for-agent --this-mac，马上答复；这一轮不清东西，也不问模型新的问题（只用记下的答复）；已经在查就说一声
scan_plan是可选 scope（all / cache）→ 方案和确认卡片
scan_apply否（destructive）plan_id、choices → 移了、克隆了、部分处理、以后不再提、已不在、没动的各几项；什么都没剩时 done: true
scan_ignore否finding_id → 以后不再报这一条
scan_restore否id（c-…、p-…、auto-…）→ 放回一条或一批
scan_autoclean否on（旧的 enable 照旧认）→ 开或关不用点就清的四类（默认关）
scan_reveal是finding_id → 在访达里选中；东西不在了答 stale。标 ai.luoke/where: mac
scan_open_settings是grant（隐私与安全性里的某项权限，或「登录项」）→ 打开系统设置对应页。标 Mac
outbox_ack是id、state（shown / answered / dismissed）；answered、dismissed 的不再出

非只读的工具没有完整的 ai.luoke/user-action（surfaceId、componentId、at）答 needs_user_action。其他错误码：not_ready、stale、invalid、failed。发现的编号跨轮稳定：规则名加规范化路径（或规则给的键）的哈希。卡片里家目录下的路径写成 ~/…。

生成任务

三个任务的提示词在 prompts/（照顶层 ADR 0019 的格式），装好的包用编在 luoke-scan 里的那份，开发版从程序往上找仓库里的；建议参数 temperature 0、top_p 1、不思考。每一轮规则查完（自动清理之后）、存报告之前问：先 GET /tasks，只问 available 的任务，POST /tasks/<任务>/v1/chat/completions，后台优先级、流式，请求体和 bench/run_eval.py 发的逐字节一样。每轮新问的最多 skills 10 条、identify 5 条、explain 10 条，三个任务一共最多 3 分钟，一条最多等 90 秒；一个任务被挡回、出错或超时，这一轮就不再问它（主控说等不超过 5 秒时等一次再问）。答复按任务、提示词指纹和输入记在 model_answers 表，同一输入下一轮直接用，30 天没用到就删；agent 叫的那一轮只用记下的。只在装好的螺壳里，或指向自己主控（LUOKE_HUB_SOCKET）的开发版、用这台 Mac 自己的数据目录时问；主控不在、任务没开时只多一次 GET /tasks，报告照旧。模型说的只作为证据（model_explain、model_identify、model_note）附在发现下面，不改结论、轻重、标题和编号；卡片、清理方案、病毒提醒、scan_findings 和 report 上都显示。

任务提示词输入 → 输出
luoke-scan.explain第 4 版，至多 120 字、300 token卡片上要用户看的发现（不是仅供参考的，或仅供参考但风险高的；skill 和说明文件的不问），重的、大的在前：结论、标题、位置、大小、规则的依据（整个不超过 3000 字）→ 一两句大白话：是什么、为什么报、处理会怎样。不改结论，不编数字，不说已经处理，would_lose 每项都说，不写命令。显示前照评测的检查再核：超长、Markdown、命令、网址、说已经做了、把不是放心删的说成能删、输入里没有的带单位的数字，都不显示

luoke-scan.skills第 3 版，400 token规则报了的 skill（skill.*，不含说明文件），问时重读一遍：名字、说明、允许的工具、文件列表、SKILL.md 正文、其他几个文件、规则查到的，整个 JSON 不超过 6000 字符 → JSON {fits, does, beyond, risk}。只在说对不上时附说明，说对得上时什么都不附（免得替 skill 打包票）；带网址、域名、IP、命令、密钥、代码的句子不显示，指到 skill 里没有的文件的那条去掉

打包

  • scripts/package_app.py --out <目录> 编出 luoke-scan/，照螺壳.app 的 Contents 摆：Helpers/ 里是 luoke-scan、luoke-scan-admin（Go 编，只出 arm64；luoke-scan 带打包标记，发行团队标识由 LUOKE_RELEASE_TEAM 编进去，源码里不写）和 clamscan、freshclam、sigtool、yara（照 Homebrew 里装好的拷来，标识 ai.luoke.scan.<名字>）；Frameworks/ 是它们要的库，路径改成 @rpath，ClamAV 的 RAR 支持运行时由 LD_LIBRARY_PATH 指到这里；Resources/scan/ 是去掉草案标记的配件清单、bundled-tools.json（每个随包程序和库的版本、来源、SHA-256）和图标；Resources/licenses/luoke-scan/ 是许可证（ClamAV 为 GPLv2）和第三方说明（ClamAV 完整的对应源码挂在螺壳的发布上，说明里指向索引）。
  • 两个程序各链进一份 Info.plist（标识和版本号），签名盖住它，本体从签名信息读版本；拷进去以后、签名以前去掉调试信息和本地符号（strip -S -x）。这里只做临时签名、定好标识。
  • 进螺壳：luoke-core 的 app/build_app.sh 给了 LUOKE_SCAN_SRC 才带：跑那个提交的 package_app.py，Resources、Frameworks 在外层 --deep 签名之前拷进去，Helpers 之后拷进去，再不带 --deep 签一次；版本写进螺壳 Info.plist 的 LuokeScanVersion。正式签名时统一加 hardened runtime、保留标识，签好后跑 package_app.py --verify-app <螺壳.app>。
  • 核对：签名完整、标识对、没有 get-task-allow，正式签名的要 hardened runtime、和螺壳同一个团队；编进去的提示词、freshclam.conf、根证书和仓库里的一样；没有包外的库路径；第三方库只有允许清单里的，第三方说明覆盖每个文件；在读不到 Homebrew 的沙箱里用包里的 clamscan 和 YARA 真扫一个 EICAR 测试文件；包里的 luoke-scan 不收开发参数。Go 只用标准库和 golang.org/x/sys。

已知限制

  • 两轮之间不看新下载的：快速扫描（scan --quick）的代码在，但清单的空闲任务只有 update、scan，本体也只放行这两条，没人起它。
  • 第一轮常没有病毒库：开启后马上跑的那一轮排在 update 前面，病毒扫描要等之后的一轮。
  • 不降优先级：扫描和它起的 clamscan、git 等都按默认优先级跑，自己不调低。
  • 「现在查一下」那一轮不归主控：scan_now 起的一轮不是空闲任务，用户回来时不让路。
  • 模型的说明要主控开着任务：三个生成任务没开（不在 GET /tasks 的 available 里）时一条都不问，报告和卡片只有规则的文字；skills 第 3 版只在 16 档的参数上评过。
  • 没有窗口：扫描只有命令行，两页基础页和卡片由 agent 交给螺壳的窗口画；在终端里能看的是 report、findings、status、cleaned、system。
  • 规则写在代码里：规则、门槛、缓存清单、skill 和说明文件的位置表都在 Go 代码里，没有规则文件；规则包版本只是一个常量。加一条规则要改代码、发新版。
  • skill 和说明文件只看写法：编译过的程序、压缩包、太大的文件只报「读不了」；拼出来的命令、写法正常而用意不正的看不出来；只查位置表里的地方。
  • 恶意包名单要自己导入：扫描不下载名单，没导入过这一项不查；导入以后不会自己更新，过 30 天只提醒。
  • 没有按类别手动关自动清的开关：只能全关，或放回一次让那一类停下。
