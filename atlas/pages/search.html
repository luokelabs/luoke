深度搜索

给 Mac 上用户选的文件夹和照片图库建索引，按字词和按意思找回来。没有自己的窗口，入口在 agent 的对话和螺壳窗口的全局搜索，窗口还显示它的概况和权限。深度搜索这边的接口已备好；窗口和对话由 luoke-agent 写，还没上线，现在只能用命令行。向量由主控算，自己不带模型。

仓库 luoke-search（Swift 包 LuokeSearchKit）· 版本 0.1.0，按代码 a0113d3 核对 · 未发布：不在 v1 首发中，进 beta 2 · 只支持 macOS 26.2 及以上

职责

  • 第一版搜本机文件（文档、PDF 含扫描件、截图、图片、视频、录音）和照片图库。不搜代码。
  • 只读用户的文件，不改、不移动、不上传；照片图库只读。
  • 不主动找用户：只经 agent 的 outbox 报三类事。改设置、打开文件、请 macOS 问照片权限，这三件都要用户在卡片上点按。
  • 第一版不读也不写记忆，搜索词不写进记忆。

运行形态

入口行为
螺壳深度搜索.appbundle id ai.luoke.search，LSUIElement（不出现在程序坞）。主控在登录时带 --resident 拉起，打开即 serve；带 --resident 时向主控 PUT /accessory/resident，收到 SIGTERM 退出前 POST /accessory/exiting
luoke-search serve常驻服务：在 run/agent.sock 上提供 MCP，并跟着文件夹和照片图库更新索引；每 5 分钟补一次还在等的向量，每 2 分钟看一次设置、照片权限和文件夹能不能读；10 分钟没人搜就放掉内存里的向量。--socket 换 socket 路径，--no-watch 只开 socket
luoke-search index --job第一遍建索引（供主控的空闲任务调用）：同步设置里的文件夹和照片图库、读等着的、补向量；SIGTERM / SIGINT 时读完手上那个文件就停，退出码 0，下次接着读；标准错误只有计数
其他子命令同一个可执行文件 Contents/MacOS/luoke-search 也是命令行，见「接口」
  • 没有自己的窗口：设计上用户在 agent 的对话里提问，agent 调 MCP 工具并画结果卡片（agent 的对话还没做）；搜哪些文件夹、是否加入照片图库也由 agent 的卡片询问。配件清单给螺壳的窗口提供概况（summary）、权限状态（permissions）和一行介绍（listing）。
  • 读取和算向量分开：读取（取文字、OCR、抽帧、切声音）由本工具完成，读完即可按字词搜；向量找主控要，主控不在或忙时记为等向量，以后补。
  • 跟着文件夹：常驻服务启动时把文件夹走一遍（只看名字和时间，不读内容），移出不再搜的；之后用 FSEvents 盯着，变化停 0.75 秒后一起处理（最长攒 5 秒），只看变了的路径（新的、改过的、移动或改名的只改路径、删掉的、整个搬进来的文件夹）。新变的文件马上读，每次最多 50 个，排在第一遍的积压前面，读完补向量。设置改了就换成盯新的文件夹。
  • 第一遍兜底：常驻服务每 2 分钟检查一次，有等着读的就读一段（最多 100 个）；文件一有变化就让路。等着读的按截图、图片和照片、PDF、文档、录音、视频的顺序，同类里新的先。
  • 什么时候停：连着主控时只听主控的后台状态（GET /tasks 的 background），再加本机的低电量模式和过热，设置里的 on_battery 不起作用；没连主控时才看 on_battery（默认关）、低电量和过热。补向量只在主控暂停后台时停。常驻服务从不带 X-Luoke-Allow-Battery，打开 app 时带了 --allow-battery 也不带。停着时 search_status 的 paused 写原因和由谁暂停，答复里说一句"因为螺壳的后台已暂停（在用电池）…"。
  • 长文件先读开头：超过 50 页的 PDF 第一遍只读前 30 页，超过 40 段的文档只读前 40 段，条目记为 partial，读到的部分照样能搜；所有文件都过一遍以后，PDF 再每次 30 页往后补，文档剩下的一步读完，每步读完就存，能停能续；文件改了从头读。盘拔了或内容被 iCloud 挪走时留到下次，不当成读不了。
  • 不在这台 Mac 上：等着读的文件只在 iCloud、或盘不在时放一边，计入 not_on_this_mac，回到本机再读；以前记成"文件不在了"的重排一次。
  • 单个文件的看门狗（index、index --job、常驻服务都开着）：读一个文件时每秒看一次本进程内存和这个文件读了多久。内存超过上限（物理内存的一半，限在 4–8 GB）且至少一半是读这个文件时涨的，一步读了 15 分钟（只算 Mac 醒着的时间），或各步加起来超过总时限（60 分钟或每页 5 秒，取大的；剩不到 60 秒不开新一步），就把这个文件（连同修改时间和大小）和原因写进 run/stopped-file.json，以退出码 75 结束进程；下次起来先把它记为读不了，文件改过才重读。
  • 读到一半进程没了：每个条目记读的次数，两次都没读完就不再读（长文件的后续部分同样计数，已读的留着）。
  • 照片图库：常驻服务盯着图库的变更通知（变化攒 2 秒合一次），新拍的马上读。常驻服务从不询问：设置打开了图库但还没问过时，outbox 报 needs-access/photos/<编号>，用户在卡片上点「继续」才经 search_request_access 请 macOS 询问，最多等 240 秒；limited 权限算允许。被拒后卡片改成去系统设置，并带「算了」。
  • 线程：常驻的活在自己的一条串行队列上，MCP 另有连接线程；读文件（尤其 OCR）不在 Swift 并发的线程池里做，一个进程同时只做一张 OCR。
  • 签名：hardened runtime，权限只有 Apple Events（让 QuickTime Player 跳到某一刻）和照片图库。

不读什么

  • 不跟符号链接；不进包（含照片图库的包，图库经 PhotoKit 读）、名字像凭证的文件夹、隐藏文件夹、~/Library、*.noindex、开发用文件夹（node_modules、venv、site-packages、DerivedData、Pods 等）和用户跳过的文件夹。
  • 代码项目（含 .git、package.json、Package.swift、pyproject.toml、Cargo.toml、.xcodeproj 等的文件夹）里只读截图。
  • 只在 iCloud、没下载到本机的文件不读（读会触发下载）。
  • 像数据集的文件夹：同一个文件夹里同一类媒体（图片、视频、录音）≥ 300 个、其中 ≥ 70% 是机器起的名字（纯数字、十六进制串和 UUID、frame_0042、clip-000123 这类数据集词加数字），这一类不读，文档照读。相机和系统起的名字（IMG_、DSC、PXL_、截屏等）、名字里带日期的、其他词加数字的不算；图片再抽 10 张看 EXIF，一半以上写了相机厂家或型号的不跳。用户直接选的文件夹（含套在另一个选中文件夹里的）不算。status 和 search_status 列出这些文件夹。
  • 凭证文件不读：按扩展名（pem、p12、kdbx、key、ovpn 等）、名字开头（id_rsa、.env、.netrc 等）、名字里的词（password、credentials、secret、api key、recovery codes、seed phrase 等）、中日韩片段（密码、口令、密钥、私钥、助记词、恢复码等）和密码管理器的导出（logins.csv、bitwarden / lastpass 导出、keepass）。单独的 key、token 不算。开头是 zip 的单文件 Keynote（.key）不算凭证，也不读、不报。
  • 发布版的搜索范围：只收家目录内和 /Volumes/<盘>/…；路径任何一段不能隐藏；~/Library 下只收 Mobile Documents（iCloud 云盘），所以 ~/Library/CloudStorage 里的第三方网盘不收；不收 /、/Volumes 本身和 Time Machine 的备份。先解开符号链接再判，每次走文件夹都重判。
  • 拔掉的盘、macOS 不让读的根文件夹记为读不了，其中已有的条目保留。

audioAVFoundation 解成 16 kHz 单声道，30 秒一窗、每 25 秒起一窗，静音窗丢掉；不转文字，等声音向量那一窗的起止秒
video每 3 秒一帧（最多 1200 帧），和上一张留下的帧几乎一样的不留；音轨照录音切。没有画面、有声音的按声音读，两样都没有才记读不了；AVFoundation 打不开的格式（mkv、webm 等）记读不了那一帧或那一窗的秒数

  • OCR 用系统的 Vision，指定语言、中文排第一（简体、繁体、英文、日文、韩文，再加本机偏好的语言）。
  • 每个条目的时间：有拍摄时间用拍摄时间，否则用修改时间。照片图库的条目路径记为 photos:<本机标识>，标题是导入时的文件名，没有就叫"照片""视频"。
  • 每个条目另有一段"名字"（文件名和所在文件夹），只按字词搜。
  • 读法升版时（现在文档是 3，其他是 1），旧版读过的条目自动重读。
  • 认 59 个扩展名：文档 14 个、PDF、图片 20 个（含 dng、cr2、nef 等相机原片）、视频 13 个、录音 11 个。ts、mts 要看同步字节。列在表里不等于读得出，AVFoundation 打不开的记读不了。

怎么搜

  • 按字词：SQLite FTS5 两张表，fts（unicode61 + Porter 词干）和 fts_tri（trigram，给中文、日文等不用空格的文字）。查询中的中日文用系统分词（NLTokenizer）切词，去掉停用词和相对时间词（"上个月""去年"等，交给 agent 换成 since / until）；分词器拆成单字的相邻字连起来再试（可选词：找到每个加 0.1、最多 0.3，找不到不扣，不能单独让条目入围）；三个字以上走 trigram，两个字用 LIKE；带空格的文字 3 字以上、索引里没有原词时按前缀找，阿拉伯字母和印度系文字的词一律按前缀找。存关键词和查问题前都先做同样的规整：去掉看不见的格式字符，阿拉伯文去掉元音符号和拉长线，并统一几个字母的写法。问题只看前 200 字，必需词最多 12 个、可选词最多 8 个，每个词最多取 5000 条。
  • 类型词：查询中的"截图""照片""录音""视频""PDF""文档"等不当关键词，给对应类型加分（不是筛选），这类条目按意思 z ≥ 1 即入围；"照片"同时指文件夹里的图片和图库的照片。只有类型词、按意思也没找到时，列出该类型最新的条目。
  • 按意思：查询向量以 user-waiting 向主控要（模型在加载时最多等两次，一次请求限时 10 秒）。全部向量以 fp16 存在索引里，搜索时整块读进内存，之后只增量读改过的行，每 1024 行转 fp32 用 vDSP 求余弦。每个条目取最好的一段。
  • 混合打分（默认做法 A）：余弦先换成 z 分：满 20 行的模态（文字、图片、声音）按自己的均值居中，不满的按全体均值；离散度全体合着算，每行跟其余各行比（留一法），并向典型值 0.03 收缩。条目入围条件：z ≥ 2（类型词对上时 ≥ 1），或含必需的查询词至少一半。分数 = z + 2 ×（命中词比例）1.5 + 0.5 × 名字中的命中比例 + 0.3 × 名次项 + 类型词加 1。查询的词都含数字（编号、单号）时按精确查找：字词权重加倍、z 减半。
  • 其他打分做法只在 eval --scoring 里用于对比：b（每个模态只和自己比）、c<k>（模态的均值和方差按 k 行的分量往全体拉）、d（各自均值、离散度合着算）。
  • 结果：分数不到第一名一半的标 strong: false（卡片上标"可能相关"）；原文件已不在的不列出。结果指向含查询词最多的一段（名字和内容都对得上时指向内容）；按意思入围的指向意思最好的那段。表格命中时片段是含查询词的一两行，每格前写列名。片段和标题送出前遮掉凭证，索引里保留原文。
  • 遮凭证：规则从记忆的 find_secrets 起步并扩充，分七类：密码、验证码、密钥换成〔密码〕这样；助记词、恢复码同样整串遮；卡号、证件号留后 4 位（〔卡号 ****1111〕）。全角和其他文字的数字先折成半角再认，夹了零宽空格的两种读法都看。表格按列名遮；没有可用列名时，一列六成以上像密码就整列遮。search_open 的答复、文件夹显示名（方案、卡片、outbox）也遮；path 不遮，含 outbox 的 id 和卡片小字里的路径。已知漏：带空格又不是英文词的密码、OCR 认错的卡号、无表头的纯小写字母数字密码。
  • 拒答门槛未开：没有结果时 confident 为 false，有结果时为 null（"有结果但说不准"）。候选门槛（字词全中，或第一条的余弦过它那个模态的门槛：文字 0.70 / 图片 0.66 / 声音 0.70）只在 eval --refusal 里量，是否开启待定；开启后没过门槛的结果照给、标 confident: false。

接口

给 agent 的 MCP 工具

按 agent 工具协议（版本 1，协议版本 2026-07-28，MCP 无状态子集：server/discover、resources/list、resources/read、tools/list、tools/call，另答 initialize、ping），在 ~/.luoke-search/run/agent.sock 上 POST /mcp；luoke-search mcp 在标准输入输出上提供同一组工具（一行一条）。一次只处理一个请求；socket 上的 search_request_access 要等用户答复，不占这个锁。

工具只读参数 → 答复
search_query是query（可省：只给 since / until / kinds 时列出最新的）；可选 kinds（doc pdf screenshot image video audio photo，筛选；不认识的静默忽略）、since / until（ISO 8601 日期或时间，不带时区按本机时间）、limit（1–50，默认 10）→ hits、partial、partial_reason、confident、took_ms，加一张结果卡片（前 5 条，每条 [打开]，文件另有 [在访达中显示]，照片没有；每次 surfaceId 不同）
search_open否id、可选 reveal → 一句说明。没有 ai.luoke/user-action 答 needs_user_action。视频、录音用 QuickTime Player 跳到那一刻；PDF 说明在第几页；照片打开「照片」并说明拍摄时间，读不了图库或没允许时答 failed 并说明原因；文件不在了答 stale。标 ai.luoke/where: mac
search_status是— → items（按类型）、waiting（read / rest_of_long_files / vectors / media / not_on_this_mac）、paused（reasons、by、reading、vectors）、dataset_folders（路径和文件数）、first_pass_done、hub（state：available / downloading / busy / unsupported / not_running / not_connected，note）、folders、photos（on / needs_access / off）
search_settings是不带 change：当前设置。带 change（add_folders、remove_folders、skip_folders、photos、on_battery；文件夹可写路径或 desktop、documents、downloads、pictures、movies、music 和对应的中文名）；这一步会往 state.json 写方案→ plan_id、changes 和一张确认卡片：文件夹写访达里的名字，完整路径在小字里；加文件夹时数一下大约多少文件（桌面、文稿、下载、iCloud 云盘、外接盘这类 macOS 保护的位置不数，只说明 macOS 会先询问）
search_settings_apply否plan_id、可选 checks（用户在卡片上的勾选）→ 执行自己出过的方案。勾选不合法或全不勾答 invalid。没有 ai.luoke/user-action、或点按的不是这个方案自己的卡片，答 needs_user_action；设置文件读不了答 needs_setup；方案已不在、设置在出方案后变过、选文件夹的方案已选过或放下，都答 stale；macOS 不让读的文件夹答 needs_setup 并换上带 [打开系统设置] 的卡片
search_open_system_settings是pane：files（文件和文件夹）/ full_disk（完全磁盘访问）/ photos → 打开系统设置对应隐私页。标 Mac
search_request_access否id（photos）→ 请 macOS 询问，等用户答复。只有常驻服务会请 macOS 问，别的进程答 failed。要 ai.luoke/user-action。标 Mac、waits
outbox_ack是id、state（shown / answered / dismissed）；只收 outbox 现在可能有的 id，别的答 invalid；shown 不记，answered、dismissed 的不再出

结果条目：id（条目号加位置，如 12#p3 第 3 页、#s 幻灯片、#w 工作表、#c 第几部分、#t25.0 秒）、kind、title、path（照片图库的条目为空）、where（page / part / sheet / time / end）、date、snippet（约 160 字）、why（"第 3 页的文字对得上"等）、score、strong，以及给窗口用的 source、line、thumb、actions。

依赖主控

  • 任务：客户端请求的任务名为 luoke-search.embed（配件清单同名；开发时 LUOKE_SEARCH_EMBED_TASK 可换成归 luoke-search 的其他任务）。主控的开发配方已有这个任务，16 / 32 / 128 三档都分给 embeddinggemma-2，只收文字，verified 里有 luoke-search；发布配方里它在进流水线、过参考向量集评测之前各档关着，答 unsupported"这一档没通过验证"，深度搜索说成"这台 Mac 上的螺壳不提供按意思搜"，只按字词搜。不认识深度搜索的旧主控答 403，传输失败也一样归成 unsupported。
  • 接口：GET /tasks 读状态、后台在不在跑（background，决定暂停）和参数（batch、max_chars、max_total_chars、vector_space，以及 image_batch、image_budgets、audio_batch、max_image_bytes、max_audio_bytes、max_audio_secs），X-Luoke-Tasks-Version 变了就重读；POST /tasks/<任务>/v1/embed 送 texts 或 inputs（图片、声音的字节，不送路径）。请求头 X-Luoke-Accessory: luoke-search/0.1.0、X-Luoke-Priority，需要时 X-Luoke-Allow-Battery。要求 768 维，收到后再做 L2 归一化。
  • 提示词：查询 task: search result | query: …；文档 title: … | text: …（标题用文件名，PDF 用它自己的标题）。
  • 图片和声音：索引里不存像素和声音；主控的参数表明收某一种时，从文件重新做出同样的帧和窗口再送。预算：照片和图片 JPEG ≤ 1024 px、140；截图 PNG ≤ 1536 px、280；扫描页 PNG 1400 px、280；视频帧 JPEG ≤ 1024 px、70；声音 30 秒 WAV。一个一个做、攒够一批就发；这一档不收的预算照旧等；暂时失败的试 3 次，主控说读不了的那条不再要向量。补向量时重做图片和声音这一步也在看门狗下：内存从这个文件开始算，时间只算做图，每 30 张一步，不算送去主控的时间；停下后字照旧能搜，图和声音不再等向量。崩溃两次也放弃。有文件等着读时，一轮补向量最多 60 秒。文件不在本机时不打开、不放弃，等它回来；超了字节上限先换 JPEG 再缩一半，透明处都铺白底。
  • 主控不在或忙：照常读取、按字词搜，答复带 partial_reason（主控没在运行、不认识深度搜索、这台 Mac 不提供、还有多少段等向量等），不退回任何自带模型。补向量时 power_cooldown、lane_busy 这类短歇原地等完；其他拒绝停下、下次再补（index --wait 时按 retry_after_ms 等，连续没进展才翻倍，最多 300 秒）。vector_space 变了只重算向量，不重读文件；空间不一致时这次只按字词搜。
  • 开发不碰正在用的主控：只有默认数据目录 ~/.luoke-search 且是 app 本身，才回退到已安装主控的 socket；带 --index 或 LUOKE_SEARCH_HOME 的运行只认 LUOKE_HUB_SOCKET，没设就只按字词搜。

故障

  • 主控不在、忙或任务不可用：照常读文件、按字词搜，向量以后补；答复带 partial 和一句说明。
  • 还在建索引或长文件没读完时答复带 partial（"还有 N 个文件没读""还有 N 个长文件没读完"）；图片、视频、录音在等主控时说明暂时只能按名字和里面的字找到。
  • 文件读不了（加密 PDF、打不开的视频格式）记为 failed，只在 iCloud 的图库视频记为 skipped，都不影响其他文件；等着读的文件不在本机时放一边，不算读不了；文件消失后结果不再列出，search_open 答 stale。
  • SIGTERM：手上那个文件读完就停，删掉自己的 socket；剩下的下次接着读。
  • 单个文件读得过久或内存失控：看门狗记下该文件、以退出码 75 退出，由主控重新拉起（十分钟内最多 3 次）；该文件记为读不了，改过才重读。

已知限制

  • 发布配方里 luoke-search.embed 在过评测之前各档关着：在那之前正式环境只能按字词搜。
  • 完全磁盘访问：按 ADR 0021 改为授权给螺壳本身，常驻服务由螺壳本体起；代码还没跟上：配件清单的常驻项和 jobs 没写 "permissions": ["fda"]，常驻服务仍由主控带 --resident 拉起，文件夹的 needs-access 卡片仍叫用户在「文件和文件夹」里允许"螺壳深度搜索"。
  • 还没进主控的发布流水线；build_app.sh 不做公证。
  • 主控配方里这个任务现在只收文字；图片、视频、录音、照片只能按文件名、拍摄时间和 OCR 的字找。
  • 拒答门槛未开启，confident 有结果时恒为 null，答复不表示"有把握"。
  • 默认打分 A 在文档多、图少于 20 张的文件夹里，对的图 z 余量小（测得最低约 2.3）。问"X 的照片"而同文件夹文档写了 X 时，可能文档排第一。录音题成绩不稳定（3 题对 1 题），原因是模型的声音向量对中文说话声差。
  • 配件清单没有登记 jobs：第一遍由常驻服务兜底读，index --job 没有接上主控的空闲任务。
  • 只有类型词或只给时间时的兜底列表会列出读不了、等着读和放一边的条目（strong: true、分数 0）；点开只在 iCloud 的会触发下载。
  • 录音和视频音轨不转文字；mkv、webm 等 AVFoundation 打不开的视频读不了。
  • 照片图库测过假图库和一次真图库只读测试；iCloud"优化 Mac 储存空间"的图库和几万张的图库没测；PDF 无法从外部定位到页，只在答复中说明页码；「照片」无法定位到某一张。
  • 邮件、记忆、打字记录的搜索（第二步）未做；判断要不要搜归 agent，手机端先纯文字。找相似没做。
  • 被要求停（SIGTERM）时等手上的条目做完，一个条目可能超过主控给的 15 秒宽限（扫描 PDF 一步约 18 秒、长视频抽帧、一次阻塞的向量请求）；被强杀时这次读也计次数，同一个文件两次都这样就记成读不了，改了才重读。
