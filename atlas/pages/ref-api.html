主控任务接口

主控在 Unix socket 上提供的 HTTP/1.1 接口，供配件、主控本体和命令行 luoke 调用。每次请求一条连接。

连接

  • socket：~/Library/Application Support/luoke-core/run/hub.sock（目录 0700，文件 0600）。配件依次查找：显式路径 → 环境变量 LUOKE_HUB_SOCKET → 默认位置；给了显式路径而它不存在时报错，不退回。
  • 身份：请求头 X-Luoke-Accessory: <配件>/<版本>。版本须在配方 verified 中，或本机放行（只在内部版、本机版），或是本机 verified-history.json 中有记录的已安装版本（换回的上一版，只能用记录中的任务）；带任务名的请求还要求任务存在且属于该配件。
  • 响应头：X-Luoke-Contract: 1、X-Luoke-Tasks-Version（配方、档、模型分配、引擎版本、任务参数的摘要，有嵌入任务时还含向量空间；变化即应重读 /tasks）。
  • 请求体为 JSON，上限 32 MB，超过答 invalid_request。
  • 启动和退出：主控启动期间只答 /tasks、/status、/downloads，别的答 busy（retry_after 5）；退出期间答 engine_failed。

错误

错误体为 {"code", "message", "retry_after", …}；有 retry_after 时同时给 Retry-After 头。

HTTPcode含义
400invalid_request请求格式或参数不合法；没有这个路由
403unknown_accessory缺身份头，配件或版本未通过验证，或任务不属于该配件
403forbidden主控本体专用的路由，对端不是本体（或允许的命令行）
404task_unavailable任务不存在，或现在用不了（模型要下载、正在下载、暂停，原因同 /tasks 的 reason）；换回的上一版调用其记录外的任务
unsupported本档不支持该任务，或配件还没在这一版螺壳里验证过；这一构建或这个配件不支持该操作
409session_lost、superseded转写：主控没有这次听写到这一块为止的音频；草稿还在排队时同一会话来了更新的请求
413input_too_long超过任务参数的上限（max_chars 等）
503busy暂时不能接纳，附 reason（见主控 · 后台接纳）；主控正在启动
paused全机后台暂停或本档放不下
not_ready模型正在加载或工作进程按需重起（retry_after 2）；内存不够或内存压力 critical 后暂不启动工作进程（retry_after 30）
needs_user用户在等但内存放不下，附 occupants（占用内存的进程）
engine_failed引擎或工作进程出错；主控内部错误；主控正在退出

流式生成过程中的错误以 event: luoke.error 事件给出，另有 interrupted（后台请求被用户请求打断）。

任务

GET /tasks

返回 {contract, hub_version, tier, tasks_version, background: {state, reasons}, tasks: {<名>: {kind, main, status, reason, progress, slow, combo, model_name, params, vector_space?}}, luoke_mem?: {path, version, python?}}。只列出请求方自己的任务；status 为 available、unsupported、needs_download、downloading、paused；model_name 是只用来显示的模型名（配方的 label，没有则取目录名，本档没有模型时为 null）；vector_space 只有嵌入任务有；luoke_mem 给出主控内置的记忆库路径、版本和自带的 Python。

生成 POST /tasks/<task>/v1/chat/completions

  • 任务 kind 为 generate。请求为 OpenAI 格式的 messages（role 为 system、user、assistant；content 为字符串或分段，只取文字段；总字数 ≤ max_chars），必须 stream: true，可带 luoke_items（本批条目数，默认 1，≤ batch）；response_format 可用 json_schema（须带 schema）或 json_object。
  • 请求头 X-Luoke-Priority 必填（user-waiting 或 background）；X-Luoke-Allow-Battery: 1 可选。
  • 主控覆盖：max_tokens = item_tokens × luoke_items + fixed_tokens；采样参数取配方，是否思考取任务参数 think；中和消息中的模型特殊 token；答复中的 model 改写为组合名。
  • SSE 流中另有 event: luoke.progress（queued、loading、running）。

打分 POST /tasks/<task>/v1/score

kind score。请求 {context, candidates}（候选 ≤ batch，默认 16；前文 ≤ max_chars，默认 2000）；答复 {logprobs, model, cache_hit, ms}。超时 10 秒。

续写 POST /tasks/<task>/v1/continue

kind predict。请求 {context, k?, max_tokens?, stop?}：k、max_tokens 不给取任务参数 k（默认 8）、max_tokens（没写取 n，默认 6），也不能超过它们；stop 最多 64 个、每个 1–8 字；前文 ≤ max_chars（默认 2000）。答复 {branches: [{tokens: [{text, logprob}], finish}], model, cache_hit, ms}，finish 为 stop、length 或 eos。超时 10 秒。旧接口 /v1/predict（请求 {context, k?, n?}，答复 {continuations, model, cache_hit, ms}）仍保留。

嵌入 POST /tasks/<task>/v1/embed

kind embed。请求 {texts: [...]}（任务参数允许时可改用多模态 inputs，每条恰好一个 text、image 或 audio，答复多一个逐条的 errors）；答复 {vectors, dims, model, vector_space, ms}。默认每批 32 条、单条 32000 字、合计 320000 字；每条在工作进程里按 token 截到任务参数 max_tokens（默认 2048）。X-Luoke-Priority 可选，不带按 background：后台请求不占引擎的后台名额，按全机后台状态、交互和这个任务自己的功耗档间歇接纳（可带 X-Luoke-Allow-Battery: 1），间歇中答 busy（reason 为 lane_busy）并附 retry_after_ms；user-waiting 排到后台批的前面。

转写 POST /tasks/<task>/v1/transcribe

kind transcribe。一次听写是一个会话，音频分块追加，要草稿或终稿时算用户在等。请求 {session, seq, audio, want?, context?, language?}：session 1–64 字；seq 从 0 起逐次加一，0 为新开或从头重送；audio 是上次以后新录的部分，base64 的 PCM16LE、16 kHz、单声道；want 为 none（只追加）、draft、final（默认）或 cancel；context ≤ 任务参数 max_context_chars（默认 2000）；language 是语言的英文名，不给取任务参数。答复 {text, final, audio_secs, ms, model}，none、cancel 答 {ok: true}。音频只在内存里，终稿、取消或 30 秒没消息即丢弃；每个配件同时最多 4 个会话，新开时丢掉最久没动的；一次听写最长为任务参数 max_audio_secs（默认 120 秒）。主控接不上 seq 时答 session_lost，从 seq 0 重送整段；没算成的那一块当没收到，照 retry_after 原样重发。

预热 POST /warmup

请求 {task, lease_id?}；答复 {accepted, lease_id, expires_in: 600}，或 {accepted: false, code}：任务现在用不了为 task_unavailable、unsupported，低电量模式或内存压力不正常时新的预热为 deferred。任务不存在答 404 task_unavailable。新的预热算作交互，续期不算。生成任务的预热在底座没加载时加载底座；打分、联想、嵌入、转写任务的预热会启动工作进程（转写的已经起着的也重新热一遍）；内存不够时照样答应，真正请求时答 not_ready。

配件管理

路由说明
GET /accessories{contract, accessories}：已安装配件的公开字段 accessory、bundle_id、name、version、type、resident、memory、tasks、capabilities、jobs（只给名字）、data；没开启的螺壳里带的应用不列
PUT /accessory/resident{resident}，声明是否常驻
POST /accessory/exiting配件主动退出前通知：本体据此不把这次退出当异常，主控停止只由它使用的工作进程

主控本体专用

以下路由（注明不要求身份的除外）要求身份为 luoke-core，并按内核报告的对端 PID 核对对端是主控进程的父进程（即本体）。/settings 和 /endpoint* 另外接受主控自带的命令行 luoke（与主控同一个 Python 可执行文件、参数为 -m luoke_core.cli）。不符时答 forbidden。

路由说明
GET /status运行状态（不要求身份，启动期间也答）：档、底座、引擎、交互、后台、冒烟、设置、下载、空闲任务、端点（不含密钥）等
GET/POST /downloadsGET 答 {needed, downloads}：缺少的下载项和进度；POST {names?} 开始下载，不给就下缺的；没有发布清单的开发构建答 unsupported
GET/PUT /settingspower_mode（full、balanced、quiet）、background_on_battery、tier（只能选内存够的档，空为按内存定）、endpoint_enabled、endpoint_port（1024–65535）；PUT 还收 endpoint_key，只写进密钥文件，GET 不返回；端口往后都被占时答 busy
GET /endpoint、POST /endpoint/key端点状态和密钥；生成新密钥
POST /endpoint/models、/endpoint/models/remove{path, name?} 登记、{name} 撤销用户自己的模型，之后重启引擎
POST /smoke在后台重新做冒烟检查，答 {started}（已在做时 {started: false, running: true}）；结果看 /status 的 smoke
POST /accessories/enable{accessory}：开启螺壳里带的应用；不是螺壳里带的应用答 unsupported（以下几条同）
POST /accessories/disable{accessory}：停用螺壳里带的应用，停掉它的空闲任务和只由它使用的工作进程，不动数据
POST /accessories/permission{accessory, permission, on}：记下或撤回用户对螺壳名下某项系统权限的同意；清单没声明这项权限答 undeclared
POST /accessories/first-use{accessory} → {jobs}：清单里标了 first_use 的空闲任务在下一次采样就起，不看安静时刻和电源
POST /accessories/delete-data{accessory, dry_run?, forget?}：删螺壳里带的应用的数据（真删前先记停用），答复同 /uninstall
POST /accessories/reregister{accessory} → {accessory, app, unregistered_others, killed}：重新登记单独装的配件（结束进程，注销同 bundle id 的其他副本，复制一份换回原位）；没装答 unsupported
POST /accessories/restart{accessory} → {accessory, app, killed}：重新启动输入法（结束进程再拉起）；没装或不是输入法答 unsupported
POST /uninstall{accessory, data?, forget?, dry_run?}；dry_run 只答计划（要删的 .app、旧版、数据路径，能从记忆里忘掉多少），真卸载答复另列 removed、errors。先停它的空闲任务；也删除 previous.noindex 里该配件的旧版（答复 previous、previous_copies）；螺壳里带的应用没有 .app 可删，只记停用；螺壳记忆不能单独卸载（invalid_request）；没装答 unsupported
GET /accessories/previous留有旧版的配件：{accessories: [{accessory, name, type, bundle_id, current, previous, verified, release}]}；verified 为假的不能换回
POST /accessories/rollback{accessory} → {accessory, from, to, type, bundle_id}；无旧版或无验证记录 unsupported，签名不过 invalid_request，对调失败 engine_failed
POST /jobs/run（不要求身份）{job}（<配件>.<任务名>）→ {job, queued}：让某个空闲任务在下一个安静时刻运行，不等最小间隔，其余条件照旧；只在内部版、本机版和实验室版可用，其他答 unsupported

高级用户端点

  • 默认关；开启后监听 127.0.0.1，默认端口 17860（被占则往后找，最多试 20 个）。
  • 检查：Host 必须是 127.0.0.1 或 localhost；带 Origin 头一律拒绝；密钥非空时校验 Authorization: Bearer（用户可自定义或留空）；请求体上限 32 MB。
  • GET /v1/models：底座名和 user/<名字>（用户登记的模型）。POST /v1/chat/completions：要有 model 和 messages，可流式，按"用户在等"调度；均衡、静音档下一次只做一条，每条做完按用时歇（均衡 1 倍、静音 3 倍，最多 600 秒）。用户模型和底座放得下就一起加载，放不下才独占引擎；闲置 5 分钟卸掉。
  • 错误体为 {"error": {"type", "message"}}：forbidden（403，Host 或 Origin 不对）、unauthorized（401）、invalid_request（400）、not_found、model_not_found（404）、too_large（413：请求体为空或超过上限；507：模型超过独占上限，即内存 − 8%（3–8 GB）− 正在运行的专用模型 − 1 GB）、not_ready、busy、engine_failed（503）。
  • 命令行 luoke launch pi [--model M] 自动读取端口和密钥（端点没开时先打开），在 pi 的配置中写入 luoke provider 并启动 pi；luoke endpoint 显示端点状态（不印密钥）。
