# 螺壳输入法 luoke-ime

- 仓库：[`luoke-ime/`](../luoke-ime)；设计：`luoke-ime/docs/设计.md`；做法上的决定：`luoke-ime/docs/adr/`
- 本页由 luoke-ime 的会话维护，只写现行的。

## 是什么

macOS 输入法。壳只管按键、候选窗、上屏和沙盒，出什么候选全部交给输入法引擎：独立的子进程，经标准输入输出说 JSON 行，在 Seatbelt 沙盒里按声明放行。

- **打字引擎**（自带）：
  - 小鹤双拼、自然码双拼、全拼，还有一个最小示例。
  - 候选来自苹果自带的转换引擎和 RIME，模型按前文逐词重排。
  - 博客语料上首选准确率约 90%，只用苹果的是 78.8%。
- **个人化组件**（`engines/personal`）：
  - 把上屏写进记忆。
  - 替打字引擎经主控打分。
  - 联想：上屏后按 ⇥，候选来自用户自己写过的和模型续写。
- **语音输入**（`engines/voice`，快捷键引擎，做法见 ADR 0016）：
  - 设置里「语音输入」默认关，打开了才启动、才申请麦克风。
  - 按住说话，松开一次上屏。
  - 转写后可以再整理，像认真打出来的文字那样编辑：去口头禅、理顺改口、排列表和分段。
  - 「说完后整理」没选过时，16 GB 的 Mac 关。

## 对外提供

- 输入法本身。
- 把用户上屏的文字写进记忆（`ime-commit`、`ime-correction`、`ime-forget`）。经输入法上屏的都是用户自己打的或说的（粘贴不经过输入法），是记忆里最直接的一类「用户本人说的话」。
- 重排、联想、转写、整理四项的评测，给主控的配方和出版用。
- 螺壳主窗口里的输入法设置页（输入法 ADR 0018）：
  - 由包里的 `Contents/MacOS/luoke-ime mcp` 提供，照 luoke-agent 工具协议 §2a（`transport: "stdio"`）答一条请求就退出。
  - 两页：`page/settings`（通用页的全部设置，含记忆记录的开关和暂停）和 `page/apps`（各应用）。
  - `ime_set` 只改写死的一张表，要 `ai.luoke/user-action`。
  - `ime_page` 只读，记下在「各应用」页展开哪个应用（`~/.luoke/ime/window-page.json`）。
  - 和输入法自己的设置窗口改同一份 `settings.json`。
  - 配件清单里写了 `transport: "stdio"`、`service.pages`、`actions`，不写 `permissions`。
  - 页面怎么画归 luoke-agent。

## 依赖

## 对主控的需求

**身份**：
- 对主控来说配件只有一个，`luoke-ime`。
- 配件清单 `luoke-accessory.json` 在 LuokeIME.app 的 `Contents/Resources`：`type` 是 `input-method`，`memory` 为 true。
- `data` 是 `["~/.luoke/ime"]`。卸载时主控删 `~/Library/Input Methods/LuokeIME.app` 和这个目录。目录里只有输入法自己的设置、各引擎的数据、开发模式的记录和用户装的引擎，不含 `mem.db`。
- 「添加应用」里看到的介绍写在清单的 `capabilities.listing`，类别「输入」。
- 用户要在系统设置里手动添加输入源。这一步不是系统授权，不写进 `permissions`，由主控的完成页和输入法的添加引导带着做。引导的步骤、文字、截图在主控的首次安装里有一份抄的，输入法改了会告诉主控。

**任务**：

| 任务 | 方式 | 用在哪 | 延迟 | 输入法这边管的 |
|---|---|---|---|---|
| `luoke-ime.rerank` | 打分，专用模型 | 打字时按前文逐词选首选 | 最后一个键之后，整次重排约 150 ms 内到；按空格时壳最多再等 150 ms，等不到用快的那份候选 | 「有把握才改」的门槛（引擎选项 `gate`，默认 3 nats） |
| `luoke-ime.predict` | 续写：前文后面最可能的 k 个开头各贪心续几个 token，交回逐个 token 的文字和对数概率 | 上屏后给接着写的候选 | 上屏后约 300 ms 内备好；壳等 1 秒 | 停止串、怎么截、挑哪几个、门槛（现在 8 个开头、6 个 token、平均每字对数概率 ≥ −2.5） |
| `luoke-ime.transcribe` | 转写，专用模型（16 档 0.6B 8-bit，32、128 档 1.7B 8-bit） | 语音：按下就录，按住期间约每秒一份草稿（只作显示串），松开要终稿 | 16 GB M1 上热的时候，松开到终稿 p50 / p90 351 / 437 ms；冷加载约 4 s，所以按下时预热（`POST /warmup`） | 一次听写一个会话，音频按块追加（`seq` 0 新开、`session_lost` 时从 0 重送），草稿可被顶掉（`superseded`）；热词拼进 `context`；传 `language: "Chinese"`；音频不落盘、不进日志 |
| `luoke-ime.tidy` | generate，用底座 | 语音终稿以后整理（编辑），可关 | 等不到就上屏没整理的：2.5 秒起，每 200 个字多 1 秒，最多 5 秒。9B 编辑约 400 字约 2.6 s | 提示词和示例（`engines/voice/tidy_prompt.txt`、`tidy_examples.json`） |

- **打分的用法**：
  - 一次请求 10–15 个候选，共享前文。
  - 同一句里「前文 + 已定的词」反复出现，靠主控的前缀缓存。
  - 用户敲了下一个键就关连接取消。
- **慢的机器**：主控在 `GET /tasks` 里给 `luoke-ime.rerank` 标 `slow`（按实测的打分延迟，不按内存档位）。
  - 输入法每一步少给模型一半候选，一次重排最多 2 步。模型算着时，先答新键的快候选。
  - M1 16 GB 上经主控：第一份答复 p90 32 ms，选好 p50 / p90 150 / 183 ms。
- **测速探针归输入法**：主控测打分延迟用的前文和候选，照真实请求的形状定，写在 luoke-core 配方的 `params.*.probe` 里。
  - 重排：前文约 50 字、10 个候选。
  - 联想：前文约 36 字，`/v1/continue`，k 8、max_tokens 6，输入法的 34 个标点作停止串。
  - 输入法的请求形状变了，告诉 luoke-core 改这一块。
- **转写预热**：`warmup` 在模型已经加载时，也解一小段静音。闲置久了 macOS 会把权重换出内存，按下时解一下，读回权重和说话同时进行。
- **不可用时**：主控不可用、或返回 `not_ready`，打字照常（苹果和 RIME 的候选），只是没有重排和联想。语音提示原因、不上屏。输入法的主要功能不依赖 AI。
- **和后台共存**：底座在跑后台请求时，打分会慢到救不了打字。让路的做法由主控定（V1 §3）。输入法这边重排慢了，就用快的那份候选。
- **整理在 16 GB 的 Mac 上**（还开着）：底座和转写模型二选一，每次整理要重新加载 9B，测试机上 8–10 s，所以 16 GB 默认不整理。
  - 改用 4B、默认打开，还是别的做法，由 luoke-core 在测试机上比过再定（luoke-core-private#22）。
  - 定了以后，输入法照 `/tasks` 定默认值：`available` 且没有 `slow` 就开。
- **只用配方里评测过的模型**：用户自己接的模型不给输入法用，设置里这几项灰着。
  - 重排、联想要 Base 模型的对数概率，转写要音频模型，本来就换不了。
  - 以后整理要允许换模型的话，请主控在 `/tasks` 里标出这项用的是用户自己的模型。
- **评测**：
  - 重排用 `engines/xiaohe/bench.py`；联想用 `engines/personal/eval_predict.py --hub <socket>`；转写在 `evals/transcribe/`；整理在 `evals/tidy/`。
  - 都有 `--result FILE`，照 V1 的证据格式写 JSON，不带语料原文。
  - 重排、联想的语料是私有的博客语料，只在实验室的机器上跑。
  - 主控评测表 `tools/release_evals.json` 每项的 `paths` 写着这项评测读哪些文件，只在这些文件变了时重跑。评测开始读别的文件时，输入法同一次改动里请主控改 `paths`。
- **安装和启动**：
  - 装在 `~/Library/Input Methods/LuokeIME.app`，bundle id `ai.luoke.inputmethod.Luoke`，要求 macOS 26 起。
  - 由系统的输入源机制拉起，不是常驻配件，不调 `PUT /accessory/resident`。正常退出前调 `POST /accessory/exiting`。只当一份输入法服务：不是 launchd 拉起的、或已有一份在跑就退出。
  - 用户自己打开 LuokeIME.app、而螺壳还没被添加时，输入法弹添加的引导窗口（带参数运行时不弹）。
  - `LuokeIME --status` 输出一行 JSON：
    - `state` 是 `not_registered` / `not_added` / `added_not_selectable` / `ready` 之一；
    - `other_copies` 列出同 bundle id 的别的副本，不空多半切不过去，安装前要先注销它们。
  - `LuokeIME --select` 会核对真的切过去了：退出码 0 切过去了，1 调用失败，3 调用成功但没切过去。
  - 刚添加完时，之前就开着的应用不会自己去连输入法。主控切过去以后，要让试打框重新聚焦一次。
  - **换版**：主控换好包以后，结束跑在旧包里的进程（SIGTERM，3 秒后 SIGKILL），再 `open -g` 装好的路径。输入法自己也兜一层：发现磁盘上的 build 号变了，就等没在打字时自己退出、拉起新版。
- **发布时怎么带引擎**（`luoke-ime/docs/发布打包.md`）：自带的打字引擎、个人化组件、语音引擎都在 LuokeIME.app 的 `Contents/Resources/engines/` 里，和壳一起签名公证。主控只装 LuokeIME.app。
- **借主控的 Python**：
  - 个人化组件只用标准库，跑在主控包里的 `螺壳.app/Contents/Resources/python/bin/python3` 上：先找 /Applications，再找 ~/Applications。
  - 壳按 bundle id `ai.luoke.core` 找主控，在沙盒里只读地起这个 Python（`PYTHONDONTWRITEBYTECODE=1`）。找不到主控就没有个人化组件，打字照常。
  - 要主控保证：路径和 bundle id 不变；Python 3.9 以上、带 sqlite3；同一个 Team 签名、hardened runtime；换 Python 或 luoke_mem 时提前说（壳会重启个人化组件）。
- **起设置页的命令**：主窗口里输入法的设置页，要主控起装在 `~/Library/Input Methods/LuokeIME.app` 里的 `Contents/MacOS/luoke-ime mcp`。签名和 LuokeIME 同一个 Team，签名标识 `luoke-ime`。luoke-core 已接：按已装配件的清单找到包，核签名标识、Developer ID 和团队，不核版本，一个请求最多 30 秒。
- **输入法单独发版**（还开着，机制在 luoke-ops#141）：输入法是独立的 app，配方不变的改动由输入法自己发版，不等螺壳本体。由主控来拉，输入法照旧不联网、不自己检查更新。要请主控做两件事：
  1. **配件单独升级**：本体「检查更新」时，也看已装配件有没有新版，配件有新版时不要求本体跟着升。下载、核签名和公证、换上、回到上一版，都照主控现有的做法。发布地点和清单格式由主控定，输入法交出构建、签名、公证好的包。
  2. **不按版本认配件**：现在配件版本要和配方的已验证版本一模一样，主控才接它的请求。配件能不能单独发，由配件发布流程里的 CI 把关，要核什么由 johnz 和 Keith 定，输入法照那份清单接 CI。
- **最敏感**：输入法看得到用户打的每一个字，「请求文字只在内存里、不进日志」对它最要紧。

## 对 luoke-agent 的需求

引擎选项页用 LuokeA2UI，公开发布以后再接。输入法按 luoke-agent 打的标签（如 `a2ui-v0.1.0`）把那一版拷进自己的仓库，发布构建不依赖它的仓库。要的是：
- 支持全集里按目录标识 `ai.luoke/a2ui/ime/1` 放行的组件（含 Slider）。
- 数据模型改了交回整份，写回时保留界面上没有的键。
- 按钮动作交回壳，由壳转给引擎。
- 校验函数只依赖 Foundation（命令行版的 `check` 要用）。
- 渲染器不碰文件：options.json 由壳读写，不跟随符号链接。

## 在记忆里读写什么

由输入法里的**个人化组件**读写，工具标识 `luoke-ime`。
- 它在 Seatbelt 沙盒里，不能联网。
- 声明了 `memory` 权限后，沙盒只放行记忆文件本身和 SQLite 的 `-wal` `-shm` `-journal`，不跟随符号链接。路径由壳经环境变量 `LUOKE_IME_MEMORY` 给，默认 `~/.luoke/mem.db`。
- `~/.luoke` 下别的东西照样读不到，目录本身也改不了。
- 壳第一次建 `~/.luoke` 时用 700。

**写的记录**：

| 话题 | 谁说的 / 性质 | 一条是什么 |
|---|---|---|
| `ime-commit` | 用户 / 陈述 | 上屏的文字，同一应用里接连的上屏合成一段记一条。这一段开始时光标前的字放在 `data.context`，标成第三方写的（顶层 ADR 0013）。`data` 第一层放 `app`、`source`（哪个引擎）、`kind`（打字、标点、语音、英文 `english`）、`auto`（切走时自动上屏的，归纳时不当依据）。英文模式下敲的字单独一条：回车、挪光标、切走、切回中文时收尾，终端里不攒（输入法 ADR 0017） |
| `ime-correction` | 用户 / 活动 | 上屏后马上删改、在候选里改选；跟着所在的那一段写，那一段敏感就一起不记 |
| `ime-forget` | 用户 / 陈述 | 忘掉候选（候选窗里 Shift+⌫）；候选来自一条 `term` 时对它调 `reject`，不调库的 `forget`（那是真删除） |

**写的理解**：没有。常用的说法和专名（`term`）、关注的话题，由 luoke-mem 从输入法的记录里归纳、把关（顶层 ADR 0005）。

**怎么写**：
- 在后台线程里写，别的工具正写时最多等锁 10 秒，不让转问的答复等它。
- 上屏原文默认一直保留。用户设了保留期，组件才定期调 `forget_records(..., until=..., keep_cited=True)`。
- 记忆文件比库新时，打开会抛 `luoke_mem.TooNew`，输入法在菜单里标「记忆打不开」。

**读的理解**：语音热词。
- 个人化组件用 luoke_mem 的 `hotwords(limit)` 取常用说法，最多 50 条：人名最多四成、英文专名两成，剩下给用户自己的说法。
- 旧版库没有 `hotwords`，就按 `notes(kinds=["term"])` 自己挑：确认过的在前，标了敏感类别的、否掉的、被换掉的不给。
- 只交给自带的语音引擎，放进转写的上下文。人名、英文专名由 luoke-mem 归纳进 `term`，输入法照这个办法读。
- 以后还会拿理解给模型当前文、给候选加分、给联想当素材（计划）。

**记忆记录**：
- 自带的个人化组件默认开，第一次切到螺壳时提示一句，全局设置里能关（「记录输入内容到本机记忆」）。
- 关着时沙盒不放行 `mem.db`、上屏不转，组件照样打分、联想。
- 第三方的个人化组件要用户另外打开。

**不记**：
- 密码框等安全输入时什么都不记。
- 设了「禁止记录」的应用、用户暂停所有记录时，上屏不转，打字引擎也收不到反馈。
- 凭证只遮那一串，其余照记（`mask_secrets`）。
- 健康、法律、宗教政治照 `sensitive_kinds` 标上类别，不藏。
- 这些规则在输入法的 `PersonalPolicy` 一张表里（顶层 ADR 0013）。

**整份记忆的入口**：
- 输入法菜单里的「管理记忆…」和设置窗口的「查看和管理记忆…」，`mem.db` 存在时才显示，用 `open luoke://memory` 打开。
- 没有应用认领 `luoke://` 时，退回旧的「螺壳记忆.app」（bundle id `ai.luoke.memory`）；都没有时显示成灰的「还没装螺壳」。
- 壳不派生进程、不带 luoke_mem、不起 Python。
- 卸载输入法时的「一起从记忆里忘掉」由主控跑 `forget-tool`。

## 现状数据

- 博客语料 600 条首选准确率：苹果 78.8%，重排后约 90%（小鹤、自然码、全拼都是）。
- 120 ms 一个键的逐键打字，最后一个键到重排结果：M4 中位数 122 ms、p90 186 ms；M5 Max 60 / 77 ms。停顿 100 ms 按空格，上屏首选准确率 90.5%。
- 联想（博客语料，只测模型那一路）：给出时第一个就对约 41%，每次 18–24 ms（M5 Max）。
- 本机统计（模型在真实输入里帮了多少）记在引擎数据目录的 `stats.json`，只有次数。
