# 螺壳官网和社区 luoke-community

- 仓库：[`luoke-community/`](../luoke-community)。方案：`docs/封闭测试.md`、`docs/官网.md`、`docs/社区运营.md`；进度：`STATUS.md`
- 本页由 luoke-community 维护。

## 是什么

螺壳实验室（Luoke Labs）的封闭测试、官网和用户社区「螺壳社区」（顶层 ADR 0017）。

- **封闭测试**：招募测试者、按覆盖表（内存档、芯片、邮箱、输入法）挑人、分两批开始、给测试说明、收反馈、按组件转给各项目、结束时汇总。
- **官网**：前端在本仓库 `site/`（Astro 静态站）。改动先在 luoke-brand 的 `site/` 做，确认后同步过来；本项目负责页面上的事实和出处。
- **社区**：公开以后的渠道、节奏、内容（实验笔记、发布说明、月报）。平台上的图文和视频由内容工作区做，本项目给事实和出处。

## 对外提供

- **封闭测试的材料**（`beta/`）：测试说明、连接邮箱、已知问题、招募帖和报名问卷、周问卷和结束问卷、GitHub 反馈表单（装机报告、问题、卡住了、建议、邮件分错了）。测试说明、已知问题和表单发布在封闭测试仓库，用 `beta/publish.sh` 同步。
- **反馈分拣**：封闭测试期间每天看新问题，打组件标签（安装和首次运行、邮件助手、输入法、记忆、主控）和严重程度（阻断、严重、一般），合并重复的，转给对应项目；功能建议打"公开后"标签。各项目可以用 `gh issue list -l <组件>` 读自己那部分。
- **问卷结果**：只带测试编号，放在 `beta/结果/`。
- **官网**（`site/`）：各档体验、系统要求、实测数字只存一份、带出处（`site/data/tiers.json`、`claims.json`）。
- **应用图标**：`icons/brand-a/` 里是品牌 A 版打好的 `.icns`（主控 / 安装器、邮件助手、输入法）。

## 对别的项目的需求

**对 luoke-core**：每个测试版（beta1、beta2……）出版后给下载地址，测试说明照它填。

**对所有首发项目**（luoke-core、luoke-mail、luoke-ime、luoke-mem），封闭测试期间：

1. 新的已知问题告诉本项目，本项目更新 `已知问题.md`。
2. 修好的问题在对应 issue 里写明哪个版本修的。
3. 素材里的数字或说法变了告诉本项目，测试说明和官网跟着改。

**对 luoke-agent**：公开发布前给"螺壳以后会主动提醒你"那页的素材；社区什么时候能写工具，定了告诉本项目。

**对 luoke-core、luoke-agent**（[luoke#1](https://github.com/luokelabs/luoke/issues/1)，两家 11-01 都回了，都没做也没定，等顶层 ADR，定了告诉本项目）：

1. 联网和记忆：社区做的东西能不能联网、能碰记忆的哪些部分。官网"会把我的东西传出去吗"那句等这条定了再改（见下面"怎么标明"第 5 条）。
2. 标记：「官方」「社区」由主控从签名、配方和社区登记表算出来，显示名也取登记表，不读作者自己写的字段。
3. 撤下：用户怎么知道自己装的东西被撤了。两家都给了草稿（`projects/luoke-core.md`、`projects/luoke-agent.md`），ADR 定了、功能做出来以前不对外说。

**对 luoke-ime**（luoke#1，11-01 回了，没接，等顶层 ADR）：第三方引擎的确认框和设置里统一显示「第三方 · 作者自述：X · 实验室没审过代码」，真有收录时再加「社区」。文字等官网的说法定稿，本项目发原文。收录的门槛和绑版本的做法由 luoke-ime 定，等有人真想做再写。

**对 luoke-scan**（原 luoke-audit，luoke-scan-private#52）：规则的数据格式里带上贡献者署名；测试样例不用真实路径和用户内容；哪些规则不收，写成能放进贡献说明的话。11-11 直接发给了 luoke-scan 会话；主人同日定，产品会话先不为它改格式，等 Jason 那边真有外部贡献、提出具体要求再提。

## 社区和第三方接入（luoke#1 的输入）

2026-11-01 写给扩展层的顶层 ADR，同日按 luoke-core、luoke-agent、luoke-ime 的回复改过。**都是建议，还没定，不对外。** 安全边界、签名、沙盒归 luoke-core 和 luoke-agent，规则格式归 luoke-audit，这里只写流程、审核的分工和对外怎么说。

**结论**：只分「官方」和「社区」两级，看的是谁发布、谁负责，不看最初是谁写的。风险不同的东西走不同的路，不用一套流程审所有东西。眼下还没有外部的人说想做（见第 3 节），公开承诺和排期都不用抢在需求前面。

### 现状

- 入口已经公开：官网 `/contribute` 和 `luoke-contribute` 的 README。许愿走官网或 Discussions；改已有项目走各项目的 issue、PR；新项目在 `luoke-contribute` 开 issue，合适就立项、搬进螺壳、署名。
- 现在走得通的有四样：报问题、改代码、补实测、写输入法引擎（放进本机就能用）。
- 新工具到不了用户手里：主控只装实验室签名的配件。投稿页写的"用螺壳的模型和记忆"的小工具，现在只能走立项搬进来，不能自己发布。

### 1. 外部贡献者的流程

| 贡献什么 | 怎么交 | 谁审 | 按什么标准 | 进去以后算 |
|---|---|---|---|---|
| 改已有项目 | 项目仓库，先开 issue 再提 PR | 该项目 | 项目的 `CONTRIBUTING.md`；封闭测试期间首发四个组件只收修问题的，功能建议记到公开以后 | 官方，贡献者进名单 |
| 数据：体检规则、实测结果 | 规则进公开规则库提 PR（格式等 luoke-scan-private#52）；实测照旧在 luoke-core 开 issue | 先自动校验，再由对应项目审 | 每条带依据和测试样例；哪些规则不收由 luoke-audit 定 | 官方（项目审过、随版本发），贡献者署名 |
| 输入法引擎 | 不用交，放进本机就能用；想被收录，到公开的 `luokelabs/luoke-ime` 开 issue | 先自动检查，再由 luoke-ime 看结果，本项目看介绍和署名 | 先只定自动能查的：`luoke-ime check` 通过，不申请联网、GPU 和额外写入，有许可证，公开源码，能复现构建或能核对哈希。收录不等于审过代码 | 收录了算社区；没收录的只显示「第三方」 |
| 新工具 | `luoke-contribute` 开 issue（模板已有） | 本项目先对底线；做不做由主人定，和团队加新组件一样（`docs/new-component.md`） | 底线之外，进配方要多名成员同意、走同样的评测关卡 | 搬进来的算官方；自己发布的等 luoke-core、luoke-agent 定了边界才有 |

**所有路都要守的**：官网已公开的四条（不把用户的东西传出去、模型只经螺壳、动手前先问用户、秘密不碰），再加两条：贡献里不带真实用户内容；介绍里的数字有出处，说不出出处的标"作者自述"。

**谁接**：

- 本项目接 `luoke-contribute` 的申请，分拣、对底线、转给对应项目，一周内给第一次回复。
- 收不收要由人拍板。项目会话只分拣、追问、给意见，不替拍板的人说"收"或"不收"。
- 新工具立项由主人定，搬进来的进配方照旧要多名成员同意。
- 对外口径和页面归 Jason。

**开放的顺序**：

1. 现在：许愿、报问题、补实测、写引擎。
2. 规则格式定了、规则库建好：收规则。
3. 有人真想让引擎被收录：再做收录。现在的确认指纹故意不绑代码，收录要绑具体版本，就得另算整个文件夹的内容哈希、另发能核对的收录清单，由 luoke-ime 单独写 ADR。
4. luoke-core、luoke-agent 定了边界：才说第三方能自己发布工具。

**撤下**：怀疑有恶意或泄露时先撤下、再讨论，由负责那块的项目提出，主控的撤回通道执行（`revoked` 还没做），事后对外说明。

**要 Jason 定的**（主人 11-11：community 的事归 Jason，不排主人的队列，见 `ops/docs/owner-decisions.md`）：

- 每一块收不收由谁拍板。建议每块指定一位团队成员。
- "先撤下"能不能不等拍板的人点头。
- 贡献的授权。现有公开仓库 Apache-2.0 和 MIT 都有，版权署名是"螺壳实验室 Luoke Labs"。建议规则库定一种许可，用 DCO（提交里写 `Signed-off-by`），不用 CLA，个人贡献者门槛最低。

### 2. 分级和对外怎么标明

| | 官方 | 社区 |
|---|---|---|
| 谁发布、谁负责修 | 螺壳实验室 | 作者 |
| 实验室做过什么 | 签名，进配方，过各档评测 | 只做写明的几项检查 |
| 署名 | 螺壳实验室，贡献者进名单 | 作者自己选的名字 |
| 问题报到哪 | 实验室的项目 | 作者的仓库；安全问题也可以报给实验室 |

**不设「认证」这一级**：它听上去是实验室在担保，可是没在各档跑过评测就说不出"好用"，也没有人力复审每个新版本。想要更高一级，走搬进来这条路就行。

**社区的东西不进配方**（luoke-core 11-01 定）：配方是实验室在各档测过的承诺。社区的东西另放一份社区登记表，记身份、哈希、撤回状态，随检查更新取。谁往表里加、查什么，由顶层定。

**没收录的不算一级**：自己放进本机的第三方引擎，实验室没看过，输入法也判断不了收录没有，所以只显示「第三方」，不能和收录过的长得一样。

**怎么标明**：

1. **来源不靠自报**：只认签名、配方和社区登记表，作者写什么都变不成「官方」。作者名没核实过的一律写「作者自述：X」，写官方名字的要拦。
2. **写明查过什么**：凡是出现社区东西的地方都标「社区」和作者，展开是一句实话，例如"社区做的，作者负责。螺壳实验室只做过自动检查：不申请联网、要的权限和说明一致。没审过代码，也没测过好不好用。"沙盒挡得住联网，挡不住上屏时写错字，这类话也照实写。
3. **放在哪**：
   - 官网单开社区目录，有第一个真实收录的东西才开，不放示例。
   - 下载页和各档体验表只放官方，`claims.json` 的数字不收作者自述。
   - 首页口袋用 `pocket.json` 现成的 `official`、`by`。
   - 输入法确认框里，没收录的显示「第三方 · 作者自述：X · 实验室没审过代码」。「添加应用」窗口守同样的规矩。
   - 问题里打「社区」标签，转给作者。
4. **名字和形象**：社区的东西名字不以「螺壳」开头，不用海螺和小家伙，可以写"给螺壳用的"。
5. **隐私的说法**：常见问题里"不会，你的东西都只在这台 Mac 上"现在说的是实验室的应用，边界定之前官网不改。luoke-core、luoke-agent 建议默认不能联网、碰不到记忆，用户单独同意才放行，两者不同时给；这只对扩展成立，审过的 .app 算不算例外还没定。所有社区的东西都管得住，才能说社区做的也传不出去；否则只说官方的，并在社区目录写清楚。
6. **撤下的说法和留痕**：功能做出来以前不说。目录里留着，标「已撤下」和原因，不悄悄删；发布说明写一句。不说"立刻"：离线的机器要等联网，.app 自己还能运行，只是用不了螺壳的服务。
7. **用词**：对外说"社区做的""社区引擎"，不说平台、插件市场、商店、生态。
8. **署名要真**：首页口袋里灰色的几项标着「社区设想」，其实是团队假定的示例。有真实社区内容之前，这个标记要换掉或拿掉（官网的事，转给 Jason）。

**要顶层统一的词**：

- 「第三方」现在有两个意思：记录的说话人（CONTEXT），和别人写的代码（ARCHITECTURE、luoke-ime）。
- 「扩展」在顶层 CONTEXT 里没有定义，用户界面上叫"应用"，「插件」是不用的词。ADR 里要定一下。
- 「社区」在 CONTEXT 里指用螺壳的人，「社区」这一级指作者发布的东西，建议对外都写成"社区做的"以免混。

## 在记忆里读写什么

不读不写。官网和社区的素材不用真实用户的数据，截图用示例收件箱和示例记忆。

## 要守的底线

- 对外的事（发帖、邀请测试者、官网上线）每件先确认再做。
- 测试者的名字和联系方式不进仓库，只放编号和覆盖表；问卷结果只带编号。
- 反馈不要用户的内容（不贴邮件原文、打的字、记忆的内容）；诊断只含元数据，由用户决定发不发（顶层 ADR 0013）。
- 每个数字有出处，各档照实写。
