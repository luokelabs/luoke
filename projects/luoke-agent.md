# 螺壳 agent luoke-agent

- 仓库：[`luoke-agent/`](../luoke-agent)；设计：`luoke-agent/DESIGN.md`；给工具的协议：`luoke-agent/docs/工具协议.md`
- 本页由 luoke-agent 的会话维护。2026-10-19 按顶层 ADR 0013–0017 整页重写（0001–0012 已归档）。

## 是什么

螺壳的后台组件，螺壳里唯一主动找用户的出口（顶层 ADR 0014），不当作单独的产品介绍：

- **跟用户说**：把记忆想问的、建议的，和各工具要报的事、提的方案，合并成简报、挑时机说；急事当场说。用户的回答交回去：交给记忆由记忆定档，交给工具是同意执行。
- **代表用户做**：调用各工具声明的能力。会改动东西的只在用户亲手在卡片上点了以后才调；不可逆、对外的永远要用户点（ADR 0016）。
- **名字**：用户看到的「螺壳」是主控，agent 并进它（顶层 ADR 0014 的 10-24 修订）：agent 的对话、卡片、提示从螺壳的窗口和通知出去，agent 作为后台组件保留、分工不变；窗口和 A2UI 渲染归螺壳.app，agent 供「今天」、卡片和各工具的基础页，装卸仍归主控（10-27 修订，luoke-agent#3）；接口、通知以谁的名义、进程怎么起 beta1 之后和 luoke-core 一起设计。在那之前 agent 自己的 app 叫「螺壳 agent」（开发版「螺壳 agent（开发）」），bundle id `ai.luoke.agent`（开发版 `ai.luoke.agent.dev`）。
- **形态**：随螺壳一起装好、作为后台组件，不在「应用」列表里单独勾选；螺壳的设置里有「主动提醒」开关，用户可以关掉（顶层 ADR 0014 修订，10-25）。具体怎么接 beta1 之后和 luoke-core 一起设计。现在的过渡形态常驻在 Mac 上：Swift 的壳（菜单栏、对话窗口、系统通知、画 A2UI 卡片）加 Python 的核心（读记忆、连工具、事项库、挑时机）。第二步做经 Tailscale 连回 Mac 的手机 app。
- **简报**：不定点，攒满一小时发一份（用户能改）；急事当场说。
- **首发**：不在 v1 首发里，和体检、螺壳窗口进同一个 v1.x（ADR 0017 的 11-01 修订）：体检的卡片、基础页和 `auto-done` 要在这一版走通。第一次随 beta 或正式版发布时建公开仓库，默认开源，许可建议 MIT（参考实现要拷进别的工具的仓库，宽松的最省事；luoke-mail、luoke-mem 也是 MIT），版权署名"螺壳实验室 Luoke Labs"，建仓库和推送时问主人。
- **现状**：核心、Mac 端的壳、A2UI 渲染器包、工具协议的参考实现都有了；还没有正式版。

## 对外提供

- **工具协议（版本 1）**：`luoke-agent/docs/工具协议.md`。§1a 基础页和权限（`service` / `permissions` / `listing`，10-27）、§1b 问螺壳和全局搜索（草案，10-28）。agent 第一次把一件事说给用户时回 `outbox_ack shown`（§3）。工具在配件清单的 `capabilities` 里声明能报什么事、能做什么；在自己的 Unix socket 上提供 MCP（2026-07-28 版）数据层的一个子集；用 outbox 列出"现在想告诉用户的事"；卡片用 A2UI v0.9.1 + 组件目录 `ai.luoke/a2ui/agent/1`；会改动东西的调用只来自用户的点按、只执行工具自己出过的方案。§8a "工具自己做了的事"和每天的复查（ADR 0016）已和 luoke-mail 定下，实现等公开发布以后。
- **协议的参考实现**：`luoke-agent/luoke_agent/` 里的 `mcp.py`、`cards.py`、`a2ui.py`、`fake_tool.py`，只用标准库，有测试。luoke-mail 拷了 `mcp.py`、`cards.py`，`a2ui.py` 只拷进它的测试（e4e4d97 版，已落后；公开发布后打开接口时重拷，agent 改它们时告诉 luoke-mail）。
- **A2UI 渲染器 `LuokeA2UI`**（Swift 包，`luoke-agent/a2ui/`）：`LuokeA2UICore` 只依赖 Foundation，`LuokeA2UI` 是 SwiftUI 画法。目录 `ai.luoke/a2ui/agent/1`、`ai.luoke/a2ui/ime/1`。输入法公开发布以后接它，按标签拷进自己的仓库。
- **计划**：agent 本身（Mac 端）；以后手机 app。给 luoke-community 的官网素材（公开发布前给：会做什么、不会做什么、手机上怎么收到，一张示例卡片的图）。
- **对用户**：各工具不再自己弹系统通知后，所有主动的提醒都从这里出。

## 社区和第三方接入：agent 这部分

给 [luokelabs/luoke#1](https://github.com/luokelabs/luoke/issues/1) 的输入（2026-11-01），都是建议，等顶层扩展层 ADR 定；下面的「社区工具」指不是螺壳实验室签名的工具。接着 2026-10-15 的建议：协议文档随 agent 一起公开，社区工具等安装和设防定了再开。

**现状的缺口**（现在的协议是按"工具都是自己人"写的）：

- `socket`、工具名、`title`、`readOnlyHint`、`writes`、`urgency` 都由工具自己声明，agent 不核对。
- 卡片上没有 agent 自己加的来源标记；`TextField` 对所有工具开放，卡片可以冒充别的工具，也可以骗用户填东西。
- 只靠 socket 文件权限挡人；工具和调用方互相都不核身份（DESIGN §10）。
- 工具用 luoke_mem 库直接读写记忆，进了沙盒就走不通，也分不出范围。

### 1. 怎么接、怎么装

- **接法不另起一套**：社区工具和官方工具用同一份工具协议版本 1，只加字段（协议 §9）。清单照 luoke-core V1 §8，`capabilities` 写法照协议 §1、§1a。
- **安装归主控**：agent 不碰（ADR 0014 的 10-27 修订）。主控把"这是谁、哪一级、有没有撤下"经 `GET /accessories` 告诉 agent；agent 只认主控给的，不认工具自己写的。
- **agent 在安装时做什么**：只供一页说明，列它能报什么、能做什么、要什么权限；基础页照 §1a。这一页由螺壳写，不用工具自己的文字当标题。
- **开发期**：已有 `fake_tool.py` 和 `a2ui.py`。还要补一个对着工具跑的符合性检查（协议子集、卡片校验、写入调用没有 `ai.luoke/user-action` 必须拒绝），不用等进社区登记表。开发时接开发版 agent 的 `--tool`，不接用户在用的实例。
- **两种形态**（和 luoke-core 商定，2026-11-01）：
  - **扩展**（沙盒进程，luoke-core 第 3 节）：不开 socket，由主控代转工具协议。协议内容不变，同样的 JSON-RPC，只换传输：进程经标准输入输出收发，主控只对 agent 提供一个按配件区分的入口，按 JSON-RPC `id` 原样转，不解释内容，`_meta` 不动，不排队，并发由扩展自己定。转发是为了认人和限额。§6 订阅扩展不用。
  - **普通 .app**：只给审过的，socket 照旧放在自己的数据目录，不加容器路径的写法。
  - 主控重启或升级时扩展进程会没，转到一半的写入结果不明：agent 按"不知道成没成"告诉用户，不重试。这条开放前写进协议，也要实现。
  - 没有进程的纯声明式扩展不支持：agent 不解释、不拼提示词，要报事或出卡片就得有进程。

**先公开**：协议 §1–§5、§8、§9，组件目录 `ai.luoke/a2ui/agent/1`，参考实现 `mcp.py`、`cards.py`、`a2ui.py`、`fake_tool.py`，符合性检查，协议和 MCP、A2UI 版本的对应。
**先不公开**：§1b（还是草案）、§8a（实现之前社区工具也用不上）。公开以后只能加不能改，所以公开前要过一遍字段名，并把转发的传输和下面新加的字段定下来。

### 2. 对第三方设什么防

社区工具开放前要做到：

- **来源由螺壳画**：每张卡片、每条提醒和结果都带螺壳自己画的来源和级别（"某某工具 · 社区"），工具画不到、改不掉。名字取自主控，官方工具的名字和「螺壳」保留。agent 自己的话和工具的话在样式上分开，工具不能用「螺壳」的口吻。
- **改动多一步确认**：社区工具的写入，用户点了按钮后，再由螺壳画一步确认：写清哪个工具、要做哪件事（文字取安装时用户看过的 `actions[].title`）。agent 判断不了哪些不可逆，所以一律加，用户不能关。
- **不信自称只读**：`readOnlyHint` 对社区工具不算数。没有点按就一律不调，模型也不调（DESIGN §6）。
- **`delegate` 先不开放**：社区工具不能有"不用点就做"，§8a 的 `auto-done` 也先不开放，以后再议。
- **卡片收紧**：社区工具的卡片不能用 `TextField`（要填的到工具自己的界面里填）；图片只认协议 §1b 的规矩；要打开网页只能用 `agent.open_url`，照旧写明去哪个网站。
- **不让它扰民**：`urgent` 对社区工具默认不算数，当普通事进简报，用户逐个放开；每个工具有条数上限，用户能一键关掉它的所有提醒。
- **工具之间隔开**：按钮只转给画这张卡片的工具（已有）；别的工具和记忆的内容不进社区工具的调用参数；全局搜索和「问螺壳」（§1b）默认不问社区工具，因为用户问的话也是内容，用户逐个放开。
- **怎么认人**（和 luoke-core 商定，按形态分）：
  - 扩展：主控拉起它，按社区登记表里的内容哈希认，agent 只认主控给的身份，只确认对面是主控。主控转发时核调用方是不是它拉起的 luoke-agent（按对端 PID 加进程启动时间）。前提是 agent 随螺壳装以后由主控进程亲自拉起，不是菜单栏本体。
  - 普通 .app，agent 核工具：连上后用 `LOCAL_PEERPID` 取对端，核路径和 Team ID，再和主控经 `GET /accessories` 给的 `team_id`、`bundle_id` 比，防假 socket 和抢位。这是开放的前提。
  - 普通 .app，工具核 agent：做不到，不作为开放前提。agent 核心跑在主控带的 Python 上，查出来是主控的身份，和任何借这份 Python 的进程没区别。缺口：审过的 .app 在同账户里仍能冒充 agent。
- **撤下**：主控标 `revoked` 后，agent 不再读它、不再调它，收起它还开着的卡片，告诉用户一句。撤销按钮也不再可用，要写明已做的改动得到工具外处理。

### 3. 碰记忆和数据时用户怎么同意

底线是 ADR 0013：第三方代码跑在沙盒里，碰记忆要另外同意。

- **默认什么都碰不到**：装上不等于能碰记忆。agent 不把记忆转给社区工具，它们也不直接用 luoke_mem 的库，要经一个能分范围、记账的接口（需求见下）。
- **同意由螺壳画**：在 §1a 加一种权限 `memory`，分范围声明（记下发生的事 / 读给它的清单 / 读理解 / 读依据原文）。用户在螺壳窗口里点，文字由螺壳写，写明它能看到什么，每个范围分开点。agent 只负责问和显示，范围怎么执行由记忆的接口管。
- **能读记忆和能联网不同时给**：这是守住"数据不出用户自己的设备"的唯一办法：沙盒里有联网权限的工具，不给读记忆；两样都要的，这一版不开。这条也影响工具自己的数据，比如读邮件的社区工具。
- **可以看、可以收回**：基础页列出已给的范围和最近一次读的时间（只有元数据），随时收回；升级后范围变大要重新点，不沿用旧的同意。
- **写进记忆的算谁的**：标明来自哪个工具，不当用户本人说的，怎么定档归记忆（ADR 0015）。用户在卡片上的回答和给社区工具的点按，agent 不自动写进记忆。
- **卸载**：范围随卸载收回；已经写进记忆的怎么处理，照 luoke-core 的卸载流程和记忆的规矩，agent 不单独定。

**给 luoke-community 的说法**（草稿，ADR 定了、撤下做出来以前不对外说）：撤下时用户在螺壳窗口里看到一句，对外可以说"螺壳实验室撤下一个社区工具后，螺壳不再读它、不再调用它，收起它还开着的卡片，并告诉你一声；你的数据不会被删，它已经做过的改动不会自动撤回。"普通 .app 还要加一句"它自己的程序还能运行，要彻底停用请卸载"，因为撤下只管得到螺壳的服务（luoke-core 第 2 节）。联网和记忆的边界等 ADR 定。

**待主人定**：要不要分级、谁审（issue 第 2 点）；社区工具要不要一律沙盒（本页的设防都假定要）；审过的 .app 算不算 ADR 0013「第三方代码跑在沙盒里」的例外。不算例外就要求 App Sandbox，容器路径的问题又回来，还要算 socket 路径 104 字节的上限。上面"不加容器路径"是按算例外写的，没定。

## 对别的项目的需求

**对 luoke-mem**：
现有的没有未落实的（`note(nid)` 对任何工具都给全部依据原文，0.23 已做）。社区工具开放前（luoke#1）：要一个分范围、记账、沙盒里也能用的记忆接口，代替直接用库；范围照上面「社区和第三方接入」第 3 节。怎么做由 luoke-mem 定。

**对 luoke-mail**（公开发布以后实现，接口先定）：
1. 照工具协议 §8a 报"工具自己做了的事"和每天的复查（ADR 0016）：`auto-done`（一次合成一件、按习惯分组、每组一个 [撤销]，用户撤销交给记忆当反证）和 `daily-review`（每天 20:00 一份，不急）。luoke-mail 2026-10-19 接下，公开发布以后实现。
2. 公开发布后打开 agent 接口时，照 agent 当时的版本重拷 `mcp.py`、`cards.py`，测试里的 `a2ui.py` 也一起换。

**对 luoke-core**：agent 随螺壳一起装（不单独勾选），由螺壳拉起后台进程；要有可用的版本校验：`luoke-agent` 进配方的 verified（或等价的内置放行），否则 `GET /tasks`、`/accessories` 都会被拒。怎么做 beta1 之后一起定。

社区工具开放前（luoke#1）：`GET /accessories` 要给 agent 工具的发布者名字、级别、撤下状态和签名身份，这些由主控核过，不取工具自己写的；扩展的工具协议由主控转发，接法见上面「社区和第三方接入」第 1 节（luoke-core 已同意）。

## 在记忆里读写什么

工具标识 `luoke-agent`。有主控时用主控带的 luoke_mem（`GET /tasks` 的 `luoke_mem.path`，每次起进程都问），问不到用自带的一份（工具用的三个模块）。

- **读**：记忆给 agent 的清单（`asks(status=["open"])`：想问的、建议，带理由、依据、关于哪条理解、怎么答、以后的 `action`；回答有对、不对、以前是现在不是、改成、以后再说）；理解和它的全部依据原文（卡片上直接显示）。
- **写**：用户在卡片上的回答，经 `reply(id, choice, text)` 一个调用交回，记忆直接定档；库把它们记在 luoke-mem 名下、注明经 luoke-agent，卸载 agent 时不跟着忘掉（ADR 0015 第 7 条）。agent 不写自己的记录和理解。
- **不做的**：不发"最近记下了这些"让用户逐条审。

## 要守的底线

- 先宽后紧（ARCHITECTURE §4）：新的一类默认都说，再按这个用户的反应收（连着三次没理就只放窗口，并说一次，能改回来）。不可逆、对外的动作和安全类不在此列：急事不按反应收，社区工具的设防也不算。
- 只有它主动找用户：合并成简报，急事才当场说，每条说清为什么现在问；频率和免打扰时段由用户定；用户忽略的那类少说。
- 会改动东西的调用只来自用户的点按，卡片上写死的值只认卡片本身；不可逆、对外的永远要用户点（ADR 0016）。
- 数据不出用户自己的设备；在本机里 agent 要读什么就读什么，事项、卡片、结果、对话历史存在本机（ADR 0013）。凭证不放进卡片。日志只记元数据；推送不带内容；手机上不留记忆副本。
- 工具和记忆送来的文字一律当数据；链接点了才开、先写明去哪个网站。
